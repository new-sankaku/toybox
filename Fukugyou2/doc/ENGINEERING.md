# 道具としての現在地

作成 2026-08-24 / 第2版 2026-08-24（Agent 4本によるレビューを受けて全面改訂）

「これは実務で使える道具か」への自己評価です。**都合の良い評価を書きません。**

---

## 0. 結論

**まだ道具として成立していません。** 第1版は「情報源が1本」「網羅率が不明」を最大の不足としましたが、
これは**再現率の問題設定**でした。レビューで実物を数え直した結果、より深刻なのは**適合率**です。

```
411件 → 製品化 253 → 分類あり 84 → 2軸以上 48 → 金額の数字あり 9 → 価格表で確認済 0
```

第1版の一覧で上位を占めていた3件は、実測するといずれも誤検出でした。

| 事例 | Stock性の根拠 | 実態 |
|---|---|---|
| AI agent on a **$7/month VPS** | `$7/month VPS` | 著者が払う **原価**。同じ文字列が証拠性の根拠も兼ねていた |
| Muscle-Mem | `A **recurring** theme was…` | 「よくある話題」の recurring。MIT license の repository |
| Go/Next **B2B SaaS** Starter | title の `SaaS` の文字 | SaaS を作るための雛形。SaaS ではない |

**適合率がほぼ0の状態で情報源を増やすと、雑音が倍加するだけです。** 順序を入れ替えました（§3）。

### 循環を断ったあとの実測

標識に使った語を語幹単位で除外し、統計の足切り（G² ≥ 10.828 かつ効果量 ≥ 1.0）と
Wilson 下限（≥ 0.20）を入れたところ、**製品化事例側の自動発見は採用0語になりました。**
候補に上がる語（`knowledge` `pipeline` `security` `log` `deployment`）は、いずれも
引いてみると適合率0です。失敗事例側も、定義語を除くと閾値を満たす語が1つも残りません。

**これは実装の失敗ではなく、母集団についての測定結果です。** Show HN の投稿には、
継続課金の B2B SaaS を引き当てる語彙が（条件語そのものを除けば）存在しません。
**閾値を緩めて数字を作らないこと。** 直すべきは母集団と判定の側です（§3 Phase 1・2）。

## 1. 備わっているもの

| 項目 | 実装 |
|---|---|
| **設定と code の分離** | 判定に効く閾値・条件・分類・業界・LLM の provider/model は `config/*.yaml`（CLI の実行上限は code に既定値） |
| **検索語の自動生成** | `discover_queries.py`。製品化事例側は人が語を書きません（失敗事例側は人の定義から出発します） |
| **循環の遮断** | 標識に使った語を**語幹の前方一致**で候補から除外（完全一致では `automat` → `automation` がすり抜けます） |
| **統計の足切り** | G²（2×2 完全形）と Log Ratio（効果量）の両方。既定 p=.001 かつ相対頻度2倍 |
| **小標本への耐性** | 適合率の判定は **Wilson score interval の下限**（点推定は 4/20 を 0.20 と読みます） |
| **母集団の無作為抽出** | 期間ごとに無作為 page。seed を `log/runs/*.json` に記録 |
| **原価と売価の区別（部分）** | 一致した語の周辺に打ち消し語（VPS・token costs・raises など）があれば数えません |
| **3値の状態** | 価格 page は「取得した／取得失敗／取りに行っていない」。report でも分けて表示 |
| **代替値で埋めない** | header 欠落・取得失敗は `SourceError`。0件では埋めません |
| **再現性の記録** | `log/runs/*.json`（git commit・引数・件数・失敗・host 別 request 数・sampling seed） |
| **中断耐性** | 全 file 書き込みは一時 file → `os.replace`。途中で止めても既存 file は壊れません |
| **request の上限** | `config/sources.yaml` / `config/discovery.yaml` の `budget` で host ごとに頭打ち |
| **一時失敗の再送** | 429 / 5xx / 通信断のみ指数 backoff。`Retry-After` は秒数と HTTP-date の両方、負値と NaN は拒否 |
| **robots.txt の尊重** | RFC 9309 の status 解釈 |
| **自動 test** | **51件**。network 遮断 fixture つき。今回直した bug の回帰 test を含みます |

### test の走らせ方

```bash
python -m venv .venv
.venv/bin/pip install -r requirements-dev.txt   # Windows: .venv\Scripts\pip
.venv/bin/python -m pytest tests -q
```

## 3. 次にやる順（効果 ÷ 手間）

**第1版から順序を入れ替えました。** 適合率を上げてから、母集団を広げます。

### Phase 1 — 判定を「語の一致」から「抽出値」へ

各事例の本文から構造化して抜き、**抜けなかったものは欠損のまま候補外**にします。

```
{ 売価, 通貨, 課金単位(月/席/従量), 支払主体, 提供者人数, 客の業種,
  毎回人が触る工程, 対象業務の発生頻度(毎日/毎月/年1), 収益実数と出所 }
```

- `売価` と `原価` を別 field にするだけで、§0 の3件は全て落ちます。
- `対象業務の発生頻度` が、`METHOD.md` §3 型4（解約が速い）の軸になります。
  **「最も致命的」と書いた軸が、初めて実装されます。**
- 抽出は `config/llm.yaml` の設定で行い、**抽出結果は必ず出所（本文の該当箇所）とともに保存**します。
  LLM の出力をそのまま証拠にはしません。

### Phase 2 — 観測単位を「投稿」から「価格表を持つ製品」へ

HN は残しますが、採否は製品 directory 側で決めます（日本: BOXIL / ITreview、英語: Product Hunt / Indie Hackers）。
record の必須 field を `価格表URL`・`月額`・`提供開始年` にし、**取れないものは一覧に載せません**。
これで `industries_jp.txt` の15業界に初めて日本の実在製品が入り、転用 worksheet が成立します。

### Phase 3 — 網羅率を測る

**capture-recapture（標識再捕獲法）**。独立な2つの検索語群 A・B の重なりから母集団を推定します
（Lincoln–Petersen `N ≈ |A|·|B| / |A∩B|`）。query 間に正の相関があるため Petersen は過小推定になります。
**捕獲確率の異質性を許す Chao の Mh 推定量を使い、下限として扱います。**
飽和判定（現在の `new_positives`）もこれに置き換えます。

### Phase 4 — 壊れないようにする

CI（push で pytest と config の regex 検証）、`schema_version`、日をまたぐ store、多重比較の BH法（FDR q=0.05）。

## 4. 「プロの道具」と呼べる条件（自己判定）

**第1版は「8項目中5つ」と書きましたが、甘すぎました。実態は3つです。**

| 条件 | 第1版 | 現在 | 理由 |
|---|---|---|---|
| 同じ入力から同じ出力が出る | 満たす | **部分** | 実行記録は5 tool に拡大。ただし失敗事例側の採否指標が手元の件数に依存します |
| 失敗が黙って結果に混ざらない | 満たす | **満たす** | 3値の状態を report まで通しました。0件で埋める箇所を除去しました |
| すべての数字に出所と取得日がある | 満たす | **満たす** | keyness の G² と効果量も記録に残るようにしました |
| 閾値と条件が code の外にあり履歴が残る | 満たす | **部分** | 判定の閾値は config、CLI の実行上限は code。doc の記述を実態に合わせました |
| 人の語彙に探索が縛られない | 満たす | **部分** | 製品化事例側のみ。失敗事例側は人の定義から出発します |
| **判定が測りたいものを測っている** | （項目なし） | **未達** | §0。ここが最大の問題です |
| 網羅の程度を数字で言える | 未達 | **未達** | Phase 3 |
| 情報源が1本でない | 未達 | **未達** | Phase 2 |

**満たすは2つ、部分が3つ、未達が3つです。**

現時点の一覧は、**候補の生成にも十分ではありません**。上位が誤検出で埋まるためです。
Phase 1 を終えて初めて「候補の生成には使える」水準になります。

## 5. レビューで見つかった不具合と、その扱い

Agent 4本（手法・code・doc 整合・調査有効性）による検証で見つかったもののうち、主要なものです。
**実測で再現を確認したものだけを載せています。**

| 見つかったもの | 実測 | 対応 |
|---|---|---|
| 価格 page への link 追跡が dead code（`for u in list(urls)`） | 41件中 2page 目を取れた事例 **0件** | 修正。回帰 test を追加（現在は追跡できています） |
| 「取得失敗」が report で「証拠なし」に化けていた | 11件が誤表示 | 3値に分離。report と欠損の節も修正 |
| 原価を継続課金と読んでいた | 上位3件すべて | 打ち消し語を導入。4軸該当は 3件 → **0件** に |
| 循環の遮断が語形変化ですり抜け | 採用語の6/10が標識語の語形変化 | 語幹の前方一致に変更。採用語は激減しました |
| 層化 sampling が層化でなかった | 9か月の期間から末尾13日分のみ | 無作為 page 抽出に変更（母集団 938 → 1815件） |
| G² が2 cell の近似だった | a=500,b=100 で 291.10 vs 完全形 299.35 | 完全形に置換。効果量（Log Ratio）と有意水準も追加 |
| 適合率が点推定 n=20 だった | 採用10語中2語が本来は棄却 | Wilson 下限に変更 |
| Qiita の header 欠落を「0件」にしていた | 規律3 違反 | `SourceError` に変更。test で固定 |
| `--dry-run` でも事例 file に書いていた | 再現性の破壊 | 修正 |
| jsonl の書き込みが非 atomic | 中断で file が縮み、しかも読めてしまう | 一時 file → `os.replace` に変更 |
| `Retry-After: -5` で `time.sleep` が例外 | 実行確認済み | 値域検査と HTTP-date 解釈を追加 |
| budget が2 tool にしか効いていなかった | doc の主張と不一致 | 全 tool に適用。`config/sources.yaml` に集約 |
| 日本語の提案語に統計的な足切りが無かった | 提案6語中3語が無関係 | G²・効果量・適合率下限で検証。**6語 → 1語**（確定申告、適合率下限 0.70） |
| n-gram を stopword 除去後に作っていた | `"browser automations"` という存在しない phrase を生成 | 除去前の token 列から作るよう変更 |

**未対応（Phase 1 以降で扱うもの）**: 判定の抽出化、観測単位の変更、失敗事例の撤退理由 field、
飽和判定の capture-recapture 置換、多重比較の補正、日をまたぐ蓄積、CI。
