# J: Indie Hackers を日本向け候補として使えるか — 裏取りの記録

取得日 **2026-08-18**

**この記録が埋める穴**: `C_discovery.md` は困りごとの発見元を扱っていますが、
海外の起業家 community を候補源として使えるかを検証していません。
本記録は Indie Hackers を候補源として実際に走査し、**出てきた候補を一次情報で潰した記録**です。

**結論を先に**: Indie Hackers から出た候補は、走査した範囲では **5件中4件が棄却**されました。
残る1件も、日本では掲載経路が閉じているため掲載型では成立しません。
**この source の価値は「候補の発見」ではなく「販路の実証事例」にあります。**

---

## 0. 情報源としての位置づけ

Indie Hackers の投稿・case study は `MARKET_RESEARCH.md` §2.1 の梯子で **6段目**
（実務家の実測値 開示、生き残りだけを見る偏り あり）です。
一部の「機会」記事は出典が無く **8段目（使わない）** に落ちます。

**したがって本 source は、単独では判断に使えません。** 本記録では全候補を
梯子2段目（配布元の実測値）または4段目（公的統計・所管省庁）に当ててから採否を決めています。

### 1.1 投稿の内訳 — 大半は「作る対象」ではない

実取得した投稿15件を分類したところ、**12件が「集客の問題」**で、
「作れば売れる」型の困りごとは **2件**（AI 生成 code の品質保証、AI 生成 spam の識別）のみでした。
comment 数上位3件（225 / 199 / 166）はすべて集客系です。

これは `MARKET_RESEARCH.md` §6.5「集客の手段が無い企画は、需要があっても成立しません」と
**独立に一致します。** 起業家 community で最も語られているのは、作る対象ではなく作った後の壁です。

## 2. 棄却した候補と、棄却の根拠

### 2.1 AI 生成 code の品質保証 — 棄却（0/3条件）

VS Code Marketplace を実測し、`config/thresholds.yaml` の `vscode.dev_keywords` にかけました。

測定 2026-08-18 / endpoint は `thresholds.yaml` 記載のとおり / 上位8件

| 条件 | 閾値 | `code review` | `ai code review` |
|---|---|---|---|
| C1 検索が薄い | hits ≤ 532 | 39,389 ✗ | 44,025 ✗ |
| C2 大きいが不評 | 導入 ≥ 813,364 かつ 評価 ≤ 3.833 | ✗ | ✗ |
| C3 放置されている | 更新月数中央値 ≥ 46.73 | 1.95 ✗ | 2.00 ✗ |
| **判定**（2/3で通過） | | **0/3 棄却** | **0/3 棄却** |

上位の顔ぶれは Bito（導入 947,864 / 評価 4.22 / 更新 0.2か月）、
Qodo（導入 896,594 / 評価 4.68 / 更新 1.5か月）。**大手が高評価で占拠し、全社が活発に更新しています。**

> **注意**: 先に WordPress.org API で同じ語を測りましたが、**生態系の選定を誤っていました。**
> AI code 品質保証の主戦場は WordPress ではありません。VS Code 側の数値を正とします。

### 2.2 Chrome Manifest v2 廃止に伴う空席 — 棄却（期限切れ）

Chrome 公式 timeline（`developer.chrome.com`、取得 2026-08-18）:

- 2025年3月31日: 全 channel で MV2 拡張が既定で無効化
- **2025年7月24日（Chrome 138）: 無効化完了**
- 2026年8月31日: Chrome Web Store から残存 MV2 拡張を撤去

**user は1年以上前に代替へ移行済みです。** 空席は既に埋まっています。

### 2.3 goo.gl 廃止に伴う link 修復需要 — 棄却（期限切れ＋前提の逆転）

Google 公式（`developers.googleblog.com`、取得 2026-08-18）:

- 停止日は **2025年8月25日**。本日時点で約1年経過
- さらに **Google が方針を撤回**し、「2024年後半に利用のない link のみ停止、他は存続」に変更

記事の前提「数百万の link が一斉に切れる／約100万 site が該当」は**成立していません。**
`goo.gl/*` に HTTP 要求を投げ、404 が返ることも確認済みです。

### 2.4 月$29〜$49 帯の単機能 SaaS — 棄却（単価が成立しない）

`tools/economics.py --sweep`（前提は `config/economics.yaml`）:

| 目標粗利/月 | 月4,500円 | 月15,000円 | 月50,000円 | 月150,000円 |
|---|---|---|---|---|
| 5万円 | **不可** | 可 | 可 | 可 |
| 10万円 | **不可** | 可 | 可 | 可 |
| 30万円 | **不可** | **不可** | 可 | 可 |

**月4,500円（≒$30）帯は、目標を副業月収の中央値5万円まで下げても成立しません。**
月4,500円で目標30万円を作るには95.2契約が要り、個別の声かけの維持上限12.1件を大きく超え、
掲載でも月802件の導入増が必要で実測分布の範囲外です。

Indie Hackers で目立つ `$29/月`（Postiz）・`$49/月`（Gleap 下位 tier）はこの帯です。
これらが海外で成立しているのは**掲載型で桁違いの母数に届いているから**であり
（Postiz は Reddit 1投稿で10万 view、GitHub trending）、
**日本語圏で同じ母数が出るかは未検証です。**

### 2.5 期限つき機会に共通する構造上の欠陥

2.2 と 2.3 は、いずれも Indie Hackers の「機会」記事に由来します。

> **この種の記事は執筆時点の期限つき event を扱うのに、database として蓄積され掲載され続けます。**
> **日付を確認せずに着手すると確実に空振りします。** 候補源として使うなら、
> 記事の日付と、書かれている期限が未来か過去かを最初に確認してください。

## 3. 日本の制度が強制発生させている需要（一次情報）

棄却を免れた唯一の領域です。**期限が過去ではなく未来**である点が 2.2 / 2.3 と決定的に違います。

出典はすべて所管省庁。取得日 2026-08-18。

### 3.1 令和8年10月1日に同時発生（本日から44日）

| 制度 | 内容 | 出典 |
|---|---|---|
| Invoice 経過措置 | 80%控除 → **70%控除** | 国税庁 Q&A 問113【令和8年4月改訂】 |
| 控除限度額 | 免税事業者からの仕入れ **10億円 → 1億円** | 同上 |
| 2割特例 | 令和8年9月30日の属する課税期間で終了 | 国税庁 |
| Customer harassment 対策 | 事業主に措置義務化（中小企業の猶予規定なし） | 厚労省 |
| 社会保険 賃金要件 | 年収106万円の壁を撤廃 | 厚労省 |

> **「80%→50%」は誤りです。** 令和8年度税制改正（令和8年3月31日成立・公布）で
> 適用期限が2年延長され、70% が新設されて「7・5・3割控除」になりました。
> **二次情報にはまだ旧内容が流通しています。** 一次情報で確認してください。

### 3.2 控除割合の推移（国税庁 Q&A 問113 の表のまま）

| 期間 | 割合 |
|---|---|
| 令和5年10月1日 〜 令和8年9月30日 | 80% |
| 令和8年10月1日 〜 令和10年9月30日 | 70% |
| 令和10年10月1日 〜 令和12年9月30日 | 50% |
| 令和12年10月1日 〜 令和13年9月30日 | 30% |
| 令和13年10月1日 以後 | 控除不可 |

### 3.3 その後に確定している改定

| 時期 | 内容 | 出典 |
|---|---|---|
| 令和9年10月 | 社会保険の企業規模要件 51人 → 36人（以後 R11:21人 / R14:11人 / R17:10人以下） | 厚労省 |
| 令和9年分以後 | 青色申告特別控除 55→65万円（e-Tax 必須）、65→75万円（優良な電子帳簿等が必須） | 財務省 大綱 |
| 令和9・10年分 | 3割特例（個人事業者のみ。法人は適用不可） | 国税庁 |
| 2027 / 2028 / 2029年9月 | 厚生年金 標準報酬月額の上限を 68→71→75万円 | 厚労省 |

### 3.4 最も注目すべき1点

**仕入先別・年間累計1億円の判定**が新規に必須化されます（令和8年10月1日以後に開始する課税期間）。
従来の10億円判定では対象がほぼ大企業に限られていましたが、1億円まで下がることで該当が大きく増えます。
**「仕入先ごとに年間累計を追跡する」軸は、従来の会計処理には存在しませんでした。**

### 3.5 未確認（この需要を採用する前に潰すこと）

- **freee・マネーフォワード・弥生が実装するはず**です。制度対応は会計 software 大手の中核責務であり、
  同じ機能で競合しても勝てません。**「大手が実装しない隙間」の実在は未確認です。**
- 電子帳簿保存法の猶予措置は**適用期限の日付が一次情報に存在しません**。
  「保存できる環境が整うまで」という状態依存の限定のみです。

## 4. 日本に、個人が掲載できる場所はあるか（決定的な制約）

Indie Hackers の case study 10件で最強の単一 channel は**既存 marketplace への掲載**でした
（Zigpoll: Shopify App Store が新規登録の33%で最大源）。
`MARKET_RESEARCH.md` §6.5.1 の「掲載型のみが12.1件の上限を超えられる」と一致します。

**したがって日本向けの可否は「日本に、個人が掲載できる marketplace が実在するか」に還元されます。**

運営元の公式 site のみで確認。取得日 2026-08-18。

| 掲載先 | 個人（非法人）の可否 | 根拠 |
|---|---|---|
| **Shopify App Store** | **可** | 規約が Partner を "an individual or entity" と定義。**日本法人登記の要件なし**。登録は一回 $19、revenue share は年$1,000,000 まで開発者100%、超過分85% |
| **MakeShop apps** | **可** | 登録 form の「事業形態」で法人／個人を選択可。一般公開は料率10%（makeshop 決済）／20%（独自決済） |
| BASE デザインマーケット | 可（theme のみ、app 不可） | 公式 FAQ が個人登録を明記。手数料30% |
| カラーミーショップ | **確認不可** | 個人可の明記なし。公開申請時に「会社情報」入力あり。料率非公開 |
| STORES | **確認不可** | 規約は「個人である開発パートナー」を想定するが、登録 form の必須項目に「法人名」 |
| **freee アプリストア** | **不可** | 規約 第4条2項「アプリ開発者が**日本国内に登記されている法人でない場合**」は不承諾 |
| **kintone / サイボウズ** | **不可** | 「**法人格をもつ企業のみ**」「個人事業主は登録不可」 |
| **LINE** | **不可** | 「**所定の申請等を行った法人ユーザーのみ**」。申込は営業経由 |
| マネーフォワード | 確認不可 | 第三者 app を一般公開する仕組み自体が公式 document に存在せず |
| BASE Apps | 不可（全事業者） | 「現在、BASE の公式 Apps への申請や公募は、おこなっておりません」 |

### 4.1 この表が意味すること

**§3 の制度起因需要と、個人が使える掲載経路は、直接には交差しません。**
税務・会計・業務系の掲載先（freee / kintone / LINE）はいずれも法人限定で、個人には閉じています。

**日本の制度対応 software を個人が作る場合、掲載型は使えず、個別の声かけに限定されます。**
その場合 §6.5.1 の維持上限12.1件が効き、`economics.py` の逆算から**単価は月5万円以上が必要**です。

## 5. 生き残った経路は2つだけ

| 経路 | 販路 | 必要単価 | 主な未確認事項 |
|---|---|---|---|
| **A. Shopify App Store** | 掲載型（上限なし） | 目標30万円なら月5万円以上 | 日本語圏の母数。日本語 listing の空席（下記） |
| **B. 日本の制度対応** | 個別の声かけ（上限12.1件） | 月15万円級（目標30万円で2.9契約） | 大手が実装しない隙間の実在 |

### 5.1 経路A に付随する未検証の仮説

Shopify の公式 changelog より（取得 2026-08-18）:

- app listing の**自動翻訳の対象8言語**（Brazilian Portuguese, Danish, Dutch, French, German,
  Simplified Chinese, Spanish, Swedish）に **日本語は含まれない**。日本語 listing は手動追加が必要
- 一方、App Store の**日本語検索は 2025年5月21日に改善**（同義語・文字 matching・autocomplete）

**仮説**: 海外開発者は日本語 listing を手動で作らないため、日本語検索での上位が空いている可能性がある。

**この仮説は未検証です。** `apps.shopify.com/search` の結果は client-side 描画で
HTML には出ず、実 browser も本環境の proxy 経由では全 site に到達できませんでした
（`example.com` も `ERR_CONNECTION_RESET`）。**回避策は取っていません。**

**検証方法**: 通常の網からの実 browser で、`請求書`『在庫管理』等の日本語語で検索し、
上位8件の listing が日本語か英語か、導入数と評価、直近3年の参入の有無を数えてください
（`MARKET_RESEARCH.md` §4 段階0 の「掲載・記事ありの場合」の2条件）。
