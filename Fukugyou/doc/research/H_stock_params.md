# H: 掲載からの集客数 — 実測

測定日 **2026-08-12** / 対象: WordPress 追加機能 API（`api.wordpress.org/plugins/info/1.2/`、無料・認証不要）
標本: 業務系の検索語 **22語**（`G_thresholds.md` §1.1 と同一）× 上位8件 = **172件**（登録から6か月未満を除外）
生 応答: `log/raw/wordpress/20260812/`（語ごとに1 file。`tools/scan_stock_params.py` が保存）

**この記録が埋める穴**: `MARKET_RESEARCH.md` §9 の「掲載からの集客量 は未測定」。
§6.5.1 表B の数値は仮の設定値でしたが、本記録で**実測値に置き換えました**。

---

## 0. 先に、使えなかった指標

**`downloaded`（累計ダウンロード数）は到達量の指標として使えません。撤回します。**

WordPress の `downloaded` は**自動更新のダウンロードを含みます**。導入数30万件の
`woocommerce-pdf-invoices-packing-slips` は累計23,402,712 DL・登録から12.5年で、
月あたり156,000 DL になりますが、これは新規利用者の数ではなく**既存30万件への更新配信**が大半です。

一度この指標で「掲載1件あたり月2,166 DL（中央値）」という値を出しましたが、**破棄しました。**
使えるのは `active_installs`（実際に有効な導入数の stock）だけです。

## 1. 中核の実測値 — 導入数の月あたり増加

`active_installs ÷ 登録からの経過月数`。**これが掲載からの集客量 です。**

| 参入時期 | n | 月あたりの導入増 p25 | **中央値** | p75 |
|---|---|---|---|---|
| **参入3年以内** | 23 | 6.3件 | **36.2件** | 90.8件 |
| 3〜6年 | 27 | 5.9件 | 38.1件 | 106.4件 |
| 6〜10年 | 61 | 10.4件 | 52.6件 | 312.8件 |
| 10年超 | 61 | 22.8件 | 171.0件 | 1,295.1件 |

**これから参入する人が参照すべきは1行目です。** 6〜10年・10年超の行は、
**上位8件に残れた掲載だけを見ている生き残りだけを見る偏り**（`MARKET_RESEARCH.md` §1 第5条）を含みます。
参入3年以内の行にも同じ 偏り はありますが、**期間が短いぶん 偏り も小さい**という以上のことは言えません。

**限界**: `active_installs` は**有効数字1桁に丸められます**（実測確認済み）。
小さい値ほど相対誤差が大きく、導入数90件の掲載は実際には50〜149件のどこかです。
また増え方は解約後の残存なので、**粗い獲得数より小さい値**です。

## 2. 新規参入は、そもそも上位8件に入れているか

**22語中 9語は、上位8件に「直近3年に登録された掲載」が1件もありません。**

```
accounting / asset management / compliance audit / contract management / crm /
digital signature / invoice / purchase order / timesheet
```

**この9語は、新規参入が上位に食い込めていない領域です。** 導入数の大きさとは無関係に、
ここは段階0 で落とせます。**残る13語（59%）だけが、掲載・記事の販路として検討に値します。**

上位8件に入れた新規参入23件の導入数分布: p10 **42** / p25 **90** / 中央値 **700** / p75 **2,500** / p90 **30,000**。

実際に入れた上位10件:

| 掲載 | 検索語 | 導入数 | 経過 | 月あたりの導入増 |
|---|---|---|---|---|
| woocommerce-shipping | shipping | 70,000 | 24.4月 | 2,867.8 |
| simplybook | booking calendar | 30,000 | 28.2月 | 1,063.1 |
| stripe-tax-for-woocommerce | tax calculation | 30,000 | 24.8月 | 1,211.1 |
| chatway-live-chat | helpdesk | 30,000 | 33.1月 | 905.1 |
| fluent-booking | appointment scheduling | 20,000 | 24.9月 | 804.2 |
| catfolders-document-gallery | document management | 3,000 | 34.8月 | 86.3 |

**上位5件はいずれも既存企業の製品です**（WooCommerce 本体、SimplyBook.me、Stripe、Chatway、FluentCRM）。
**個人が参照すべきは6位以下**で、そこでの月あたりの導入増は **36〜96件**です。中央値36.2件はこの帯にあります。

## 3. 【最重要】掲載・記事は、契約数では個別の声かけに勝ちません

`doc/verify/X2_reachmath.md` §2.3 は「掲載・記事は同じ時間で個別の声かけの **8.6〜57倍**」としましたが、
**あれは仮の設定値（資産1単位あたり月20到達など）による計算でした。** 実測で置き換えます。

| 販路 | 到達 | 定常契約数 | 要する時間 |
|---|---|---|---|
| **個別の声かけ**（1対1接触） | 月121.3人接触 × 成約0.5% | **12.1件** | **月30.3時間を永続** |
| 掲載・記事 新規参入 p25 | 月6.3導入 × 転換1% | 1.3件 | 月4時間 |
| **掲載・記事 新規参入 中央値** | 月36.2導入 × 転換1% | **7.2件** | 月4時間 |
| 掲載・記事 新規参入 p75 | 月90.8導入 × 転換1% | 18.2件 | 月4時間 |
| 掲載・記事 新規参入 中央値 | 月36.2導入 × 転換3% | 21.7件 | 月4時間 |

（解約 月5%。構築40時間は初期費用として別途）

**中央値の掲載1件（7.2契約）は、全力の1対1接触（12.1契約）に契約数で負けます。**
X2 の「掲載・記事に変えれば月4,500円でも成立する」は、**中央値では成立しません。**

### 3.1 それでも掲載・記事を選ぶ理由は、時間あたりの効率です

| 販路 | 月1時間あたりの定常契約数 | 個別の声かけ比 |
|---|---|---|
| 個別の声かけ | 0.40件 | 1.0倍 |
| 掲載・記事 中央値・転換1% | **1.81件** | **4.5倍** |
| 掲載・記事 中央値・転換3% | 5.43件 | 13.6倍 |
| 掲載・記事 p75・転換1% | 4.54件 | 11.3倍 |
| 掲載・記事 p75・転換3% | 13.62件 | 34.0倍 |

**倍率は「月4時間で」の値です。** 週7時間（月30.3時間）を全部掲載・記事に投じられるなら
掲載を複数持てますが、**掲載を7本作っても検索順位は7倍にならない**ので、この外挿は成立しません。
実務的には「**掲載1〜2本＋残りの時間を個別の声かけに**」が現実的な形です。

### 3.2 したがって正しい結論

> **掲載・記事の優位は「同じ時間でより多く届く」ではなく「**少ない時間で、止めても消えない到達を持てる**」ことです。**
> **契約数そのものを増やしたいなら、上位25%の掲載（月90件以上の純増）に入る必要があります。**
> **中央値の掲載では、目標粗利は月5万〜9万円が上限です。**

## 4. 目標別に必要な導入増え方（転換1% / 解約5%）

★＝実測中央値36.2件で届く、△＝p75の90.8件で届く、無印＝実測の範囲では届かない

必要な月あたり導入増 = `M ÷ 転換率`、`M = c·B ÷ (1 − e^(−c·T))`（到達に必要な獲得。**維持に必要な数ではない**）。

| 目標粗利/月 | 単価4,500円 | 単価15,000円 | 単価50,000円 | 単価150,000円 |
|---|---|---|---|---|
| **50,000円（中央値）** | 134件 | 40件 △ | 12件 ★ | 4件 ★ |
| **92,445円（平均）** | 247件 | 74件 △ | 22件 ★ | 7件 ★ |
| **200,000円** | 535件 | 160件 | 48件 △ | 16件 ★ |
| **500,000円** | 1,337件 | 401件 | 120件 | 40件 △ |

**読み方**: 副業月収の中央値（月5万円）を狙うなら、**単価50,000円で掲載1本**が実測の中央値で届きます。
単価15,000円だと上位25%が要ります。**月50万円は、単価150,000円でも上位25%が必要です。**

> **初出時、この表は誤っていました。** 必要な月あたり導入増に「維持に必要な数（契約数×解約率）」を使っていました。
> 正しい式は上記で、18か月到達なら維持の1.68倍です。`tools/economics.py` の検算で発見しました。

## 5. 減衰率（δ）— 測ろうとして、交絡で測れませんでした

最終更新からの経過月数で層別すると、こうなります。

| 最終更新 | n | 導入数の中央値 |
|---|---|---|
| 0〜1か月前 | 105 | 10,000 |
| 1〜3か月前 | 50 | 1,500 |
| 3〜12か月前 | 13 | 3,000 |
| 12か月以上前 | 4 | 70 |

差は大きく見えますが、**これは減衰の測定になっていません。** 更新を止めた掲載は
**元から人気が無かった可能性**が排除できず（逆因果）、しかも12か月以上の層は n=4 しかありません。

**したがって δ は未測定のままです。** §6.5.1 では δ を明示的に使わず、
「導入数の月あたり増加」という観測可能な量で直接計算する形に変えてあります。

**言えることは1つだけ**: 上位8件に残っている掲載の **61%（105/172）が直近1か月以内に更新されています。**
**上位に居続けるには継続的な更新が要る**、という以上のことは、この数値 からは言えません。

## 6. 未確認のまま残るもの

| 項目 | 状態 |
|---|---|
| **無料→有料の転換率** | **未測定。** §3・§4 の1%と3%は仮置きです。この値が結論を最も強く動かします |
| **減衰率 δ** | **測定不能**（§5。逆因果と小標本） |
| WordPress 以外の生態系の増え方 | **未測定。** Atlassian は `totalInstalls` が取れるので同じ測定が可能ですが、今回はやっていません |
| 日本語圏の販路（BOOTH・ココナラ等）の到達量 | **未測定。** 導入数に相当する公開値が存在しません |
| 上位8件に入れなかった掲載の分布 | **測っていません。** 本記録は全部「上位8件に入れた掲載」なので、**強い生き残りだけを見る偏り があります。**「上位に入れればこれくらい」であって「参入すればこれくらい」ではありません |

**最後の項目が本記録の最大の限界です。** 分母（参入したが上位に入れなかった掲載）を
測る方法が WordPress API にはありません（検索結果は上位しか返らない）。

## 7. 再現方法

```bash
python tools/scan_stock_params.py --keywords config/keywords_business.txt --top 8
```

または直接:

```bash
curl -sg "https://api.wordpress.org/plugins/info/1.2/?action=query_plugins&request[search]=invoice&request[per_page]=8"
```

`added`（登録日）と `active_installs` を取り、`active_installs ÷ 経過月数` を語ごと・順位ごとに集計します。
**平均は出さないこと**（`AUTOMATION.md` §2 制約7）。分布（p25 / 中央値 / p75）で持ちます。
