## 0. 前提の整理（第1版から後退させた箇所を含む）

| 論点 | 本版の立場 | 根拠の状態 |
|---|---|---|
| ジャンル選びの調査 | **工程を1つ割く価値はない。ただし禁止もしない。** 段階0 で3領域を比べる30分は使う価値がある | **第1版の「やらない」は撤回。** 根拠にしていた3つのうち、べき乗則による説明は成立せず、5.6倍対400倍は分散の分解ではなく（対数尺度で **η²（説明できる割合） ≈ 9.5%**）、自前調査35,995件で差が出なかったのは測り方で説明が付きます（§0.1）。「情報がゼロ」ではなく「**工程を割く価値はないが、3択に30分かける価値はある**」水準 |
| TAM / SAM / SOM | **省略してよい** | 予測妥当性を検証した査読論文が発見できなかったため。「無効という証拠がある」ではなく「有効という証拠が無い」という控えめな根拠付け |
| 成功事例からの逆算 | **手法として使わない** | Denrell (2003, *Organization Science*) の数理模型 と Golder & Tellis (1993) の実証。検証で無傷 |
| 「激戦区を避けろ」 | **根拠のない通説として扱う** | Golder & Tellis: 最初に市場を作った企業の失敗率 **47%**、長期にわたり首位を保った企業は 50分野中 **4社** のみ。母集団の作り方が明示されている |
| 調査の目的 | **「当たりを見つける」でなく「外れを安く捨てる」** | 無作為化試験2本（116社 / 759社）。はっきり出た効果は売上増ではなく **見込みの無い案を早くやめること**。検証で強化された（§0.2） |

### 0.1 自前調査（35,995件でジャンル間の差がほぼゼロ）の読み直し

べき乗則を根拠にできない以上、別の説明が要ります。有力なものが2つあります。

- **測り方の問題**: 候補の検索語を、どのジャンルについても同じ手順（同じ道具の候補表示を展開、同じ起点の語の作り方）で集めたなら、ジャンルは「性質の違う集団」ではなく**同じ手順で作った語の束に貼ったラベル**にすぎません。平均が揃うのは当たり前で、需要の性質ではありません。→ **確認すべきこと: ジャンルごとに集め方が違ったか、起点の語が別々の由来だったか。同じ手順なら、あの実験はジャンルを測っていません。**
- **指標の問題**: 「平均」は分布の差を消してしまいます。RevenueCat は「2年以内に月$10,000へ届いた割合」という別の指標で、ジャンル間に5.6倍（オッズ比6.0）の差を検出しています。**平均では消える差が、到達率では残ります。**

したがって当時の結論は「ジャンルに情報が無い」ではなく「**使った指標に情報が無かった**」可能性が高いです。あの道具を再開する必要はありませんが、やめた理由は書き換えてください。

### 0.2 この前提と正面から緊張関係にある反証（第1版で落としていました）

**Gompers, Kovner, Lerner & Scharfstein (2010), *Journal of Financial Economics* 96(1)** は、VC の出資を受けた起業家の次回成功率を、前回成功 30% / 前回失敗 22% / 初回 21% と報告しています。そして**次の成功を最もよく予測するのは「伸びる業種と、伸びる年を選ぶ力」**であって、経営やアイデアの質ではない、と分解しました（1983年創業のコンピュータ企業は52%が上場に届き、1985年創業は18%）。

つまり「いつ・どの業種で始めるか」が繰り返し効く力として観測されており、本手順書の「領域選びは決め手ではない」という立場と衝突します。

**それでも領域選びに工程を割かない理由**は3つです。(1) 対象がVC出資かつ上場到達の企業で、個人が作る道具とは分布がまるで違う、(2) 著者ら自身が「成功者と見なされると資源が集まる」という自己成就の面があると書いている、(3) **「伸びた業種・伸びた年」は後になって分かるもので、始める前に測れる項目ではない**。

3点目が実務的な決め手です。反証は棄却したのではなく、**事前に使える形になっていない**ため採用していません。

## 1. 設計原則（7条）

1. **調べる単位をジャンルでなく「自分 × 特定の相手 × 特定の作業」に置く。** ジャンルで説明できるのは結果の1割ほどで、ゼロではないが工程を割く水準ではありません。
2. **探す起点を市場でなく自分（同じ分野での実務経験）に置く。** Azoulay et al. (2020) の行政記録ほぼ全件で、同じ分野の経験がある人の急成長（上位0.1%）到達率は **0.11% → 0.26%**（約2.4倍）。決定打ではありません。効くのは経験年数ではなく **その相手のその作業を、どれだけ内側から知っているか** で、そこまで具体化して初めて効きます。（確信度 高）
3. **調べる前に「何が起きたら間違いと分かるか」を書く。** ただ情報を集めるだけの行為に効果があるという証拠は確認されていません。（確信度 中〜高）
4. **成果は「何個を、どれだけ安く、確信を持って捨てられたか」で測る。** 残す成果物は「有望な候補の一覧」ではなく **「捨てた候補と、捨てた理由の一覧」**。少ない件数で確実に言えるのは否定側だけです（§3 段階5）。（確信度 中〜高）
5. **成功者の「事実」（値段・時期・売り方）は使い、「なぜ成功したかの説明」は証拠にしない。** 併せて **失敗した側も数える**（撤退した競合を探す）。（確信度 高）
6. **市場の大きさでなく「自分が実際に届けられる集客先」を実測する。** さらに **「空いているかを測ってから入る」のではなく「数字が見える集客先を持つ市場を選ぶ」**。空きを入る前に測る確実な方法は無く、唯一の例外が導入数を公開している配布先です。（確信度 中）
7. **引用する数字は原典に当たる。辿れなければ使わない。標本・期間・分母を必ず書く。**（確信度 高）

> 第1版はこの第7条を自分で破っていました。標本の誤帰属1件、算術不一致1件、別指標の転用1件、版の混成1件、元 document に無い数値1件。本版では §10 に検証記録を置き、数値には標本を併記します。

## 2. 情報源の採否ルール

### 2.1 証拠の強さの順位

上ほど強い。**下位の情報は上位の情報を覆せません。**

```
1. 自分の実験 数値（自分が受け取った金、2か月目の継続決済）
2. 配布元の実測値（導入数、downloads、質問件数 — 推定ではない実数）
3. 査読論文・無作為化試験
4. 公的統計（e-Stat, 就業構造基本調査, BLS, Census）
5. 企業の公開されている数値（利害あり。標本定義が書いてあるものに限る）
6. 実務家の実測値 開示（survivorship 偏り あり）
7. 逸話・体験談
8. 出典なき記事 ← 使わない
```

### 2.3 数値 に支持されたもの（標本つき）

- **96.55% の ページは Google からの流入がゼロ**（Ahrefs, 2023-12-01、約140億ページ。ただし 索引全体 3,408億ページ の一部・検索語 6.51億という 注記 が原典に明記）。「SEO は無駄」ではなく「**既定値は流入ゼロであり、それを覆す理由の説明が必要**」の意味。
- **副業月収は中央値 5万円 / 平均 92,445円、5万円未満が 41.2%**（JILPT 調査series No.245、副業者 n=11,358、web monitor 調査、実施2022-10）。**正規の職員・従業員の副業実施率は 2.5%**（総務省 令和4年就業構造基本調査、副業者305万人・比率4.8%、分母は非農林業従事者）。→ **§4 の金額宣言の目安を置ける唯一の公的分布です。**
- **生産性の体感は測定の代わりにならない**（METR 無作為化試験, arXiv:2507.09089。熟練 open-情報源 developer 16人 / 実issue 246件。AI 使用時 19% 遅く、事前予測 +24%、事後自己評価 +20%。METR 自身が本結果を historical と 名前 している点も併記）。

### 2.4 記事を読むときの判別

数字を見たら必ず問う: **標本は何件か / 期間はいつか / 誰が集めたか / 分母は何か / これを書くと誰が得をするか。** 分布を示さず金額だけを出す記事は統計ではなく広告です。日本のステマ規制（2023-10-01 施行）の**規制対象は広告主のみ**で書き手に表記義務はなく、消費者庁も「広告主は掲載後に全ての表示内容の確認を行っていない」と明記しています。review 記事の既定値は「実体験」ではなく「成果報酬」に置いてください。

## 3. 調査の流れ（全18週）

第1版は12週でしたが、**継続収入型の唯一の真の証拠である「2回目の入金」が入っていませんでした**。有償提供を復活させて16週に延ばし、第3版で工数を積み直して18週（週0〜17）としています。**延びた2週は工数ではなく、聞き取りが週7時間の予算に収まらなかった分です**（`doc/WORKFLOW.md` §0）。

```
段階0  棚卸し・逆算・販路・規約確認  週0〜1   7.0h
   ↓ 関門: 集客の手段を宣言 / 個別の声かけは上限12.1件・掲載・記事は新規参入の実績 / 支援工数 ≦ 15.2h / 当事者1名 / 決済
段階1  困りごと集めと相手探し      週1〜4  14.0h
   ↓ 関門: 同一の困りごと5人(投資済み3人) / 相手45名 / 経路別の返信数を記録 / 反証1件
段階2  混み具合調べ                週2       3.5h
   ↓ 関門: 判定式4条件のうち2つ以上 ＋ 絶対条件(新規参入の実績・決済の仕組み)
段階3  聞き取り12件                週4〜8  24.0h
   ↓ 関門: 12件中7件が同じきっかけ（3経路以上に分散していること）
段階4  有償提供 3名                週9〜16 26.0h
   ↓ 関門: 3名全員が2回目も支払ったか
段階5  先行販売                    週9〜17 10.5h
   ↓ 関門: 事前に宣言した件数（分母つき）
着手判断
```

**段階2 を週3から週2へ前倒ししています。** 実測棄却率64%（22語中14語を落とす）で工数3.5時間と、**最も安く最も多く殺す関門**だからです。第2版はこれを週3に置き、最も高く最も殺さない関門（段階4）に全工数の46%を配っていました。

週7時間（平日夜1時間×3日＋週末4時間）。**週末4時間のうち「整理と判断」の1時間は絶対に削らないこと。** 無作為化試験が示す効果は 数値を取ることではなく、取った 数値で判断を更新することから来ています。

### 段階0: 棚卸し・逆算・販路・規約確認（週0〜1 / 7.0時間）

| 作業 | 時間 |
|---|---|
| 過去2年で「自作した 道具 / spreadsheet」を全部書き出す | 1時間 |
| そのうち、同僚や取引先も同じ物を作っていた（または欲しがった）ものに印をつける | 30分 |
| 印がついた領域を3つに絞り、**§3.1 の検索先と 検索語** で30分ずつ観察して1つに決める | 1.5時間 |
| **§6.4 の逆算表を自分の数字で埋め、必要月次純増契約数を出す** | 30分 |
| **採用する決済の仕組み と、type 別の前提を確認（§7）** | 1時間 |
| 決めた理由と「これが外れる条件」を書く。**§4 の判定基準表を全部埋める** | 1.5時間 |

**関門（4つとも満たすこと。1が最優先）**

1. **販路がある**（§6.5）。**これが最初の関門です。** 以下を数字で埋められること。
   - 必要な集客数 ＝ 必要月次純増契約数 ÷ 想定成約率（§6.5.1）
   - 手持ちで届く人数 ＝ 今すぐ実名で挙げられる相手の数
   - 差分をどの販路で埋めるか。その販路が**事前に測れるもの**か（§6.5.3）
   - **必要な集客数が手持ち＋販路で賄えないなら、単価を上げて必要人数を減らす。** それでも届かない企画は、ここで捨てます。聞き取りに進んでも意味がありません
2. **その作業をどれだけ内側から知っているか**: 「その顧客のその作業について、外部の人間が知らないことを1つ以上、具体的に書ける」。書いた内容を、**その領域の当事者1名に見せて承認を得る**こと。自己申告のみでは通しません。
3. **必要月次純増契約数が出ている**（§6.4）。1の入力になります。
4. **決済の仕組み が実在する**。配布元に課金機構が無い型（Chrome / VS Code / Obsidian / WordPress.org）を選ぶ場合、license key 検証 server の運用が発生し、これは「stock」の前提を崩します。承知の上か確認してください。

**印がつく項目が1つも無ければ、領域選定をやり直します。**

### 段階1: 困りごと集めと相手探し（週1〜2 / 14.0時間）

| 作業 | 週あたり |
|---|---|
| 観察・記録（§3.1 の検索先と 検索語） | 2時間 |

#### 3.2.1 自分で記事を書くこと — 候補者の発見手段としては数えない

**「対象領域で困った経験を Qiita / Zenn / note に書き、反応した人を候補者にする」という手は、経路から外しました。**

第1版では別の経路として置き、元資料（`research/C_discovery.md` §6.2.2）の「日本語圏で最も費用の低い候補者発見法」という記述をそのまま引き継いでいました。**しかしその節で出典と確信度が付いているのは 配布元の規模だけで、「候補者発見に効く」という効果の主張には出典も確信度もありません。** 順位付けは私が独自に付けたもので、元資料にはありません。

**効果を確認できていない上に、確認済みの数字から見て期待値はほぼゼロです。** Qiita は月間 PV 5,000万・月間 UU 800万（公式発表）ですが、閲覧は人気記事に極端に偏るため、無名の書き手による新規記事の閲覧数は中央値でみれば平均を大きく下回ります。そこから「読んだ人のうち書き込む人」「書き込んだ人のうち当事者」と掛け算が続きます。**記事を書いて反応を待つ設計にすると、段階1 は何も起きないまま2週間が過ぎます。**

**それでも記事を書く価値は別のところにあります。**

- **名乗りになる。** 経路1・2・3で声をかけるとき、「この領域でこういう記事を書いた者です」と示せると、見知らぬ個人からの連絡という最大の障壁が下がります
- **非同期で費用がかからない。** 背景で走らせておく分にはよく、当たれば儲けものです

**ただし、届く人数には計上しないでください。** 計上した瞬間、実体の無い数字で §6.5.1 の必要な集客数を賄ったことになります。

#### 3.3 日本語圏で効かない経路

**見知らぬ個人への突然の連絡（見知らぬ相手への突然の連絡）は忌避されやすく、紹介の重みが大きい**——これが日本語圏の一次情報収集の前提です。したがって経路1・2を先に埋め、3・4・5を補助に使います。**ただし経路3（求人・外注の募集主）は「見知らぬ個人からの連絡」ではありません。相手が公開の場で募集を出しており、返信は想定内です。**

**ただしこの認識には統計的裏付けがありません。** 日本の B2B における 見知らぬ相手への突然の連絡 の反応率を測った 数値 は、本調査では発見できませんでした（参考: 英語圏の 見知らぬ相手への突然のメール 返信率は2024年で3〜5.1%程度という集計がありますが、販売元の b記録による集計で確信度は低）。**実務家の間で広く共有された認識である、という以上のことは言えません。** 自分の実測（§6.5.2）で置き換えてください。

#### 3.4 やってはいけないこと（法令）

**以下は法律の助言ではありません。該当し得る論点の一覧です。適用の有無は事業の形態で変わるので、判断は専門家に確認してください。**

- **紹介ページに価格を出して、実際には販売しないこと。** 景品表示法第5条第3号に基づく「おとり広告に関する表示」（平成5年公正取引委員会告示第17号）の**第1号（取引に応じることができない場合）・第4号（取引する意思がない場合）**に該当し得ます。**ただし告示の主体要件は「一般消費者に販売・提供することを業とする者」なので、売り先が事業者のみなら射程外になり得ます。** 一般消費者向けなら、価格ではなく「案内を受け取る」形にしてください
- **先行販売を行う場合、特定商取引法第11条の通信販売の表示**（提供時期・返品に関する事項・事業者情報など）。**ただし法第26条により「営業のため、又は営業として締結するもの」＝事業者間取引は適用除外**です。また事業者情報は「請求があれば遅滞なく提供する」旨の措置で省略できますが、**返品に関する事項は省略できません**
- **勤務先の守秘義務。** 現職の取引先に声をかける場合、業務で知った情報を私的な事業に使うことになっていないかを確認すること

> **第1版はこの後半4時間を削除したまま、段階3 の「12件」だけを維持していました。** その状態では 調査の流れ は第3週で物理的に停止し、しかも停止の原因が「手順の欠落」なのに「この領域は駄目だった」と誤読されます。設計上の欠陥が仮説の失敗に化けるのが最悪の形です。

**この 工程 は「相手探し」であると同時に「販路の最初の実測」です。** 15名に声をかけて何名から返信が来たかが、あなたの手持ち販路の反応率です。この数字を `log/reach.md` に記録してください。**推定していた獲得能力が、ここで初めて実測に置き換わります。**

**関門（週2終了時、4つとも）**
- 別々の人が5人以上、同じ困りごとを言っている。うち3人以上が「自作した / 金を払っている / 時間を使っている」を明言している
- **接触可能な候補者が45名 一覧化できている**（下記）
- **手持ち販路の反応率を実測した**（声をかけた数と返信数）。**実測値が 段階0 の想定を大きく下回る場合、必要な集客数を計算し直す**。下回ったまま先へ進まないこと
- **反証 記録に、この時点で仮説に不利な事実が最低1件書かれている**（0件は「探していない」手がかり です）

> **なぜ45名か。** 候補15名から聞き取り12件を得るには**歩留まり80%**が要り、承諾率0.7・実施率0.9 を置いても必要な返信率は **127%** で、数学的に不可能です。現実的な歩留まりでの必要接触数は次のとおりです。

> | 経路 | 歩留まり | 12件に必要な接触 |
> |---|---|---|
> | 経路1 現職・前職（強い縁） | 37.8% | **32名** |
> | 経路1 現職・前職（並） | 20.4% | **59名** |
> | 経路2 紹介 | 44.1% | 28名 |

> **時間は足りています。** 週割りの連絡・日程調整は合計8.3時間で、1接触0.25時間なら33名、10分なら50名に届きます。**欠陥は工数ではなく数字です。**

### 段階2: 混み具合調べ（週2 / 3.5時間）

**この 工程 の目的は候補の発見ではなく、候補の棄却です。** 段階0〜1 で出た入口にのみ適用します。ここで新しい 狭い領域 を探し始めると、B の「候補生成の篩」を棄却 関門 に流用する目的反転が起きます。

**判定式は実測して決め直しました**（`config/thresholds.yaml`、測定記録は `doc/research/G_thresholds.md`）。業務系 検索語22語について4生態系の API を実際に叩き、分布の 百分位 から閾値を引いています。

**通過条件は「4条件のうち 2つ以上」です。**

> **第1版の「3つ以上」は成立しませんでした。** 各条件を p25/p75 線で切ると1条件あたりの成立率は構造的に約25%になり、条件どうしはほぼ独立なので、**3条件の同時成立は22語で0語**になります。加えて第1版の4条件は**厳しさが5倍以上ばらついていました**——「rating 80未満」は実測 p12（極端に厳しい）、「hit 数が数百件以下」は実測 p50（ほとんど選別していない）、「6か月以上更新停止」は p93、「対応 比が中央値の2倍」は p56。個数で数える 規則 が、この不揃いな厳しさの上に載っていました。

**WordPress 生態系の閾値（2026-08-11 実測）**

| 条件 | 閾値 | 由来 |
|---|---|---|
| C1 検索 hit 数が薄い | `info.results` ≤ **268** | 語別分布の p25（n=22） |
| C2 上位に「導入数は多いが評価が低い」がいる | 上位8件に installs ≥ **52,500** かつ rating ≤ **88** が1件以上 | 件単位の p75 / p25（n=176 / 152） |
| C3 上位が放置されている | 上位8件の最終更新からの経過月数の中央値 ≥ **1.19か月** | 語別分布の p75（n=22） |
| C4 未解決の不満が溜まっている | `support_threads / active_installs × 1000` の中央値 ≥ **0.116** | 語別分布の p75（n=22） |

**実測での通過率は 22語中8語（36.4%）**でした。

> **この関門には選別力がありません。** 検証で、4条件を語ごとに無作為へ振り直した場合の通過率を計算したところ、**期待値 39.9%（8.78語）**で、実測の 36.4%（8語）は無作為分布の27パーセンタイルに入ります。**「4条件を組んだこと」が通過率を動かしていません**（`doc/verify/X3_gates.md` §2）。
>
> 理由は明快で、**4条件すべてが「同じ22語の中での順位」だからです。** p25 と p75 は必ず存在するので、22語すべてが儲からない領域でも必ず約25%が該当します。**通過語が出ることは、通過語が儲かることの証拠を1 bit も含みません。** `G_thresholds.md` §8 が「合格率が10〜36%から大きく外れたら閾値ではなく 検索語の組を疑え」と書いているのは、この関門が**標本の形にしか反応しない**ことの裏返しです。

**したがって、この関門は単独では使えません。絶対条件を必ず併せてください。**

| 併せる絶対条件 | 中身 | 出所 |
|---|---|---|
| **決済の仕組みがあるか** | その生態系で金を受け取れるか。**無いなら測る意味がありません** | §7.2 |
| **新規参入が届いているか** | 上位8件に直近3年の参入があり、その増え方が必要な月あたり導入増以上か（§6.5.1）。**大手の導入数と比べても関門になりません**——実測で86〜100%が通過しました | §6.5.1 |

**決済の仕組みを確認してから測ってください。** 閾値を実測した4生態系のうち、**Chrome Web Store / VS Code / WordPress.org には 配布元の中の課金機構がありません**（§7.2）。

ただし「収益化できない」と同義ではありません。**WordPress.org は外部 SaaS 連携が可能で、有料版を別 追加機能 として外部配布する構造なら成立します**（§7.2）。Chrome も自前の決済で回せます。**成立しないのは「配布元の中だけで完結する」形です。**

| 生態系 | 4条件そろうか | 配布元の中決済 | 実際にどうなるか |
|---|---|---|---|
| WordPress | ○ 4/4 | **なし** | 混み具合は最も正確に測れるが、**license 検証 server の運用が別途発生**（§7.5 の「継続収入の前提を崩す」に該当） |
| Atlassian | 3/4（不満が測れない） | **あり** | 決済まで完結する唯一の測定可能な生態系。導入者は決裁の通った企業 |
| VS Code | 3/4（業務系では2/4） | なし | 開発系 検索語のみ |
| Chrome | 2/4（hit 数が原理的に測れない） | なし | 測定にも決済にも向かない |

**「最も正確に測れる生態系」と「決済まで完結する生態系」が一致していません。** 段階0 で決済の仕組みを決めるとき（§7.3）、この不一致を織り込んでください。第2版はこの2つを別々の節に書いており、突き合わせていませんでした。

**生態系別の可否**

| 生態系 | 使える条件 | 通過率 | 注意 |
|---|---|---|---|
| WordPress | 4 / 4 | 8/22語 | 唯一4条件そろう |
| Atlassian | 3 / 4 | 5/22語 | C4（不満）が測れない。`lastModified` は更新日として使えない |
| VS Code | 3 / 4 | 4/20語 | **開発系 検索語のみ。** 業務系の検索語 では評価が集まらず C2 が使えない |
| Chrome Web Store | 2 / 4 | 1/10語 | **公開 API が存在せず、C1（hit 数）が原理的に測れない** |
| Shopify | 未測定 | — | 内訳非公開 |

**評価不能な生態系を選んだ場合は、この段階を「上位製品の評価件数の分布」で代替し、判定の重心を段階3（聞き取り12件）へ移してください。**

> **閾値の信頼性**: 語単位の 百分位 は n=20〜22 しかなく、再標本法による90%信頼区間は点推定の1/3〜1.6倍まで動きます。**絶対視せず、狙う生態系が決まったら自分の 検索語の組で再測定してください**（手順は `G_thresholds.md` §8）。
>
> **C2 の読み方**: 「評価が低い＝不満がある」と読まないでください。評価の低さを不満の proxy にするのは 評価の甘さ により誤りです（§5.3）。C2 は「**上位に評価の低い大手がいる**」という事実の記述に留めます。

絞り込みの流れ の各段階で独立した 情報源 に切り替えるのは、雑音 を通しにくくするためです。ただし **情報源どうしには相関があるため（人気な 狭い領域 はどの 情報源 でも人気）、偽陽性率が単純に積になるわけではありません。** 正しい枠組みは多重比較ではなく **勝者の呪い（選ばれたものは実力より良く見える）（選択後の推定 偏り）** で、実務上の意味は「絞り込みの流れ を通った候補の見込みは、通過時点の推定より必ず低い」ということです。また AND 条件の 絞り込みの流れ は**真の候補も落とします**（5段で感度 0.33）。これは欠陥ではなく §1 第4条の意図した trade-off です。

### 段階3: 聞き取り12件（週4〜7 / 24.0時間）

**「買いますか」と尋ねない。** 聞くのは**直近の実作業の時系列**、**既存代替案と投下 費用**、**きっかけ** です。

> **質問文そのものは `OUTREACH.md` §3 にあります**（11問と、聞いてはいけない4問）。本節は時間配分と判定の設計です。

```
0〜3分    前置き・録音許可
3〜13分   直近の実作業を時系列で
13〜20分  既存代替案と投下 費用（既に何に金と時間を払っているか）
20〜26分  きっかけ（なぜその日に動いたか）
26〜29分  乗り換えを止めているもの（不安・惰性）
29〜30分  紹介依頼・画面を見せてもらう依頼
```

**価格の仮説はここで作ります**（第1版はどこにも書いていませんでした）。自分の支払意思を聞くと よく見せたい心理による偏り が乗るため、**inferred valuation**（他者の価値を推測させる）を使います。

```
・あなたと同じ職種の方が、この 道具 に月いくらまで払うと思いますか。
・あなたの会社で、この種の 道具の稟議が通る金額の上限はいくらぐらいですか。
```

**これは推測値であって実測ではないので、価格決定の根拠ではなく仮説生成にのみ使います。** 決定は 段階4〜5 の実価格で行います。金額を直接聞く場合は「仮の話では高めに答えてしまう傾向が知られているので、実際に今月の予算から出すとしたら、という前提でお答えください」を前置きしてください。

**きっかけ の分類 名前 は 段階3 開始前に確定させ、以後追加しないこと。** 走りながら 名前 を作ると「同じ きっかけ」の判定が自由になり、関門 が意味を失います。

**関門（6件時点・中間）**: 6件のうち「**金または時間を実際に投じている**」が2件以下なら中止。これは 見込みなしでの中止なので α を消費しません。

**関門（12件時点）**: **7件以上**が同一 きっかけ なら 段階4 へ。

> 閾値の根拠を差し替えました。第1版は Guest et al. (2006) の「metatheme は6件で出現」を8/12の根拠にしていましたが、**あれは theme の出現（話題の出尽くし）であって出現率（出現率）の話ではなく、転用は成立しません**（2/6 の信頼区間は 4〜78%）。7/12 は二項分布から置いた値です。なおこの停止規則は、真の集中度50%の候補を**81%落とします**。取りこぼしを承知の上で採用する 関門 です。

> **12件も 同じ集団から集めた標本です。** 段階5 と同じ問題が、こちらにもあります。12名は §3.2 の同じ名簿から集まるため、相関を入れると**偽陽性が 15.8% → 32.7%（相関0.3）へ倍増し、検出力はほとんど変わりません**（`doc/verify/X3_gates.md` §3.6）。つまり**関門が緩む側にだけ効きます。**
>
> **同じ経路から12名を集めた場合、「同じ きっかけ」は需要の 手がかり ではなく経路の 手がかり です。** 同じ職場・同じ業界の12人が同じきっかけを語るのは当たり前で、それは市場の性質ではありません。
>
> **対処: 12件を最低3経路に分散させ、経路の内訳を必ず記録してください**（§3.2 の経路1だけで12件を埋めない）。関門を判定するとき、**同一きっかけ7件が2経路以内に偏っていたら、通過とみなさない**こと。これを段階0 で宣言しておいてください。

**きっかけ がばらばらなら中止。** 「特定 客層 に集中しているので 客層 を絞って追加」は、**走行中の 関門 緩和そのものなので禁止します**（第1版はこれを許していました）。客層 を絞り直すなら 段階0 からやり直しです。

### 段階4: 有償提供 3名（週8〜15 / 26.0時間）

**継続収入型の事業 の成否を決めるのは初回決済ではなく継続決済です。** ここが本手順書の実質的な判定点になります。

| 作業 | 時間 |
|---|---|
| 1名に人手で提供（週1.5時間 × 3週）— 要件を採るための最小回数 | 4.5時間 |
| その作業を最小実装に落とす（3名へ配布できる範囲まで） | 12.0時間 |
| 3名の対応（週0.5時間 × 3名 × 5週） | 7.5時間 |
| 請求・継続確認 | 2.0時間 |

> **ここに工数をかけすぎないこと。** この関門の棄却率は**14%**です（全計算に使う月次解約4.9%を当てると、3名全員が2か月目も払う確率は `0.951³ = 86%`）。**棄却1件あたり378.6時間**で、最も安い関門（混み具合調べ 5.6時間）の68倍になります。
>
> **人手にこだわる根拠は、費用の不等号（作るより手でやるほうが安い）です。** 最小実装が `Hi` 時間、この関門の棄却確率が `p` のとき、人手で代行してよい上限は `p × Hi` 時間です。棄却確率14%なら、最小実装12時間に対して**人手に使ってよいのは1.7時間**という計算になります。**上表が12.0時間を実装に振っているのはこのためです。**
>
> **判定条件**: `人手の総時間 < 棄却確率 × 最小実装時間` を満たす間だけ人手を続けます。実装が12時間で終わらないと判明した時点で、人手へ戻すのが正しい判断です。**この再判定は、実装に着手して実測が出た週にできます。**

**変えていないもの**: **8週間という期間**と、**関門「3名全員が2か月目も支払った」**。短縮できないのは工数ではなく課金周期です。実装が速くても、2回目の入金は1日も早くなりません。

**必ず対価を取ってください。** 金額は想定する製品価格と同水準。無料にすると証拠強度が紹介ページ以下に落ちます。**最初の3週が人手であることは明示**してください。

**上限を先に決める: 顧客3名まで、8週間まで。**

> **作り始めると聞かなくなる、という危険がここで発生します。** 実装を12時間認めた以上、防御を別に立てる必要があります。**週次の記録に「顧客と話した時間」と「コードを触った時間」を別々に書き、後者が前者を上回る週が2週続いたら警告としてください。**

**関門（週15末）**

| 条件 | 判定 |
|---|---|
| 3名全員が**2か月目も支払った** | 製品化へ進む |
| 1〜2名が継続 | 継続者側に絞って 有償提供 を4週延長（**段階0 でこの分岐を許可すると宣言していた場合のみ**） |
| 0名が継続 | **中止。** 価値提案が成立していません |

### 段階5: 先行販売（週14〜16 / 10.5時間）

紹介ページを1枚作り、有償提供 の顧客と 聞き取り 12名へ 先行販売 を提示します。

> **その1枚に何を載せ、何を載せないかは `OUTREACH.md` §4 にあります。** 取るのは決済への同意で、無料登録ではありません。**断りの文言をそのまま記録してください**（「高い」「今は忙しい」「上を通せない」は別の意味です）。

**判定は 規則 of three**: 接触30名から0件なら、成約率の95%上側限界は **9.5%（片側）**。**ただしこれは30名が互いに独立な場合の値で、本手順書の設計では成り立ちません。**

30名は同一経路（§3.2 の名簿）・同一時期（3週間）・同一の提示文・同一価格を共有します。これは 同じ集団から集めた標本で、同じ職場・同じ業界の相手は成約するかどうかが相関します。相関を入れると上限は緩みます。

| 経路の分け方 | 相関 0.1 | 相関 0.2 | 相関 0.3 |
|---|---|---|---|
| 10経路 × 3名 | 10.5% | 11.5% | 12.7% |
| 3経路 × 10名 | 13.6% | **17.5%** | 21.6% |
| 単一経路 30名 | 20.7% | **30.7%** | 40.9% |

**相関がどれくらいかは実測していません（未確認）。** ただし相関ゼロとは「同じ職場の同僚10名の反応が、無関係な10名の反応と同じだけばらつく」という主張で、擁護できません。**0.1〜0.3 を作業仮説に置いてください。**

**したがって関門はこう読み替えます。**

- **元の 9.5% を回復したいなら、経路を分けて接触数を増やす**: 1経路10名なら、相関0.1で5経路50名、相関0.2で6経路60名が必要です
- **30名のまま判定するなら、上限は約20〜30%として扱う**。「10%未満」とは言えません

> **さらに深い制約があります。** 30名全員に同じ価格・同じ文面で提示した場合、失敗の原因が「需要が無い」ではなく「文面が悪い」「価格が1桁ずれている」なら、**30件は独立な30試行ではなく、1つの提示設計に対する1回の試行**です。**規則 of three が言えるのは「この提示・この価格・この経路での成約率の上限」までで、「この価値提案の上限」ではありません。** 第2版の「30名接触で1件も出ない事業は副業の時間では立ち上がらない」は、**「この提示では立ち上がらない」**に訂正します（`doc/verify/X3_gates.md` §3）。
>
> **したがって、0件だった場合に必ず切り分けてください。** 提示文と価格を1回だけ変えて、別経路の10名に出し直す。それでも0件なら価値提案の問題です。この切り分けを段階0 の時点で許可すると宣言しておくこと（走り始めてから足すと関門の緩和になります）。

**判定には必ず分母（提示した相手の人数）を書いてください。** 分母の無い「3件売れた」は判定に使えません。

**Google Search Console は 関門 ではなく補助観測に降格します。** §2.3 の通り既定値は流入ゼロなので、**表示回数 0 は需要の不在ではなく 検索に載っているかどうかを測っているだけ**です（第1版の致命的な誤りでした）。表示回数 が立てば「その語で検索されている」という追加証拠になりますが、立たなくても仮説の反証にはなりません。需要の実測は上記の 先行販売 で行います。

なお **A/B テスト は個人規模では回りません。** 成約率 2%→3% の検出には power 0.8 / α 0.05 で**各群3,825・合計7,650 click** が必要で、月500 visit なら15.3か月かかります。比較実験ではなく「金が動いたか / 動かなかったか」の2値と 規則 of three で判定する設計です。

**反証 記録を判定基準に入れている理由**: 段階1 の「別々の5人が同じ困りごとを言っているか」は、探せば大抵見つかるため都合のいい事実だけ集める偏り に無防備です。**仮説に不利な事実を書く欄を独立の 関門 にしないと、この 調査の流れ は「肯定を集める装置」になります。**

## 5. 使う 情報源（実測検証済み・2026-08-11）

すべて実際に 取得 して 応答 を確認済みです（`doc/verify/V3_endpoints.md` に実行 command と返り値）。

### 5.1 順序

### 5.2 個別（落とし穴つき）

| # | 情報源 | 取れるもの | 費用 | **必ず知っておくこと** |
|---|---|---|---|---|

### 5.3 使い方の制約

- **検索数 には「真値」が存在しません。** 道具 間の乖離は誤差ではなく**定義の違い**で、複数 道具の平均を取っても真値に近づきません。**桁でしか判断せず、2倍差は差と見なさない。**
- **Ahrefs の「median 乖離 49.52%」は 訪問者数の推定の誤差であり、検索数 の誤差ではありません**（1,635 site、2022-05-03、US GSC vs US organic 推定）。第1版は別指標に転用していました。
- **Google Trends の相関 0.496 は popular 語（"GDP Growth"）の再取得間の値**で、低頻度 検索語の数値ではありません（Brazil: 0.496 / 0.545 / 0.564、US: 0.655 / 0.516 / 0.575）。低頻度 検索語 が不安定なのは別途知られていますが、**この数字はその根拠になりません。**
- **訪問者数の推定 道具 は個人規模では使えません**（SparkToro 検証、641 site / 7,692 site-月。最良 Semrush 0.790 / 最悪 Ahrefs 0.504。ただし Ahrefs 値は organic のみを測る指標のため SparkToro 自身が unfair と認めています）。
- **★の低さを不満の proxy にしない。** 評価の甘さ により、非公開で「二度と雇わない」と答えた発注者の **28.4%** が公開では4★以上を付けていました（Filippas, Horton & Golden, NBER WP 25857 / *Marketing Science* 2022）。
- **公的統計（e-Stat / BLS / Census / Eurostat）は入口単位には粒度が粗すぎます。** 用途は「分母」と「顧客数の上限」の確認に限定。

## 6. 競合・価格・単位経済

### 6.1 競合は「推定しない」。撤退した競合を探す

個人が狙う規模では 訪問者数の推定は使えません（§5.3）。**離散 event の日付だけを取ります**（推定ではなく観測なので誤差がありません）。

| 取るもの | 取り方（具体） | 何が分かるか |
|---|---|---|
| **価格改定日** | Wayback CDX API に競合の pricing ページの URL を投げ、snapshot 一覧を取得 → **内容が変化した日付だけ**を抽出 | **複数社に値上げ実績があるか。** 無ければ commodity 化を疑う |
| **release 日** | GitHub の releases、または製品サイトの 変更履歴 / 更新履歴 page | 開発の投入量。間隔が開き続けていれば実質停止 |
| **review 投稿日** | 配布先の店の評価一覧、G2 / Capterra の投稿日 | 増加速度から顧客増を相対比較（**件数の絶対値は顧客数ではない**） |
| **求人掲載日** | 競合の採用 page、および求人媒体で社名検索 | **どの職種を募集したか**が投資先を示す。営業を採れば販売に、特定分野の技術者を採ればその機能に投資している |

**そして必ず、撤退・終了した競合を探してください。** 生存している競合だけを測るのは、§1 第5条が禁じた生存者のみの sample です。探し方は4つです。

1. **Wayback で pricing ページが消えた**、または直近12か月の snapshot が無い
2. **GitHub repository が archive 済み**（read-only 表示）
3. 製品サイトが **404 / 別ドメインへ転送 / 買収先の案内ページに置換**
4. 配布先の店で、**最終更新が2年以上前**かつ評価が残っている

見つけたら、終了告知・最後の記事・作者の投稿を読んでください。**「なぜ畳んだか」は成功者の因果説明より信頼できます。**

### 6.2 競合の数の読み方

「競合ゼロ」は「まだ発見できていない」と区別がつきません。競合が見つからない場合は、(a) 検索語が業界語彙とずれている、(b) 内製・spreadsheet で代替されている、(c) 本当に需要が無い、のどれかを判定してから進みます。

「先に入ること」自体に優位の実証はありません（Golder & Tellis 1993: pioneer 失敗率 47%、長期 share leader は50分野 中4、long-term leader は pioneer の平均13年後に参入）。**ただしこの「13年」は戦前 分類 19年に引きずられた平均で、戦後 ジャンルは5年です。digital 製品に当てるなら5年の側を見てください。**

なお first mover advantage を巡る文献には moderator（産業の成熟度、技術変化の速さ、参入時の資源）を報告するものもあり、**「後発が常に有利」という主張はできません**。言えるのは「先行が有利という前提に実証的な根拠が乏しい」までです。

## 6.5 販路 — どうやって届けるか（**最初に決める**）

この節は他のどの節より先に読んでください。**集客の手段が無い企画は、需要があっても成立しません。** 日本政策金融公庫『2024年度新規開業実態調査』では、「顧客・販路の開拓」は開業時48.1%・現在47.7%と、**開業後もほとんど下がりません**（開業時の首位は「資金繰り、資金調達」59.2%で、現在は37.0%へ下がります）。なお同調査は「従業員の確保」「従業員教育、人材育成」が開業時より**上昇**したとも記しており、**販路が唯一の障害ではありません**。

### 6.5.1 必要な集客数 — ここで多くの企画が死ぬ

§6.4 の逆算を、契約数で止めずに**人数**まで通します。

```
必要な月次純増契約数 ÷ 成約率 = 月に届けなければならない人数
```

> **訂正（この節は一度誤っていました）。** 初出時、必要な月次獲得数を「維持に必要な数」＝ 契約数 × 解約率 と書きました。**これは誤りです。** その率ちょうどで獲得しても、契約数は目標に漸近するだけで**到達しません**（目標の99%に達するまで92か月、99.9%なら138か月）。正しくは、**目標に何か月で到達したいか**から逆算します。

契約数の増え方は `db/dt = M − c·b`（M＝月次獲得数、c＝月次解約率）に従い、T か月で目標 B に到達するための獲得数は次式です。

```
M = c·B ÷ (1 − e^(−c·T))
```

**時定数 1/c は単価によらず一定（解約5%なら20か月）**なので、単価で変わるのは「毎月何人に届けるか」の絶対量だけです。

#### 先に集客の手段を宣言する

**必要な人数を時間に換算する式は、集客の手段ごとに違います。同じ式では計算できません。**

| 型 | 中身 | 時間と到達の関係 |
|---|---|---|
| **個別の声かけ** | 知人・元同僚への連絡、紹介、問い合わせへの返信 | 自分が動いた分だけ客に届き、**動くのをやめれば止まる**。月に会える人数は 使える時間 ÷ 1人あたりの時間 が上限で、何か月続けても上がらない |
| **掲載・記事** | 配布先（WordPress の追加機能一覧など）への掲載、記事、他社製品の連携先一覧への掲載 | 一度作れば**置いたまま毎月客が来る**。順位が下がれば減るが、手を止めてもすぐには止まらない |

この違いのため、**「必要な人数 × 1人あたりの時間」という式は掲載に使えません。** 掲載は客1人ごとに自分の時間を使わないからです。この式で判定すると、**掲載で集客する企画が「時間が足りない＝不可」と誤って落ちます。** 成約率を実測値に置き換えても直りません。

#### 表A: 個別の声かけだけの場合

声をかけ続けても解約が追いついてくるので、契約数はある数で止まります。

```
維持上限 = (可処分時間 ÷ 1人あたりの時間) × 成約率 ÷ 解約率
        = (30.33 ÷ 0.25) × 0.005 ÷ 0.05 = 12.1件
```

**この 12.1件が上限です。いくらの値段をつけても、目標をいくらにしても、この数字は変わりません。**

| 単価 | 目標契約数 | 維持上限12.1件との比 | 支援工数（0.25h/件/月） | 判定 |
|---|---|---|---|---|
| 月4,500円 | 158.7件 | 13.1倍 | **39.7時間/月（可処分の131%）** | **不可（二重に）** |
| 月15,000円 | 47.6件 | 3.9倍 | 11.9時間/月 | **不可** |
| 月50,000円 | 14.3件 | 1.2倍 | 3.6時間/月 | **不可**（§6.4 の価格帯別解約率を使うと可に反転） |
| 月150,000円 | 4.8件 | 収まる | 1.2時間/月 | **可** |

（見知らぬ相手への成約率0.5%・1接触0.25時間・可処分30.3時間/月・解約 月5%・18か月到達。**すべて仮の設定値で、段階1 と 段階5 の実測で置き換える対象です**）

> **この4行は単価の判定ではありません。** すべて「目標契約数が 12.1件を超えるか」の言い換えで、倍率も `目標契約数 ÷ 12.1` です。**言えるのは「1対1接触だけを集客の手段とする個人は契約数を約12件までしか維持できない。だから12件で目標に届く単価が要る」までです**（`doc/verify/X2_reachmath.md` §3）。

**この表が崩れる条件**: 成約率と1人あたりの手間を、値段によらず一定と置いています。**実際には高い値段ほど相手の決裁が重くなり、成約率は下がって手間は増えます。** その悪化がある水準を超えると**この表は全行「不可」に反転**し、さらに悪化すると中くらいの値段が最悪になります。**結論は、測っていない数字にきわどく依存しています。**

**目標50万円を個別の声かけだけで達成するには、1件あたり約59,000円/月が要ります**（`714,286 ÷ 12.1`。実名の知り合い60名の寄与と18か月の途中経過を含めると約64,000円）。

| 掲載・記事 p75・転換1% | 月90.8導入 | 18.2件 | 月4時間 |
| 掲載・記事 中央値・転換3% | 月36.2導入 | 21.7件 | 月4時間 |

**ふつうの掲載1本（7.2契約）は、時間を全部つぎ込んだ個別の声かけ（12.1契約）より少ない。** 「掲載にすれば安い値段でも成り立つ」は、ふつうの掲載では成り立ちません。

**掲載が優れているのは、かかる時間です。**

| 販路 | 月1時間あたりの定常契約数 | 個別の声かけ比 |
|---|---|---|
| 個別の声かけ | 0.40件 | 1.0倍 |
| 掲載・記事 中央値・転換1% | **1.81件** | **4.5倍** |
| 掲載・記事 p75・転換1% | 4.54件 | 11.3倍 |
| 掲載・記事 中央値・転換3% | 5.43件 | 13.6倍 |

> **結論**: 掲載の利点は「たくさん集まる」ではなく「**少ない時間で済み、手を止めても客が来続ける**」ことです。**契約数そのものを増やしたいなら、上位25%（月90件以上増える掲載）に入る必要があります。ふつうの掲載1本では、狙える粗利は月5万〜9万円までです。**
>
> **掲載を7本作っても検索で7倍の順位は取れない**ので、単純に倍にはなりません。現実的なのは「**掲載1〜2本 ＋ 残りの時間を個別の声かけ**」です。

> **未確認**: 無料→有料の転換率1%・3%は仮置きです。**この値が結論を最も強く動かします。** また上表は全部「上位8件に入れた掲載」の値なので、**参入したが上位に入れなかった掲載を分母に含みません**（検索結果が上位しか返らないため測定不能）。「上位に入れればこれくらい」であって「参入すればこれくらい」ではありません。

#### 段階0 で問うこと

**「必要時間が30.3時間に収まるか」ではありません。次の3つです。**

1. **時間を止めても到達が残る販路があるか**（掲載・記事を持つか、それとも1人あたりの時間に縛られるか）
2. **掲載・記事なら、新規参入が実際に届いているか**（下記。§1 第6条が言っているのはこれです）
3. **契約数そのものが食う時間を引いたか**（支援 0.25時間/件/月。契約60件で可処分の半分が消えます）

#### 掲載・記事の関門は「新規参入が届いているか」で見る

> **大手の導入数を関門にしてはいけません。** 「上位8件の導入数 ≥ 必要導入数」は**実測で22語中19〜22語（86〜100%）が通過**します。上位8件は必ず大手なので当然です。大手の導入数は領域の天井を示すだけで、**あなたが届く水準ではありません。** 見るべきは**新規参入の実績**です。

**2条件で判定します（実測: `doc/research/H_stock_params.md`）。**

| 条件 | 中身 | 実測での通過 |
|---|---|---|
| **A** | 上位8件に**直近3年に登録された掲載**が1件以上ある | **13/22語（59%）** |
| **B** | その掲載の月あたりの導入増 ≥ 必要な月あたり導入増 | Aを満たす語のうち、目標と単価による |

**AとBの両方を満たす語の割合（実測22語・転換率1%）**

| 目標粗利/月 | 単価4,500円 | 単価15,000円 | 単価50,000円 | 単価150,000円 |
|---|---|---|---|---|
| 50,000円 | 23% | 36% | 45% | 55% |
| 200,000円 | 23% | 23% | 27% | 45% |
| 500,000円 | **5%** | 23% | 23% | 36% |

**5〜55%が通過し、目標と単価で動きます。関門として機能しています。** これは段階2 の4条件（無作為と区別がつかない）とは対照的です。

**条件Aで落ちる9語**（上位8件に直近3年の参入が1件も無い）:

```
accounting / asset management / compliance audit / contract management / crm /
digital signature / invoice / purchase order / timesheet
```

**この9語は、導入数の大きさとは無関係に、新規参入が上位に食い込めていない領域です。** 段階0 で落とせます。

### 6.5.1.1 目標を先に選ぶ

上表は目標粗利を月50万円に固定していますが、**これは副業月収の中央値5万円の10倍**です（§2.3）。**単価の議論の前に、目標を選んでください。**

**以下は個別の声かけだけ（表A）の場合の表です。掲載・記事を持つなら、この「不可」は当てはまりません。**

| 目標（粗利/月） | 副業月収分布での位置 | 契約数（単価15,000円） | 必要到達/月 | 個別の声かけだけで可能か |
|---|---|---|---|---|
| 50,000円 | 中央値 | 4.8件 | 20人 | **可** |
| 92,445円 | 平均 | 8.8件 | 37人 | **可（20.4時間/月）** |
| 200,000円 | 中央値の4倍 | 19.0件 | 80人 | 単価50,000円なら可（7.4時間） |
| 500,000円 | **中央値の10倍** | 47.6件 | 201人 | **単価59,000円以上でなければ不可** |

（成約率2%・解約 月5%・18か月到達。最終行の最低単価は表A の維持上限12.1件から `714,286 ÷ 12.1`）

**したがって必要人数を減らす手は3つあります。「単価を上げるか、目標を下げるか、販路を掲載・記事に変えるか」です。**

**3つ目が最も大きく効きます。** 同じ時間を投じたとき、掲載・記事は個別の声かけの 8.6〜57倍の到達を生みます（`doc/verify/X2_reachmath.md` §2.3。集客量 は仮の設定値で、倍率の絶対値ではなく桁の違いが要点です）。単価と目標は数倍の幅しかありません。

**動かせる幅を掛けると、効き方の順位はこうなります。**

| 変数 | 弾力性 | 現実に動かせる幅 | 必要人数が動く倍率 |
|---|---|---|---|
| **成約率**（経路の選択で決まる） | 1.000 | 750倍 | **750倍** |
| 単価 | 1.000 | 33倍 | 33倍 |
| 目標粗利 | 1.000 | 20倍 | 20倍 |
| 利益率 | 1.000 | 3倍 | 3倍 |
| 目標までの月数 | 0.617 | 3倍 | 2.0倍 |
| 解約率 | 0.383 | 6倍 | 2.0倍 |

> **弾力性の順位そのものは、意思決定に使わないでください。** 第2版は「成約率＝利益率＝単価＝1.000 > 目標までの月数 0.617 > 解約率 0.383」という順位を結論として置いていましたが、これは分析ではありません。**上位4個が 1.000 になるのは、式が単なる積と商だからで、微分する前から確定しています。** 残る2個も恒等式 `解約率の弾力性 − 目標までの月数の弾力性 = 1` で結ばれた同じ量です。自由度は実質1個で、その値は「解約率 × 目標までの月数」だけで決まります。
>
> したがって**「解約率が最も効かない」は、18か月という自分で選んだ設定の帰結であって、解約率という量の性質ではありません。** 目標までの月数を60か月に置けば解約率の弾力性は 0.843 になり、最も強い変数の一つに変わります。
>
> さらに、これらは他を固定した偏微分です。**手順書自身が §6.4 で引く価格帯別の解約率（月$50未満 GRR 23% / 月$250超 GRR 70%）を入れると、単価の全微分は −1.155 になります。** 成約率が単価とともに下がる分まで入れると、**符号すら手元の 数値では決まりません**（弾力性1.5で正に反転＝単価を上げると必要人数が増える）。**「−1.000（厳密）」は代数の性質であって、世界の性質ではありません。**

なお成約率が高い経路（紹介・知人）は**母数が有限**なので、規模を出す局面では動かせません。**動かせる成約率とは「掲載・記事の販路に切り替える」ことを指します。**

**したがって単価設計は「いくらなら売れるか」ではなく「自分が月に何人に届けられるか」の問題です。** 成約率2%は仮置きで、実測は 段階5 で取ります。**成約率が半分になれば必要人数は倍**なので、この表は下振れ側で読んでください。

### 6.5.2 「獲得能力」の測り方（第1版では未定義でした）

関門に「自分の獲得能力の範囲内か」と書きながら、測り方を書いていませんでした。以下で測ります。

**推定してはいけません。実際に届けて数えます。**

| 段階 | 何を測るか | 得られる数 |
|---|---|---|
| 段階0 | **§3.2 の経路1**（現職・前職の関係者）を実名で書き出して数える。名前が書けない相手は数えない | **手持ちで届く人数** |
| 段階1 | 15人に声をかけ、**何人から返信があったか**を数える | **手持ちからの反応率** |
| 段階3 | 聞き取りの末尾で毎回紹介を依頼し、**何件つながったか**を数える | **紹介による増分** |
| 段階5 | 何人に提示して何件成約したか | **実成約率**（推定でなく実測） |

**段階1 は「相手探し」であると同時に「販路の最初の実測」です。** ただし15人で3人なら点推定20%でも、**95%信頼区間は7%〜45%**（上下で6.4倍）で、これだけでは何も判定できません。反応率を±10ポイントの精度で測るには**93名**（真の率が20%前後と分かっていれば60名）が必要です。

**判定に効くのは反応率ではなく、段階0 で数えた実名の人数です。** 必要到達が月200人なら、実名の知り合いが150人でも1か月分に届きません。反応率は「どの経路に時間を使うか」を決めるための数字であって、販路が足りるかを決める数字ではありません。**15名しか使えないなら経路を1つに絞って測ってください**——2経路に分けると各7〜8名になり、どちらの数字も意味を持ちません。

**手持ちだけで足りない場合、外部から人を連れてくる手段が要ります。** それが次項です。

### 6.5.3 販路の候補と、事前に測れるか

**販路の「空き」を入る前に測る信頼できる方法を、本調査では発見できませんでした**（`doc/research/D_competition_pricing.md` §6.3、確信度 **中**、「不在の確認に基づく判断」）。**「存在しない」と証明されたわけではありません。** 発見できた唯一の例外が、導入数が公開されている配布先です。

**販路は「事前に測れるか」の1軸では分類できません。3類型に分けます。** 第2版は2類型（測れる / 測れない）で書いており、**「事前には測れないが、数時間で実測できる」販路が枠組みから漏れていました。** 日本語圏の販路はほぼ全部この第3類型に入るため、漏らすと日本語圏の選択肢が消えます。

| 類型 | 意味 | 判定への使い方 |
|---|---|---|
| **① 事前に測れる** | 競合の導入数が公開されている | 参入前に §6.5.1 表B で可否を判定できる |
| **② 安く実測できる** | 出品・掲載に数時間、費用ほぼゼロ。閲覧数・受注数が実測で返る | **段階0〜1 のうちに出して数える。** 推定しない |
| **③ 測れない** | 参加して観察するしかない | 判定の重心を段階4〜5（金）へ移す |

**販路の候補**

| 販路 | 型（流量/在庫） | 類型 | 測り方 | 週7時間での適性 |
|---|---|---|---|---|
| **配布先の店の中の検索**（WordPress / Atlassian / VS Code 等） | 掲載・記事 | **①** | 競合の導入数が公開されている。上位が独占的か、中位に隙間があるか | **最高** |
| **他社製品との連携経由** | 掲載・記事 | ① | 連携先一覧の掲載数と分類の空き | 高 |
| **BOOTH / ココナラ / note（有料）/ DLsite** | 掲載・記事 | **②** | **出品して、閲覧数・お気に入り数・受注数を数える。** 日本語圏で決済まで完結する数少ない経路 | 中〜高（**未検証**。下記） |
| **検索流入**（自分の記事） | 掲載・記事 | ②〜③ | 検索件数＋上位10件の実体分類（個人サイトが3件以上入っているか） | 中（**既定値は流入ゼロ**。時間がかかる） |
| **自分が当事者である集まり** | 個別の声かけ | ③ | 参加して観察するしかない | 高（当事者である場合のみ） |
| **紹介・口コミ** | 個別の声かけ | ③（段階3 で実測） | 聞き取り末尾の紹介依頼の成功率 | 高 |
| **有料広告** | 個別の声かけ | ③（推定精度15〜30%） | — | **低**。必要契約数が少ないと広告費を回収できない |

> **日本語圏の行は未検証です。** BOOTH・ココナラ・note・DLsite の手数料・審査条件・入金条件は本調査で一次確認していません（`doc/research/A〜F` に日本語圏の販路は note / Qiita / Zenn しか出ず、その3件は §3.2.1 で候補者発見の経路からは外しています）。**候補として名前を挙げたもので、料率と条件は着手前に各自で一次確認してください。**
>
> **なぜ追加したか**: 第2版の販路表は WordPress / Atlassian / VS Code だけで、§7.2 の 配布元の表も8件すべて英語圏でした。この状態で §1 第6条（数字が見える集客先を持つ市場を選ぶ）に従うと、**§1 第2条（自分が内側から知っている領域を起点にする）が破れます**——何も知らない市場へ行け、という結論になるためです。2つの原則の衝突を、第2版は扱っていませんでした。

**結論: 集客先の空きを測ってから参入するのではなく、「数字が見える集客先、または安く実測できる集客先を持つ市場を選ぶ」のが、個人に取れる唯一の合理的な策です。**

実務的には次の3つのどれかです。

1. **配布先の店に出す** — 店の中の検索が既に人を運んでいるので、自分で集客しなくてよい。競合の導入数で混み具合が事前に見える。ただし店の条件変更に丸ごと依存する（§7.5）
2. **出品して数える** — 日本語圏なら、事前に測るより出して実測するほうが安く済みます。**数時間で階層2（配布元の実測値）の証拠が取れる**ので、机上の段階2 より強い判定材料になります
3. **自分が既に当事者である集まりに出す** — 販路が「自分の既存の関係」なので、確保済み。ただし人数の上限が早く来る

**どれでもない企画は、集客を一から作ることになります。** それが週7時間で可能かを、段階0 で正直に見積もってください。

### 6.5.4 検索流入を当てにする場合の前提

**約140億ページのうち96.55%が、Googleからの流入ゼロ**です（Ahrefs, 2023-12-01。index全体の一部・検索語 6.51億という限定あり）。

これは「検索流入は無駄」ではなく「**既定値は流入ゼロであり、そうならない理由を説明できなければ計画に入れてはいけない**」という意味です。説明とは、上位10件に個人のページが実際に入っていること、その語の検索意図が自分の解決策と一致していること、の2点を実体で確認することです。**難易度の指標だけを見て判断しないでください**（被リンク数だけの代理指標で、意図も品質も見ていません）。

### 7.4 税務・規程の確認論点（税務助言ではありません。税理士に確認する項目の 一覧 です）

1. 消費税の内外判定（「電気通信利用役務の提供」は**役務提供を受けた者の住所等**で判定。国税庁 タックスアンサー No.6118）。顧客所在地の記録・証跡が前提
2. 事業者向け / 消費者向けの区分と reverse charge
3. 適格請求書発行事業者の登録要否（**顧客が国内法人中心か海外個人中心かで判断が変わります**）

5. 海外 配布元 からの支払いにおける源泉徴収と租税条約の届出（W-8BEN）
6. 給与所得者の副業所得の申告要否と、住民税の徴収方法（会社への通知経路）
7. 勤務先の副業規程・職務発明規程・競業避止・OSS への貢献に関する規程

### 7.5 配布元に潰される危険 の判定基準

告知から実施までの実績は **0日（Chrome Web Store の新規有料拡張作成は 廃止予定 announce と同時に不可）／5日（Twitter API 2023）／約30〜60日（Reddit API 2023）／6か月前告知の明文（Atlassian）** と幅があり、平均を語る意味がありません。**「最悪、告知と同時に条件が変わる」を前提に置いてください。**

価格改定は率ではなく桁で来ます（Reddit は Apollo に 50M 取得s あたり $12,000 を提示し、実績を当てはめると月$1.7M 相当）。判定基準は **「現在の原価に対する感応度」ではなく「原価が100倍になった場合に事業が成立するか」**。

### 第2版で私が持ち込んだ誤りの型（2026-08-12 追加）

第2版の欠陥には、第1版とは別の型が3つありました。**どれも「原則は正しいのに、実装が原則を裏切っている」形をしています。**
