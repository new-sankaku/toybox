# 声のかけ方 — 誰に、どこで、何と書いて送るか

`MARKET_RESEARCH.md` は「**何件で合格か**」を決める文書です。
本書は「**何を書いて、どこに送るか**」を決めます。この2つが揃わないと段階1が動きません。

根拠は `research/I_first_customers.md`。**文面そのものは私が書いたもので、出典はありません。**
出典があるのは、その下敷きにした原則のほうです（過去の行動を聞く／将来の意思を聞かない＝`MARKET_RESEARCH.md` §1）。
**段階1で経路別に返信数を数え、効かない文面は捨ててください。**

---

## 0. 先に確認すること（送る前）

| 確認先 | 何を | 落ちたらどうなるか |
|---|---|---|
| 勤務先の副業規程 | 副業の可否、届出の要否 | 全部止まる |
| 秘密保持契約・競業避止 | **現職の顧客・取引先に声をかけてよいか** | 経路1がほぼ消える |
| Lancers・CrowdWorks の規約 | **依頼者への直接の持ちかけ、外部サービスの案内が許されるか** | 経路4が消える（`research/I_first_customers.md` §2.3） |
| 配布元のcommunity規約 | 署名欄での自分の道具の案内 | 掲示板経由が消える |

**未確認のまま送らないでください。** ここは調査ではなく確認で、合計1時間かかりません。

## 1. どこに相手が居るか

**返信が来やすい順です。この順位は私が付けたもので、実測ではありません。**

| 経路 | 実在の場所 | 相手の状態 |
|---|---|---|
| **1 現職・前職の関係者** | 自分の連絡先。元同僚、他部署、取引先の担当者 | **実名で数えられる唯一の経路。** ここが手持ちの大半 |
| **2 聞き取りの末尾の紹介** | 話を聞いた相手の頭の中 | 相手が既に話を聞いてくれた後なので断られにくい |
| **3 求人・外注の募集主** | Lancers、CrowdWorks、ココナラ（依頼側）、Indeed の業務委託枠 | **その作業に、この金額を、いま払うと言っている**。金が既に動いている |
| **4 「作ってみた」記事の書き手** | Qiita、Zenn、note、個人ブログ | 既存の製品で満たされなかった当事者そのもの |
| **5 展示会の来場者** | 日本展示会協会の開催一覧。**94.4%が平日のみ＝有給が要る** | 出展者ではなく**来場者**に話しかける |

**Qiita・Zenn・teratail・知恵袋は「拾う場所」で「声をかける場所」ではありません。**
ここで拾うのは相手の**言い回し**です。返信欄で営業しないでください。

## 2. 何と書いて送るか

### 共通の型

**4文まで。添付なし。依頼は1つだけ。**

1. 共通の過去で名乗る（部署名・案件名を具体的に）
2. **具体的な作業を1つ名指しする**（「業務効率化」ではなく「月末の請求書の突合」）
3. **売る物が無いと書く**
4. 30分をくださいと頼み、日程を2案こちらから出す

### 2.1 経路1 — 元同僚・他部署・取引先

```
件名: ◯◯の件で30分いただけませんか

◯◯さん、ご無沙汰しています。△△（部署名・案件名）でご一緒した□□です。

いま、◯◯（相手が今もやっているはずの具体的な作業）まわりのやり方を調べていて、
実際にやっている方に30分ほど話を聞かせてもらっています。

売り込みではありません。まだ何も作っていないので、売る物がありません。

来週の火曜か木曜の夕方で、30分いただけませんか。
```

### 2.2 経路2 — 聞き取りの末尾で紹介を頼む

**12件すべての末尾で、必ずこの一文を言います。**

```
同じことで困っていそうな方、心当たりありますか。
お名前だけ伺えれば、私から連絡します。
```

**「紹介してください」と言わないこと。** 相手に連絡の手間が発生した瞬間に断られます。
「心当たり」を聞き、動くのは自分です。

### 2.3 経路3 — 求人・外注の募集主（Storemapper型）

**募集が出ている案件に、外注の提案としてではなく道具の提案として出します。**

```
◯◯の募集を拝見しました。

同じことを、外注ではなく道具で片付ける方法があります。
（何をどうするかを1行。機能一覧は書かない）

まだ作っている途中なので、お金はいただきません。
合わなければ、そのまま募集を続けてください。

画面をお見せしながら15分だけ話せますか。
```

**規約で外部への案内が禁じられている場合、この文面は送れません**（§0）。
その場合は**受注してから**同じ相手に道具の話をする形になり、Storemapper と同じ道になります
（受託9か月で名簿を作ってから1通出した）。

### 2.4 経路4 — 「作ってみた」記事の書き手

```
◯◯の記事を読みました。△△のところ（記事の中の具体的な箇所）が、
自分が詰まっているところとまったく同じでした。

いま同じ問題を抱えている方に話を聞いて回っています。
記事のあと、実際どうされましたか。

30分いただけませんか。
```

**記事の具体的な箇所に触れていない連絡は、一斉送信として扱われます。** 必ず読んでから書きます。

### 2.5 送ってはいけない文面

| 型 | なぜ駄目か |
|---|---|
| 宛名が役職名・会社名 | 一斉送信と判別され、開かれません |
| 初回に資料を添付する | 読む負担が「30分」より重くなります |
| 「ご紹介させてください」で始まる | 売り込みだと最初の1行で分かります |
| 依頼が重い（1時間の打合せ、20問のアンケート） | 承諾率が落ちます |
| 自分の企画を先に説明する | **説明した瞬間、相手は当事者から評価者に変わります。** 以後の話は全部お世辞になります |

## 3. 聞き取りで何を聞くか（段階3・12人・1人30分）

**原則は1つ。過去に実際にやったことだけを聞き、これからどうするかは聞きません。**

### 3.1 聞く順（この順に降りる）

1. **直近でその作業をやったのはいつですか。その日の手順を、最初から最後まで教えてください。**
2. そのとき何分かかりましたか。**（時計で測った値ですか、感覚ですか）**
3. 月に何回ありますか。
4. **いま、それに何か買っていますか。いくらですか。**（道具・外注・人手のすべて）
5. それを買う前は、何を使っていましたか。
6. **買うと決めた日、何がありましたか。** ← きっかけ。段階3の関門はここで判定します
7. 稟議は要りましたか。誰の承認ですか。
8. うまくいかなかったとき、誰がどう困りますか。
9. **自分で何か作りましたか。**（表計算・マクロ・手順書）→ **あれば、その場で見せてもらう**
10. 同じ職種の方なら、これにいくらまで払うと思いますか。 ← **他人の推測として聞く**
11. （末尾）同じことで困っていそうな方、心当たりありますか。

**9番が最も強い信号です。** 自分で作った物がある＝既に時間を払っている証拠で、
その物の中身が、そのまま要件になります。

**10番を「あなたはいくら払いますか」と聞き替えないでください。** 自分の支払額を聞くと見栄が混ざります。

### 3.2 聞いてはいけない質問

| 質問 | 何が起きるか |
|---|---|
| 「こういう物があったら買いますか」 | 全員が「いいですね」と答えます。判定に使えません |
| 「あなたはいくらなら買いますか」 | 見栄で高く言うか、遠慮で低く言うかのどちらかです |
| 「◯◯って不便じゃないですか」 | 誘導です。相手は同意します |
| 自分の企画の説明 | 相手が評価者に変わります（§2.5） |

### 3.3 その場で記録すること

**言葉そのままを書き取ります。要約しないでください。** 要約すると限定が落ちます。
特に**金額・回数・時間・日付**は、聞いた数値をそのまま。

## 4. 先行販売で何を出すか（段階5）

### 4.1 出すもの — 画面1つ分

| 項目 | 中身 |
|---|---|
| 誰の | 相手の職種と場面を名指し |
| どの作業が | 聞き取りで出た**相手の言い回しのまま** |
| どうなるか | 前と後を1行ずつ |
| いくら | **月額を1つだけ。** 3段階の料金表は出さない |
| いつから | 具体的な日付 |
| やめ方 | 解約の条件を書く |

**出すもの**: 実際の画面（作業中でも可）、値段、開始日、解約条件。
**出さないもの**: 機能一覧、技術構成、今後の予定。

### 4.2 取る行動

**決済への同意です。無料登録ではありません。**
無料登録の件数は判定に使えません（`MARKET_RESEARCH.md` §5 — 判定は2回目の入金）。

### 4.3 数えるもの

**断られた数を数えないと、成約率が出せません。**

| 数える | なぜ |
|---|---|
| 提示した人数 | 分母。これが無いと「3件売れた」は判定に使えません |
| 断られた数 | 上と対 |
| **断りの文言そのまま** | 「高い」「今は忙しい」「上を通せない」で意味が違います |
| 決済した数 | 分子 |

## 5. 記録の付け方 — これが最初の実測

**段階1の目的は相手探しであると同時に、集客力の初回実測です。**
`MARKET_RESEARCH.md` §6.5 の想定値（成約率0.5%など）を、ここで実測に置き換えます。

`log/outreach.md` に経路別で置きます。

| 経路 | 送った | 返信 | 承諾 | 実施 | 返信率 |
|---|---|---|---|---|---|
| 1 現職・前職 | | | | | |
| 2 紹介 | | | | | |
| 3 求人・外注 | | | | | |
| 4 記事の書き手 | | | | | |
| 5 展示会 | | | | | |

**経路をまとめて1つの率にしないでください。** 経路ごとに桁が違います
（`MARKET_RESEARCH.md` §6.5.5 — 強い縁で20〜38%、記事の書き手で6%）。
まとめると、効いている経路が平均に埋もれます。

**同じ経路に同じ文面で送った30通は、30回の試行ではありません。**
文面が1つなら、試行も1回です（`MARKET_RESEARCH.md` §8）。
**返信がゼロなら、まず文面を疑ってください。需要ではなく。**
