| 層 | 判定 |
|---|---|

## 2. 【最重要】時間制約の関数形が誤っている

### 2.1 model が実際に主張していること

§4 の判定基準表は関門をこう定義します。

> | 0 | **必要時間/月**（必要到達 × 1接触の所要） | **≤ 30.3時間** |

§6.5.1 の表もこの式で時間列を作っています。整理すると model は

```
必要時間 = M × (τ / s)          τ = 1接触の所要時間、s = 成約率
```

と述べており、**`τ/s`（契約1件を取るのに要する自分の時間）を販路によらない定数として扱っています。**

### 2.2 なぜこれが誤りか

販路には根本的に異なる2種類があります。

- **流量型（1対1接触）**: 時間を払うと到達が生まれ、払うのを止めると到達は消える。到達の上限は `H/τ`（Hは可処分時間）で、**何か月続けても増えません**。
- **在庫型（配布先の店の掲載・記事・連携先の掲載枠）**: 時間を払うと**資産**が生まれ、資産が毎月到達を生む。資産は減衰 δ で目減りするが、払うのを止めても直ちには消えない。到達は**累積投下時間の関数**であり、時間そのものの関数ではありません。

在庫型を状態変数で書くと（A＝資産量、κ＝資産1単位あたり所要時間、a＝資産1単位あたり月間到達、δ＝減衰率）

```
dA/dt = h/κ − δ·A      到達 R = a·A
```

流量型には δ が存在しません。**この1個の parameter の有無が、両者を別の関数形にしています。** `τ/s` をどんな値に置き換えても、在庫型は流量型の式で表現できません。成約率の実測（段階5）で s を差し替えても直りません。

### 2.3 定量（同じ30.3時間/月を投じた場合の18か月後の契約数）

成約率 s を共通にして、時間の使い方だけを変えました。

| 使い方 | s=0.5% | s=1.0% | s=2.0% |
|---|---|---|---|
| 流量型（1対1接触 121件/月が上限） | **7.2件** | 14.4件 | 28.8件 |
| 在庫型（5時間で記事1本、月20到達、減衰3%/月） | **61.9件** | 123.7件 | 247.5件 |
| 在庫型（配布先の店に1件掲載、月1,000到達、減衰2%/月） | **410.5件** | 820.9件 | 1,641.8件 |

（在庫型の到達 parameter は仮の設定値です。絶対値ではなく**同一時間で8.6倍〜57倍の差が出る**という構造が要点です。§4 で実測値に置き換えます。）

目標契約数は 4,500円→158.7件、15,000円→47.6件、50,000円→14.3件。**流量型では 7.2件で全行が届かず、在庫型では 4,500円の行（158.7件）にも届きます。単価は一切変えていません。**

### 2.4 手順書自身との矛盾

これは外部からの異論ではなく、**手順書内部の矛盾**です。

- §1 第6条: 「供給側の空きを事前に測る信頼できる手段は存在せず、**唯一の例外が install 数が公開される marketplace**」
- §6.5.3: 配布先の店の中の検索 = 「事前に測れるか **○ 唯一測れる**」「週7時間での適性 **最高**」「**店の中の検索が既に人を運んでいるので、自分で集客しなくてよい**」
- §6.5.3 結論: 「**測れる販路を持つ市場を選ぶ**のが、個人に取れる唯一の合理的な策です」

**「自分で集客しなくてよい」とは、まさに τ ≈ 0 という意味です。** ところが §4 の関門は `必要時間 = 必要到達 × 1接触の所要` で、この販路を通す枠が存在しません。段階0 でこの欄を埋めようとする読者は、手順書が最良と推奨した販路を数式に入力できず、必ず流量型の数字を書くことになります。

**結果として、手順書が最良と推奨する販路を選んだ企画ほど、段階0 の関門で不合格になります。** §3 段階0 の関門1は「それでも届かない企画は、ここで捨てます」と書いており、この誤判定は段階1 に進む前に企画を殺します。

### 2.5 歪みの向き

**悲観側（企画を過剰に殺す方向）。** しかも系統的です。在庫型の販路を持つ企画ほど強く殺されます。

## 3. 【最重要】4行の表は、単価の判定ではない

### 3.1 model の定常状態

流量型のみの場合、契約数の定常値は解析的に出ます。

```
b_∞ = (H/τ) · s / c
```

手順書の設定値（H=30.33時間/月、τ=0.25時間、s=0.5%、c=0.05）を入れると

```
b_∞ = 121.3 × 0.005 / 0.05 = 12.13 件
```

**手順書の model の下では、契約数はどんなに時間をかけても永久に12.13件を超えません。** 単価にも、目標にも、到達期間 T にも依存しません。

### 3.2 4つの判定は、この1つの数との比較に過ぎない

| 単価 | 必要契約数 B | b_∞=12.13 との比較 | 本文の判定 |
|---|---|---|---|
| 4,500円 | 158.7 | > 12.13 | 不可 ✓ |
| 15,000円 | 47.6 | > 12.13 | 不可 ✓ |
| 50,000円 | 14.3 | > 12.13 | 不可 ✓ |
| 150,000円 | 4.8 | ≤ 12.13 | 可 ✓ |

**4行すべてが再現されます。** 「21倍」「6倍」「1.4倍」という倍率も `B / 12.13` の言い換えです。最低単価も `714,286 ÷ 12.13 = 58,870円`（本文の 64,024円は18か月の過渡と実名 pool 60名の寄与を含めた版で、同じ量です）。

### 3.3 したがって、本文の結論の正しい表現は

> 単価 月4,500円は不可（21倍）、15,000円は不可（6倍）、50,000円は不可（1.4倍）、150,000円のみ可

ではなく、

> **見知らぬ相手への1対1接触だけを販路とする個人は、契約数を約12件までしか維持できない。したがってその販路しか持たないなら、12件で目標に届く単価（約6万円以上）が必要である。**

です。**この言い方に直すと、結論が「単価について」ではなく「販路の型について」であることが見えます。** そして12という数の由来は `H/τ × s/c` であって、価格帯とは無関係です。

現在の書き方は、**単価という読者が動かせる変数に、販路という別の変数の帰結を帰属させています。** 読者は「月4,500円の製品は個人には無理」と読みますが、model が実際に言えるのは「cold outreach だけで月4,500円の製品を売るのは無理」です。後者は正しく、前者は model の射程外です。

## 5. 弾力性分析の再計算と、その意味

### 5.1 再計算（数値は一致）

```
R = (G / (m·P)) · c / (s · (1 − e^{−cT}))
```

対数弾力性（解析値と数値微分が一致）:

| 変数 | 弾力性 | 本文 |
|---|---|---|
| 目標 G | +1.000000 | — |
| 利益率 m | −1.000000 | 1.000 ✓ |
| 単価 P | −1.000000 | 1.000 ✓ |
| 成約率 s | −1.000000 | 1.000 ✓ |
| 到達期間 T | −0.616606 | 0.617 ✓ |
| 解約率 c | +0.383394 | 0.383 ✓ |

**数値は全て一致します。**

### 5.2 しかし、この6個の数は独立ではありません

依頼文の指摘は正しく、しかも指摘より強く言えます。

- G・m・P・s は式の中で**単なる積と商**として現れます。したがって弾力性が ±1 になるのは**微分する前から確定**しています。世界について何も述べていません。
- 残る c と T は独立ではありません。`x ≡ cT·e^{−cT}/(1−e^{−cT})` と置くと

```
ε_T = −x        ε_c = 1 − x        よって  ε_c − ε_T = 1（常に、恒等的に）
```

cT=0.9 のとき x=0.6166 で、本文の 0.617 と 0.383 になります。**弾力性表6個の自由度は実質1個（x）で、その x は cT だけで決まります。**

| cT | ε_T | ε_c |
|---|---|---|
| 0.3 | −0.857 | +0.143 |
| 0.9（本文） | −0.617 | +0.383 |
| 2.0 | −0.313 | +0.687 |
| 5.0 | −0.034 | +0.966 |

**「解約率は最も効かない」は、cT=0.9 という設定の帰結であって、解約率という量の性質ではありません。** T=60か月なら cT=3.0 で ε_c=0.843 となり、解約率は最強の lever の1つになります。本文は「唯一 data に裏付けのある前提（解約率）が最も効かない」を皮肉として提示していますが、これは18か月という自分で選んだ期間設定を、解約率の性質と誤って読んだものです。

### 5.3 弾力性は lever の順位付けに使えません

弾力性が順位付けに使えるのは、**全ての変数が同じ倍率だけ動かせるとき**だけです。実際に動かせる幅を掛けると順位が変わります。

| 変数 | 弾力性 | 現実的に動かせる幅 | R が動く倍率 |
|---|---|---|---|
| 成約率 s（経路選択 0.02%〜15%） | 1.000 | 750倍 | **750倍** |
| 目標 G（5万〜100万円） | 1.000 | 20倍 | 20倍 |
| 単価 P（4,500〜150,000円） | 1.000 | 33倍 | 33倍 |
| 利益率 m（30%〜90%） | 1.000 | 3倍 | 3倍 |
| 到達期間 T（12〜36か月） | 0.617 | 3倍 | 2.0倍 |
| 解約率 c（2%〜12%） | 0.383 | 6倍 | 2.0倍 |

**同じ「1.000」の中で影響力が250倍違います。** W3 の D-3 はこれを正しく指摘していますが、本文 §6.5.1.1 は「成約率＝利益率＝単価＝1.000 > 到達期間 0.617 > 解約率 0.383」という順位だけを残しました。W3 の限定が統合で落ちた形です（§10 の「限定の脱落」型の再発）。

### 5.4 さらに、偏微分であること自体が誤り

弾力性表は「他を固定して1変数を動かす」偏微分です。**手順書が引く data 自身が、これらの変数が相関することを示しています。**

§6.4 が引く ChartMogul 2025 の価格帯別 retention（月$50未満 GRR 23% / 月$250超 GRR 70%）から

```
c($30帯)  = −ln(0.23)/12 = 12.25%/月
c($1000帯) = −ln(0.70)/12 =  2.97%/月
d ln c / d ln P = −0.404
```

したがって解約率経路だけを入れた**全微分**は

```
d lnR/d lnP = −1 + ε_c · (d ln c/d ln P) = −1 + 0.383 × (−0.404) = −1.155
```

成約率が単価とともに下がる分（`d ln s/d ln P = −ε_s`）を加えると

| ε_s | 全微分 d lnR/d lnP | 意味 |
|---|---|---|
| 0.0 | −1.155 | 単価を上げると必要人数は減る |
| 0.6 | −0.555 | 減るが弱い |
| 1.0 | −0.155 | ほぼ効かない |
| 1.5 | **+0.345** | **単価を上げると必要人数は増える** |

**本文の「−1.000（厳密）」は代数の性質であって、世界の性質ではありません。** 全微分の値どころか**符号すら、手順書が持つ data では決まりません。**

### 5.5 判定

**弾力性分析は「分析」として成立していません。** 4個は式の形の言い換え、2個は恒等式で結ばれた1個、そして全て偏微分で相関が無視されています。**この節から得られる正しい情報は「R は G・s・m・P の積商である」という、式を見れば分かることだけです。**

## 6. 「単価を上げれば必要人数が減る」は正しいか

### 6.1 定式化

成約率と1接触の労力を単価に結合させます。

```
s(P) = s₀·(P/P₀)^(−ε)        τ(P) = τ₀·(P/P₀)^(+γ)
必要時間 = (M/s)·τ  ∝  P^(ε+γ−1)
```

- `ε+γ < 1` → 必要時間は単価とともに**減る**（本文の前提。本文は ε=γ=0 を置いている）
- `ε+γ = 1` → 必要時間は単価に**依存しない**
- `ε+γ > 1` → 必要時間は単価とともに**増える**

`ε+γ = 1` は「獲得費用が契約単価に比例する」（CAC/ACV 一定）という形であり、SaaS で広く言われる経験則です。**この経験則の原典は本 session では確認できていません（未確認）。** ただし、この経験則を仮定しなくても以下の計算は成立します。

### 6.2 数値（必要時間/月。可処分30.3時間）

| ε+γ | 4,500円 | 15,000円 | 50,000円 | 150,000円 | 形 |
|---|---|---|---|---|---|
| 0.0（本文の前提） | 652.0 | 183.9 | 43.5 | **3.4 可** | 単調減少 |
| 0.4 | 402.8 | 183.9 | 70.4 | **8.5 可** | 単調減少 |
| 0.6 | 316.6 | 183.9 | 89.6 | **13.5 可** | 単調減少 |
| 0.95 | — | — | 136.6 | **30.3 境界** | ほぼ平坦 |
| 1.0 | 195.6 | 183.9 | 145.1 | 33.9 **不可** | 平坦 |
| 1.2 | 153.7 | 183.9 | **184.5** | 53.8 **不可** | **非単調（中単価が最悪）** |
| 1.6 | 95.0 | 183.9 | 298.7 | 135.1 **不可** | **単価が高いほど悪い** |

### 6.3 判定

**手順書はこの結合を扱っていません。** §6.3（価格の決め方）は成約率を価格の関数として扱う枠組みを持たず、§6.5.1 の表は4行すべてで s=0.5%・τ=0.25時間を固定しています。

**そして結論「150,000円のみ可」は、`ε+γ < 0.95` のときにのみ成立し、`ε+γ ≥ 1.0` で全行不可に反転します。** 反転点が、経験則として最も語られる値（1.0）のすぐ手前にあります。すなわち**結論は、手順書が測っても述べてもいない量の値に、境界のすぐ近くで依存しています。**

`ε+γ > 1.2` では必要時間は**非単調**になり、中単価（50,000円）が最悪になります。「単価を上げれば必要人数が減る」という単調性は、model の含意ではなく、model に入れた仮定そのものです。

### 6.4 本文の仮定が何を意味しているか

本文の設定値（cold 成約率0.5%、1接触0.25時間）を LTV に換算します（粗利率70%・平均生存20か月）。

| 単価 | 契約1件に要する営業時間 | 粗利 LTV | 営業1時間あたりの粗利 |
|---|---|---|---|
| 4,500円 | 50時間 | 63,000円 | 1,260円 |
| 15,000円 | 50時間 | 210,000円 | 4,200円 |
| 50,000円 | 50時間 | 700,000円 | 14,000円 |
| 150,000円 | 50時間 | 2,100,000円 | **42,000円** |

**本文は「同じ50時間の営業で、6.3万円の顧客も210万円の顧客も同じ確率で取れる」と仮定しています。** 33倍値段の違う商材が、相手にとっての決裁の重さも、必要な説明量も、稟議の有無も全く同じという仮定です。§7 の型別表が「法人なら請求書・稟議・年払い」と自分で書いている事実と整合しません。

**この仮定こそが「150,000円のみ可」を生んでいます。** 現実の向きは逆（高単価ほど ε も γ も大きい）である可能性が高く、その場合 §6.5.1 の順位は**部分的に逆転します**。

### 6.5 歪みの向き

**高単価側に楽観、低単価側に悲観。** すなわち「単価を上げよ」という処方を系統的に過大評価します。

### 7.1 口コミの複利（#6）の定量

```
db/dt = R·s + k·b − c·b     →     M = (c−k)·B / (1 − e^{−(c−k)T})
```

単価15,000円（B=47.6）:

| k（1顧客が月あたり連れてくる新規） | 実効 c−k | M | 必要時間 |
|---|---|---|---|
| 0.000（本文） | +0.050 | 4.012 | 200.6h |
| 0.010 | +0.040 | 3.711 | 185.6h |
| 0.020 | +0.030 | 3.424 | 171.2h |
| 0.050 | 0.000 | 2.646 | 132.3h |
| 0.060 | −0.010 | 2.415 | 120.7h（**自走**） |

k=0.02 は「1顧客が50か月に1人紹介する」水準です。効果は数十%で、§2 の販路の型（8.6〜57倍）ほど大きくありません。**したがって口コミの脱落は本 model の主要な誤りではありませんが、`k=0` を明示せずに置いている点は記録すべきです。** 特に k > c で自走に転じる相転移が model の外にあることは、判定の性質を変えます（「毎月いくら投入するか」から「1度でも臨界に届くか」へ）。

### 7.2 定数 M（#7）の定量

目標 B=47.62 に18か月で到達するとき:

- 定数 M の場合: 総獲得 = 4.012 × 18 = **72.22件**
- 終盤に集中させた場合: 総獲得 = **47.62件**

**平坦な計画は、後ろ寄せの計画より1.52倍多くの総獲得を要します**（早く取った契約が18か月の間に解約するため）。個人の予算は「毎月の時間」であると同時に「T か月の総時間」でもあり、**「毎月の獲得率 ≤ 上限」という判定は、「総獲得 ≤ 総時間」という判定とは別物**です。手順書は前者だけを関門にしています。

### 7.3 逆向きの指摘（本文の結論を支持する側）

公平のために記録します。**低単価行を殺す正しい理由は、実は別にあります。**

| 単価 | 契約数 | 支援 0.25時間/件/月 | 予算30.3時間に占める割合 |
|---|---|---|---|
| 4,500円 | 158.7 | **39.7時間/月** | **131%（獲得0時間でも破綻）** |
| 15,000円 | 47.6 | 11.9時間/月 | 39.2% |
| 50,000円 | 14.3 | 3.6時間/月 | 11.8% |
| 150,000円 | 4.8 | 1.2時間/月 | 3.9% |

**契約数そのものが時間を食う**（支援・請求・問い合わせ）ので、低単価＝多契約は独立の理由で個人には重い。これは §7 の型別表が「単価 × 想定顧客数が support 工数を賄うか」と正しく指摘している論点ですが、**§6.5 の model には入っていません。**

同様に、手順書自身の価格帯別 GRR を使うと:

| 単価 | c | 流量型の契約数上限 b_∞ | 必要 B | 判定 |
|---|---|---|---|---|

## 8. 代替 model

### 8.1 定式化

**状態**

```
b(t)   契約数
A_j(t) 在庫型販路 j の資産量（記事本数・掲載の順位資産・連携先掲載数）
```

**販路を2種に分ける**

流量型 i（1対1接触。実名の知人・紹介・問い合わせ返信）:

```
R_i(t) = h_i(t) / τ_i             τ_i = 1接触の所要時間
制約:  ∫₀ᵀ R_i(t) dt ≤ N_i        N_i = 実名で数えられる母数（非再生）
```

在庫型 j（配布先の店の掲載・記事・連携先掲載枠）:

```
dA_j/dt = h_j(t)/κ_j − δ_j·A_j     κ_j = 資産1単位あたり所要時間、δ_j = 月次減衰率
R_j(t)  = a_j · A_j(t)             a_j = 資産1単位あたり月間到達
```

**契約の動学**（生存関数版。一定 hazard に限定しない）

```
b(T) = ∫₀ᵀ [ Σ_i R_i(u)·s_i(P) + k·b(u) ] · S(T−u) du
S(u) = 獲得から u か月後の残存率。  一定 hazard なら S(u)=e^{−c(P)u}
```

**時間予算**（手順書の model に無い項が3つ入ります）

```
Σ_i h_i(t) + Σ_j h_j(t) + σ·b(t) + h_dev(t) + h_admin  ≤  H      ∀t
                          ^^^^^^^^ 支援（契約数に比例）  ^^^^^^^^ 開発
```

**目標**

```
b(T) ≥ B(P) = G / ( m(P) · P )
```

**判定（実行可能性問題）**

> 上記の予算制約を満たす時間配分 `{h_i(t), h_j(t)}` が存在して `b(T) ≥ B(P)` となるか。

### 8.2 この model が出す、手順書と違う関門

流量型のみのとき、契約数の上限は

```
b_∞^flow = (H/τ) · s / c            ← δ を含まない
```

在庫型を含むとき、

```
b_∞^stock = (a·h/κ) · s / (δ · c)   ← δ が分母に入る
```

**両者の差は 1/δ 倍です。** δ→0（資産が減衰しない販路）で上限は発散します。

例（κ=5時間/資産、a=20到達/月/資産、s=1%、全30.3時間を資産に投下）:

| δ（月次減衰） | 半減期 | b_∞ | 成立する最低単価 |
|---|---|---|---|
| 20%/月 | 3.5か月 | 121件 | 5,887円 |
| 10%/月 | 6.9か月 | 243件 | 2,943円 |
| 5%/月 | 13.9か月 | 485件 | 1,472円 |
| 3%/月 | 23.1か月 | 809件 | 883円 |
| 1%/月 | 69.3か月 | 2,427件 | 294円 |
| （流量型） | — | **12件** | **58,870円** |

**したがって段階0 で問うべきことは「必要時間 = 必要到達 × 1接触の所要 ≤ 30.3時間か」ではなく、次の2つです。**

1. **時間を止めても到達が残る販路があるか**（δ が有限か、それとも τ に縛られるか）
2. **その販路の月間到達 a·A を、参入前に測れるか**

**2は §1 第6条・§6.5.3 が既に述べていることです。** すなわち代替 model の関門は、手順書の第6条と一致し、手順書の §4 判定基準表とは一致しません。**直すべきは §4 の関門の式であって、第6条ではありません。**

### 8.3 段階0 の関門の差し替え案

現行:

```
必要時間/月（必要到達 × 1接触の所要） ≤ 30.3時間
```

差し替え:

```
[1] 販路の型を宣言する
      流量型のみ  →  b_∞ = (H/τ)·s/c を計算し、目標契約数 B ≤ b_∞ か
                     （手順書の設定値では b_∞ ≈ 12件。単価は 714,286/b_∞ 円以上が必要）
      在庫型あり  →  [2] へ

[2] 在庫型の到達を、参入前に実測する
      配布先の店:  §5.2 の API で、狙う keyword の上位8件の active_installs を取る
                   （手順書は §3 段階2 でこれを既に実行している）
      必要な累計到達 = (目標契約数 × 到達期間中の総獲得) ÷ 成約率
      判定: 上位8件の下位帯の install 数 ≥ 必要累計到達 か

[3] 契約数そのものの時間費用を引く
      支援 σ × 目標契約数 ≤ H の半分か
      （σ=0.25時間/件/月 なら、契約数 60件で予算の半分を食う）
```

### 8.4 差し替え後の数値表（案）

**表A: 流量型のみ（1対1接触だけを販路とする場合）**

| 単価 | 目標契約数 | 流量型の上限 12.1件 | 支援工数 | 判定 |
|---|---|---|---|---|
| 4,500円 | 158.7 | 超過13倍 | 39.7h/月（予算の131%） | **不可（二重に）** |
| 15,000円 | 47.6 | 超過3.9倍 | 11.9h/月 | **不可** |
| 50,000円 | 14.3 | 超過1.2倍 | 3.6h/月 | **不可（ただし手順書自身の価格帯別解約率を使うと可）** |
| 150,000円 | 4.8 | 収まる | 1.2h/月 | **可（ただし成約率・労力が単価に依存しないという仮定つき）** |

**表B: 在庫型を1つ持つ場合（配布先の店に1件掲載。構築40時間・維持4時間/月＝月あたり6.2時間）**

必要な active installs（無料→有料 1% の場合）:

| 単価 | 目標契約数 | 必要 installs | 実測との比較（2026-08-12、keyword「invoice」） |
|---|---|---|---|
| 4,500円 | 158.7 | 15,873 | 3位 `woocommerce-delivery-notes` (30,000) で到達 |

**表Bの4行はいずれも「不可」ではありません。** そして表Bを埋めるのに必要な数字は、手順書が §5.2 で紹介し §3 段階2 で既に取得している API から無料で取れます。

**表A・表Bを並べることで初めて、この節の本当の結論が出ます。**

> **成立可否を決めているのは単価ではなく、販路が在庫型かどうかです。**
> **流量型しか持たないなら、単価6万円以上でなければ成立しません。**
> **在庫型を1つ持てるなら、月4,500円でも成立し得ます。ただしその在庫型の到達量は、参入前に実測してください（それが §1 第6条の意味です）。**

### 8.5 §6.5.1.1 の目標水準の表について

W3 の B-5・G-4 の指摘を受けて §6.5.1.1 が追加されており、「単価を上げるか、目標を下げるか」の二択に直っています。**この修正は正しく、本検証で覆すものはありません。** ただし正しくは**三択**です。

> **単価を上げるか、目標を下げるか、販路を在庫型に変えるか。**

3つ目が最も影響が大きく（8.6〜57倍）、手順書自身が §1 第6条・§6.5.3 で最良と評価している道です。

## 10. 手順書への修正提案（優先度順）

### 最優先

1. **§4 判定基準表の「必要時間/月（必要到達 × 1接触の所要）」を撤回する。** この式は §1 第6条・§6.5.3 が最良とする販路を表現できず、その販路を選んだ企画を段階0 で不合格にします。§8.3 の3段階の関門に差し替えてください。

2. **§6.5.1 の表の見出しを「単価別」から「販路の型別」に変える。** 現行の4行は `B ≤ (H/τ)·s/c = 12.1件` という単一の判定を4通りに書いたものであり、単価について述べたものではありません（§3）。§8.4 の表A・表Bの2枚に分けてください。

3. **§6.5.1 の表の注に、成約率と1接触の所要が単価に依存しないという仮定を明記する。** そして「この仮定が崩れて `ε+γ ≥ 1` になると、結論は全行不可へ反転し、`ε+γ > 1.2` では中単価が最悪になる」ことを併記してください（§6）。現行の注（「すべて仮の設定値で、段階1 と 段階5 の実測で置き換える対象です」）は、置き換えれば直るという含みを持ちますが、**s と τ を実測値に置き換えても関数形の誤りは直りません。**

### 高

4. **§6.5.1.1 の「単価を上げるか、目標を下げるか」を「単価を上げるか、目標を下げるか、販路を在庫型に変えるか」へ。** 3つ目が最大の lever です（§8.5）。

5. **弾力性の順位（成約率＝利益率＝単価＝1.000 > 到達期間 0.617 > 解約率 0.383）を削除するか、限定を付けて残す。** 4個は式が積であることの帰結、残り2個は `ε_c − ε_T = 1` で結ばれた1個です。残すなら「動かせる幅を掛けた列」（§5.3）を必ず併記してください。**「解約率が最も効かない」は18か月という設定の帰結であり、T=60か月では最強の1つになります**（§5.2）。

6. **§6.5 の解約率を、§6.4 の価格帯別 GRR と整合させる。** 現行は §6.4 で「月$50未満 GRR 23% / 月$250超 GRR 70%」を引きながら、§6.5 では全行に c=5% を当てています。整合させると 50,000円の行の判定が反転します（§7.3）。

7. **支援工数を model に入れる。** 契約数 × σ が予算を食います。4,500円の行は獲得0時間でも予算の131%です（§7.3）。**これは本文の結論を支持する、より正しい根拠です。**

### 中

8. §6.5.1 の表の「目標契約数」列（158/47/14/**5**）が切り捨てと四捨五入の混在で、到達人数列の計算基礎（実数）とも一致しない点を修正（§1）。

9. 口コミ係数 `k = 0` を置いていることを明記（§7.1）。数十%の効果ですが、`k > c` で判定の性質が変わります。

10. 「必要月次獲得は定数」が制約でも最適でもないことを注記（§7.2）。平坦な計画は後ろ寄せより総獲得が1.52倍要ります。
