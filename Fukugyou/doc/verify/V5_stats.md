## 1. power law 論証（B §0.1 / §7.1）

### 1.1 主張の再構成

B は次の 3 段で論じています。

- (P1) 個々の query 需要は power law（Zipf 則に近い形）で分布する。
- (P2) power law 分布を category 単位で平均すると、平均値は裾に支配され、しかも category ごとの裾の形はほぼ同じになる。
- (C) ゆえに「category 平均」は設計上ほぼ定数になる量であり、分散は category **内**にしか存在しない。

B §7.1 は これを「data でなく論理です。確信度: 高」と自己評価しています。

### 1.2 検証: α の条件

power law（Pareto, 指数 α, scale x_m）の性質は α で切り替わります。

- α ≤ 1: 平均が発散
- 1 < α ≤ 2: 平均は有限だが**分散が発散**。標本平均は最大値に支配され、標本ごとに大きく揺れます
- α > 2: 分散が有限。標本平均は通常の中心極限定理に従い、n が大きければ安定します

**(P2) の「平均は裾に支配される」が成り立つのは 1 < α ≤ 2 のときだけです。** そして重要なのは、その場合に導かれる結論が (C) と**逆向き**であることです。裾に支配される平均は「安定した定数」ではなく「揺れる量」だからです。

### 1.3 計算: 同一分布から引いた 5 category の平均の散らばり

利用者の実測（5 市場 35,995 件）に合わせ、1 category あたり 7,199 点を同一 Pareto から引き、category 平均の max/min 比を 3,000 回 simulation しました。

| α | 平均の CV（1 category） | 5 category の平均 max/min（中央値） | 同 p95 | 同 最大 |
|---|---|---|---|---|
| 1.5 | 0.155 | 1.128 | 1.472 | **13.35** |
| 2.0 | 0.0285 | 1.041 | 1.087 | 1.50 |
| 2.5 | 0.0099 | 1.023 | 1.041 | 1.18 |
| 3.0 | 0.0066 | 1.015 | 1.027 | 1.06 |
| （参考）log-normal σ=2 | — | 1.182 | 1.393 | — |
| （参考）指数分布＝軽い裾 | — | **1.027** | **1.046** | — |

読み取れることは 2 つです。

1. **α > 2 の領域では、確かに category 平均はほぼ一致します。しかしそれは power law の性質ではありません。** 軽い裾の指数分布でも max/min は 1.027 で、Pareto α=2.5 の 1.023 と実質同じです。つまりこの領域で効いているのは「同一の生成分布から大標本を引けば標本平均は一致する」という**大数の法則**だけであり、power law という前提は結論に何も寄与していません。前提を落としても結論が変わらないので、論証として機能していません。
2. **α < 2 の領域では、power law は結論を支持するどころか反証します。** α=1.5 では同一分布から引いても category 平均が最大 13 倍ずれます。「裾に支配される」を真に受けるなら、category 平均には**大きな**分散が出るはずで、分散 ≈ 0 は説明できません。

### 1.4 検証: 「裾の形がほぼ同じ」は仮定であって導出ではない

B §7.1 は「power law の指数がどの category でも似ているため」と書いていますが、**これを支持する実証は本 document のどこにも提示されていません。** §7.1 の「確認できた事実」表に挙がっているのは (a) 新規 query 15%、(b) Keyword Planner の bucket 化、(c) 大多数の keyword は月 10 検索以下（確信度 低）の 3 つのみで、いずれも α の値にも category 間の α の一致にも触れていません。

これは手順書 §1 の設計原則 7「引用する数字は原典に当たる。辿れなければ使わない」に、本 document 自身が抵触しています。**論証の成否が α=2 を境に反転するにもかかわらず、α の値が一度も書かれていません。**

### 1.5 検証: 裾の形が同じでも平均は同じにならない

仮に (P2) 前半（α が category 間で共通）を認めても、(C) は導けません。Pareto の平均は α と scale x_m の両方に依存し、`E[X] = x_m · α/(α−1)` です。α が同じでも x_m が違えば平均は x_m の比だけ正確にずれます。

| α | x_m | 標本平均（20 万点） | 理論値 |
|---|---|---|---|
| 2.5 | 1.0 | 1.666 | 1.667 |
| 2.5 | 3.0 | 4.992 | 5.000 |
| 2.5 | 10.0 | 16.681 | 16.667 |

**scale が 10 倍違えば平均も正確に 10 倍違います。** 「裾の形が同じ」から「平均が同じ」への飛躍が、この論証の 2 つ目の穴です。そして category 間で需要規模が違うか否かは、まさに調査で確かめたかったことそのものです。論証は結論を前提に含んでいます。

### 1.6 判定

**不成立。** 3 か所で破綻しています。

1. α > 2 では前提が結論に寄与せず（power law でなくても同じ結論）、α < 2 では前提が結論を否定します。どちらの枝でも論証は機能しません。
2. 「category ごとの裾の形がほぼ同じ」は未検証の仮定であり、B 自身が α を一度も報告していません。
3. 裾の形の一致から平均の一致は導けません（scale parameter が独立に効きます）。

なお **結論そのもの（category 平均に情報が乏しい）が偽だと言っているのではありません。** 結論を支える論証が偽である、という判定です。

### 1.7 元の観測（35,995 件で category 間分散 ≈ 0）の代替説明

power law を根拠にできない以上、別の説明が要ります。強い順に挙げます。

**(a) 同一の生成過程から標本を引いた結果（最有力・ほぼ tautology）**
候補 query を各 category について同じ方法（同じ tool の suggestion 展開、同じ seed 語の作り方）で採取したのであれば、category は「生成分布が違う集団」ではなく「同じ生成分布に貼ったラベル」になります。この場合、標本平均が一致するのは大数の法則の帰結であって、需要の性質ではありません。**確認方法: category ごとに採取手続きが違ったか、seed 語の由来が独立だったかを点検してください。同一手続きなら、この実験は category を測っていません。**

**(b) 指標の選択（強い。RevenueCat との対比が証拠）**
「平均」は分布の差に鈍い統計量です。同じ 5 市場でも、上位 k 件の値、log 中央値、上位 5% の絶対数といった別の統計量を取れば差が出た可能性があります。実際 A §3.2 の RevenueCat は「2 年以内に月 $10,000 到達率」という**別種の統計量**で 5.6 倍（odds ratio 6.0）の差を検出しています。**同じ母集団でも、平均を取ると消える差が、到達率では残ります。**「category 間分散 ≈ 0」は「category に情報が無い」ではなく「使った統計量に情報が無い」を示している可能性が高いです。

**(c) category 定義の粗さ（集約による希釈）**
category が tool 由来の分類（広告 taxonomy 等）である場合、category 内は極端に異質になります。異質な単位を平均すると、category 間の対比は構造的に希釈されます。これは B §6.3 が公的統計について述べている「3-4 桁粗い」問題と同じ構造で、B 自身が別の場所で正しく指摘しています。

**(d) range restriction / 打ち切り**
search volume tool は下側を bucket 0 に潰し（B §2.1）、上側も database 構成で頭打ちになります。category 間で最も差が出るのは裾であるため、裾を落とした後の平均は差が出にくくなります。

**(e) 測定誤差による減衰（弱い）**
tool 推定の ±50%（log SD ≈ 0.405）は category **内**の noise です。within 分散が既に巨大（後述 log SD ≈ 2.6）な場合、η² への影響は 0.15 → 0.148 程度で、単独では分散 ≈ 0 を説明できません。**この説明は採用しないでください。**

### 1.8 修正案

B §0.1 と §7.1 の power law 論証を削除し、次に差し替えることを提案します。

> category 平均に情報が乏しかったのは、power law の性質ではなく **(1) category が同一手続きで採取された標本のラベルに過ぎなかった可能性、(2) 「平均」という統計量が分布の差に鈍いこと** の 2 つで説明されます。同じ 5 市場でも、平均でなく上位 k 件・到達率のような統計量を取れば差が出た可能性は排除できていません。したがって本 document の立場は「category に情報が無いことが証明された」ではなく、**「category を平均で測る設計は情報を取り逃すため、入口単位で測る方が labor あたりの情報量が高い」**です。

§7.1 の「確信度: 高」は、α の実測が無い以上 **「確信度: 低」** に落としてください。

## 2. 分散分解の解釈（手順書 §0 / A §3.2）

### 2.1 主張の再構成

- (P1) category 間の最大差は 8.9% / 1.6% = 5.6 倍。
- (P2) 同一集団内の上位 5% と下位 25% の売上差は約 400 倍。
- (C) ゆえに category 次元の説明力は小さく、category を測る調査は情報量が構造的にほぼゼロ。

### 2.2 検証: 倍率比は分散分解ではない

まず (P1) と (P2) は**異なる量の比**です。

- (P1) は **「月 $10,000 到達確率」という比率**の category 間比。
- (P2) は **「売上」という金額**の分位点間比。

単位も台も違う 2 つの比を並べて「5.6 対 400」と書くことは、分散分解ではありません。分子と分母が同じ尺度でないため、比の大小から分散成分の大小へ移ることはできません。**手順書 §0 の表がこの並置をそのまま「根拠」欄に置いているのは、統計的に正当化できません。**

### 2.3 計算: 同じ尺度に載せ直すと何が出るか

好意的に、両方を log 尺度の散らばりとして読み替えます。

- between: 4 category の値の log 範囲 ln(5.6) = 1.723。n=4 の範囲統計量の期待値係数 d₂ = 2.059 で割り、σ_between ≈ **0.837**
- within: p95 と p25 の比が 400 とみて、z の差 = 1.645 − (−0.674) = 2.319。ln(400) = 5.991 を割り、σ_within ≈ **2.583**

```
η² = σ²_b / (σ²_b + σ²_w) = 0.700 / (0.700 + 6.672) = 9.5%
```

感度分析（within を p97.5/p25 と読んだ場合）でも **11.9%** です。

Cohen の慣行では η² は 0.01 小 / 0.06 中 / 0.14 大です。**9.5% は「中」と「大」の間にあります。**「情報量が構造的にほぼゼロ」という表現は、彼ら自身の数字から導けません。

### 2.4 検証: 5.6 倍は意思決定として十分大きいか

- odds ratio = (0.089/0.911) / (0.016/0.984) = **6.01**
- 期待値としては、選択肢 A の成功確率が選択肢 B の **5.56 倍**
- この差を実験で検出するのに必要な標本は **各群 143 件**（α=0.05, power 0.8）。「検出できないほど小さい差」ではなく、「小標本でも容易に検出できる差」です

**期待値が 5.6 倍違う選択肢を「情報が無い」と呼ぶことはできません。** 副業の 12 週 protocol は 1 つの候補にしか賭けられませんから、成功確率 8.9% と 1.6% の違いは、他のどの gate よりも大きな効果量です。

### 2.5 検証: 「category 内分散が大きい」と「category 選択が無意味」は両立する

その通りで、両者は独立した命題です。「実行の差が大きい」ことは「立地の差が無い」ことを含意しません。

**A §3.2 はこれを正しく扱っています。**

> なお、5.6倍は「ゼロ」ではございません。**category選択は「効かない」のではなく「効き方が小さすぎて、実行の差に容易に飲み込まれる」**という表現が正確です。

**手順書 §0 はこれを硬化させています。**

> 「どの category / 市場を選ぶか」を測る調査 → **やらない。** 情報量が構造的にほぼゼロ

さらに手順書 §8「やらないこと」の筆頭に「category / 市場規模の調査」を置いています。A の「小さいが非ゼロ」から手順書の「構造的にほぼゼロ」への移動は、原典に無い強化です。手順書 §1 原則 5「成功者の『事実』は使い、『因果説明』は証拠にしない」と同じ規律を、自分の統合作業にも適用する必要があります。

### 2.6 判定

**不成立**（倍率比から分散成分の比較へ移る推論として）。加えて、彼ら自身の数字を log 尺度で分解すると η² ≈ 9.5% となり、「ほぼゼロ」という結論の**逆**が出ます。

ただし、**手順書の実務的な運用（category 調査に時間を割かず入口単位に行く）は別の根拠で正当化可能**です。それは「情報が無いから」ではなく **「category 次元は 1 割しか説明せず、しかも category を測る調査の cost が入口を測る調査より高いから」** という labor 配分の議論です。

### 2.7 修正案

手順書 §0 の 1 行目を次に差し替えます。

| 論点 | 決着 | 根拠 |
|---|---|---|
| 「どの category / 市場を選ぶか」を測る調査 | **主要な labor を割かない。ただし「無意味」ではありません** | RevenueCat 115,000 app の category 別到達率を log 尺度で分解すると、category 次元の説明力は η² ≈ 10%（8.9% 対 1.6%、odds ratio 6.0）。**非ゼロですが、残り 90% は category 内にあります。** 自前調査 35,995 件で分散 ≈ 0 だった件は、指標として「平均」を使ったことと採取手続きが category 間で共通だったことで説明され、power law では説明できません（`V5 §1`） |

そして §8 の「やらないこと」から「category / 市場規模の調査」を外し、代わりに **「category 調査に Phase を割り当てないこと（判断は 30 分以内で終える）」** と書いてください。「やらない」と「主要 labor を割かない」は別の指示です。

## 3. 「独立した source へ切り替えると noise が通過できない」（手順書 §3 Phase 2 / B §8）

### 3.1 主張の再構成

- (P1) 同じ source で候補を作り同じ source で選ぶと noise を拾う。
- (P2) funnel の各段で独立した data source に切り替えれば、noise は次段を通過できない。
- (C) ゆえにこの順序は multiple comparisons 対策である。

### 3.2 検証: 偽陽性率が積になる条件

各段の通過基準を「上位 5%」とし、5 段の funnel を考えます。真に価値の無い候補が全段を通過する確率は、各段の判定が**帰無仮説のもとで条件付き独立**なときにのみ 0.05⁵ = 3.1×10⁻⁷ になります。

交換可能な相関 ρ を入れて 40 万回 simulation した結果です。

| 段数 k | 独立仮定（積） | ρ=0.3 | ρ=0.5 | ρ=0.8 | ρ=0.95 |
|---|---|---|---|---|---|
| 2 | 0.002500 | 0.007005 | 0.012382 | 0.025143 | 0.037472 |
| 3 | 0.000125 | 0.001798 | 0.004890 | 0.016845 | 0.031302 |
| 5 | 3.1e-07 | 0.000250 | 0.001700 | 0.010533 | 0.026625 |

**ρ=0.5・5 段で、実効偽陽性率は独立仮定の約 5,000 倍です。** ρ=0.95 になると 5 段でも 2.7% しか下がらず、1 段の 5% とほとんど変わりません。

### 3.3 検証: 実際に相関はあるか

あります。しかも 2 種類の相関が重なります。

1. **需要の実体を共有する相関。** 人気の niche は WordPress の install も Stack Overflow の質問数も Keywords Everywhere の volume も高く出ます。これは**望ましい**相関（真の signal）ですが、同時に noise も相関させます。
2. **測定側を共有する相関。** B §7.5 自身が「複数 tool の平均を取っても改善しません。誤差が独立でなく（同種の panel data に由来）、系統的だから」と書いています。同じ論理が funnel にも当てはまります。特に [1] WordPress → [4] Keywords Everywhere → [2] Atlassian の 3 段は、いずれも「英語圏・B2B software」という同じ生態系の露出度に反応します。

つまり **B は §7.5 で「誤差は独立でない」と正しく述べておきながら、§8 では「source が独立していれば noise は再現しません」と述べており、同一 document 内で相反しています。**

### 3.4 検証: そもそも多重比較の枠組みが適切か

適切ではありません。「候補を絞る」行為には帰無仮説も検定統計量も p 値もありません。B §7.6 の

> 35,995 件を走査して「最も見込みのある入口」を選ぶという行為は、35,995 回の仮説検定と等価です。有意水準 5% で 35,995 回検定すれば、真に何も無くても約 1,800 件が「有意」に見えます。

は、**比喩としては有用ですが、統計的には誤りです。** 正しい枠組みは **winner's curse（選択後推定 bias / regression to the mean）** です。そしてこちらは定量化できます。観測値 = 真値 + noise とすると、選抜された候補の真値は次の割合だけ観測値より低くなります。

```
shrinkage = σ²_noise / (σ²_noise + σ²_signal)
```

tool 推定の ±50% を σ_noise = ln(1.5) = 0.405 として計算しました。

| 真の signal の log SD | shrinkage | corr(観測, 真値) |
|---|---|---|
| 0.40 | **50.7%** | 0.702 |
| 1.00 | 14.1% | 0.927 |
| 1.50 | 6.8% | 0.965 |
| 2.00 | 3.9% | 0.980 |

**重要な含意:** search volume が入口間で桁レベルに散らばる（log SD ≥ 1.5）なら、±50% の tool 誤差は選抜をほとんど汚しません。shrinkage は 7% です。**「35,995 件走査したから上位は noise」は成り立ちません。** 逆に、既に絞り込んだ 20 件の候補が互いに 2 倍以内（log SD ≈ 0.4）なら、上位選抜の半分は noise です。

つまり危険なのは **走査件数ではなく、候補間の真の差が測定誤差に対して小さいこと**です。これは B §2.4 の「2 倍差は差ではない、桁でしか判断しない」と完全に整合しており、実は B は正しい対処法を既に持っています。理由付けだけが間違っています。

### 3.5 検証: funnel が真の候補も殺すこと

AND 型 funnel は偽陽性だけでなく真陽性も掛け算で落とします。各段の検出力を 0.8 とすると全体の感度は次の通りです。

| 段数 | 全体の感度 |
|---|---|
| 2 | 0.640 |
| 3 | 0.512 |
| 5 | **0.328** |

**5 段の funnel を全通過する真の候補は 3 分の 1 です。** 手順書 §0 の設計思想「外れを安く殺す」に照らせば、これは意図した trade-off であり欠陥ではありません。ただし **手順書はこの代償を明記していません。** 「1 つの候補が落ちても候補が悪いとは限らない（3 回に 2 回は良い候補も落ちる）」と書いておかないと、利用者は 1 回の棄却で領域全体を諦めます。

### 3.6 判定

**条件付き成立。**

- 成立する部分: 独立でない source でも、段を重ねれば偽陽性は**単調に下がります**（表の通り ρ=0.8 でも 5 段で 0.05 → 0.0105）。方向は正しく、実務上の推奨も妥当です。
- 成立しない部分: (i) 「積になる」という定量的な主張、(ii) 「noise は次段を通過できない」という断定、(iii) multiple comparisons という枠組みの適用、(iv) B 内部の §7.5 との矛盾。

### 3.7 修正案

手順書 §3 Phase 2 の該当段落を差し替えます。

> 順序は §5 の通りで、**各段階で異なる data source に切り替わる**点が重要です。同じ source で候補を作り同じ source で選ぶと、その source 固有の誤差が選抜に持ち込まれます。
>
> ただし source 間には相関があるため（人気の niche はどの source でも高く出ます）、**偽陽性率は掛け算では下がりません。** 相関 0.5 の 5 段で、実効的な通過率は独立を仮定した場合の約 5,000 倍です。段を重ねる効果は「消える」ではなく「減る」です。
>
> また、AND 型の funnel は真の候補も落とします。各段の見落とし率を 2 割とすると、5 段を全通過する良い候補は **3 分の 1** です。**1 つの候補が落ちたことは、その領域が悪いことの証拠にはなりません。**
>
> なお、走査件数そのものは問題ではありません。危険なのは **候補間の真の差が測定誤差より小さいとき**です。候補が互いに 2 倍以内なら上位選抜の約半分は noise、桁が違うなら noise の混入は 1 割未満です（§5.3 の「桁でしか判断しない」はこのための規則です）。

B §7.6 の「35,995 回の仮説検定と等価」「約 1,800 件が有意に見える」は削除し、上記の shrinkage 表に置き換えてください。

## 4. Phase 3 の停止規則

### 4.1 主張の再構成

- (G1) 6 件時点で「金または時間を実際に投じている」が 2 件以下なら中止。根拠は「metatheme は 6 件で出現するため（Guest et al. 2006）、6 件で何も出なければ 12 件でも出ない」。
- (G2) 12 件中 8 件以上が同じ trigger なら次へ。ばらばらなら中止。

### 4.2 検証: alpha 消費と bias

**alpha 消費は問題になりません。** (G1) は futility（無効中止）のみで、途中で「有望」と判定して先に進む efficacy 停止がありません。futility 停止は type I error を**減らす**方向にしか働きません。したがって「中間解析で α を消費する」という一般論はこの設計には当てはまりません。

**bias は発生します。** 通過した候補についてのみ「12 件中 X 件が同一 trigger」を報告すると、条件付き期待値は上振れします。

| 真の集中度 p | E[X/12 \| X≥8] | 上方 bias |
|---|---|---|
| 0.5 | 0.708 | +0.208 |
| 0.6 | 0.730 | +0.130 |
| 0.7 | 0.764 | +0.064 |

**gate を通った候補の「集中度 70%」は、真の集中度が 50% でも普通に観測されます。** gate 通過後にこの数字を事業計画の前提（「顧客の 7 割はこの trigger を持つ」）に使ってはいけません。

### 4.3 計算: 検出力と偽陰性率

帰無仮説と対立仮説を明示します。

- **(G1)** H₀: 実際に金/時間を投じている割合 p ≤ 0.2（棄却してよい領域） / H₁: p ≥ 0.5（進めたい領域）
- **(G2)** H₀: trigger が特定の 1 つに集中していない（p ≤ 0.4） / H₁: 集中している（p ≥ 0.6）

**(G1) 単独: X ≥ 3 of 6 で継続**

| 真の p | P(中止) | P(継続) |
|---|---|---|
| 0.1 | 0.9841 | 0.0159 |
| 0.2 | 0.9011 | 0.0989 |
| 0.3 | 0.7443 | 0.2557 |
| 0.4 | 0.5443 | 0.4557 |
| **0.5** | **0.3438** | 0.6562 |
| 0.6 | 0.1792 | 0.8208 |
| 0.7 | 0.0705 | 0.9295 |
| 0.8 | 0.0170 | 0.9830 |

H₀（p=0.2）で誤って継続する率は 9.9% と良好です。しかし **H₁（p=0.5）で誤って中止する率が 34.4%** あります。真に半数の顧客が金か時間を投じている領域を、3 回に 1 回捨てます。

**(G2) 単独: X ≥ 8 of 12**

| 真の p | P(通過) |
|---|---|
| 0.3 | 0.0095 |
| 0.4 | 0.0573 |
| 0.5 | 0.1938 |
| **0.6** | **0.4382** |
| 0.7 | 0.7237 |
| 0.8 | 0.9274 |

H₀（p=0.4）での通過率 5.7% は良好です。しかし **H₁（p=0.6）での通過率は 43.8%**、つまり **偽陰性率 56.2%** です。**真に 6 割の顧客が同じ trigger を持つ領域の半分以上を、この gate は落とします。**

**両 gate の合成（構成概念が別なので掛け算になります）**

| P(投資) | P(同一 trigger) | 通過確率 |
|---|---|---|
| 0.4 | 0.6 | 0.200 |
| 0.5 | 0.6 | 0.288 |
| 0.5 | 0.7 | 0.475 |
| 0.6 | 0.6 | 0.360 |
| 0.6 | 0.7 | 0.594 |

**「顧客の 5 割が金を払っており、6 割が同じ trigger を持つ」というかなり良い領域でも、この 2 段を通過するのは 29% です。**

参考までに、両 gate が**同じ**構成概念を測っている場合（中間 gate が純粋な futility 解析になる場合）、中間 gate が失う検出力は 0.4〜0.7% に過ぎません。**問題は中間解析ではなく、最終 gate の閾値 8/12 が厳しすぎることです。**

### 4.4 検証: 「同じ trigger」の多重性

もう 1 つの問題があります。**trigger は事前に定義されておらず、12 件を見てから「8 件以上を占める trigger があるか」を探します。** これは k 個の候補 label に対する最大値の検定です。

12 件を k 個の label に一様に振った（＝集中が無い）ときの結果です。

| label 数 k | P(ある label ≥8) | P(ある label ≥6) |
|---|---|---|
| 2 | 0.3885 | 1.0000 |
| 3 | 0.0569 | 0.5280 |
| 4 | 0.0112 | 0.2177 |
| 5 | 0.0030 | 0.0970 |
| 6 | 0.0009 | 0.0470 |

trigger を 2 分類でしか記述しない人（例: 「新規案件が来たとき」対「それ以外」）は、**集中が全く無くても 39% の確率で gate を通過します。** 逆に 6 分類する人は 0.09% しか通りません。**同じ現実を見ても、記述の粒度で判定が 400 倍変わります。** これは手順書 §4 が禁じている「走りながらの gate 緩和」の一種で、しかも gate を書き換えなくても発生します。

対処: **Phase 3 開始前に trigger の分類 label を 4〜5 個、文言まで確定して file に書く。** 12 件を見てから label を作らない。手順書 §4 の「判定基準は Phase 開始前に確定」の対象に、閾値だけでなく**分類体系**も含めてください。

### 4.5 検証: Guest et al. の転用

**成立しません。**

Guest, Bunce & Johnson (2006) が示したのは **theme の飽和**、すなわち「新しい code が何件目から現れなくなるか」です（60 件中 12 件で飽和、metatheme の基本要素は 6 件で出現）。これは **「有病率の高い theme は早期に少なくとも 1 回出現する」** という主張です。

手順書 (G1) が要求しているのは **「6 件中 3 件以上」という有病率の閾値**です。この 2 つは別の量です。

出現確率を計算します。有病率 p の theme が 6 件中**少なくとも 1 回**現れる確率は次の通りです。

| 有病率 p | 1−(1−p)⁶ |
|---|---|
| 0.1 | 0.469 |
| 0.2 | 0.738 |
| 0.3 | 0.882 |
| 0.5 | 0.984 |

Guest の主張（6 件で metatheme が出る）に対応するのは 0.882〜0.984 のほう、すなわち **「6 件中 1 件も出なければ、有病率 30% 以上の theme はほぼ無い」** です。これは論理的に正しい contrapositive です。しかし手順書は **「6 件中 3 件以上」** を求めており、これは有病率 50% を暗黙に要求しています。**Guest はこの閾値について何も述べていません。**

加えて、Guest の設定は西 Africa 2 か国での同質集団に対する in-depth interview で、B2B software の購買 trigger とは対象が違います。後続研究では code 飽和が 9〜17 件と報告されており、6 件は Guest の設定に固有の値です（C §8 自身も「12 件で飽和しない市場もあります」と注記しています）。

**要するに (G1) の閾値は二項分布から直接正当化できます（§4.3 の表がそれです）。Guest を引く必要も、引く根拠もありません。** 引くとかえって「質的飽和の権威を量的閾値の根拠に見せかける」誤用になります。

### 4.6 判定

- **中止側の性質: 条件付き成立。** futility 停止であるため α 消費の問題はなく、H₀ での誤継続率も低い（9.9% / 5.7%）です。
- **検出力: 不成立。** H₁ での偽陰性率が (G1) 34%、(G2) 56%、合成で 71% に達します。手順書はこの数字を一切示していません。
- **Guest 転用: 不成立。** 質的飽和（theme の出現）を量的閾値（有病率 3/6）に転用することはできません。
- **多重性: 未処理の欠陥。** trigger 分類が事前確定されていないため、判定が記述粒度に依存します。

### 4.7 修正案

手順書 §3 Phase 3 と §4 の判定表を次のように改めます。

1. **(G1) の根拠から Guest を外す。** 差し替え文:
   > 6 件のうち「金または時間を実際に投じている」が 2 件以下なら中止。これは二項分布から直接出る基準です。真の割合が 20% なら 90% の確率で正しく中止でき、40% なら 54% で中止します。**ただし真の割合が 50% ある領域も 34% の確率で中止します。** この gate は「安く殺す」ための非対称な設計であり、中止は「需要が無い証明」ではありません。
2. **(G2) の閾値を緩め、偽陰性率を明記する。** 8/12 は真の集中度 60% の領域を 56% 落とします。**7/12 に緩めると** P(通過 | p=0.6) = 0.665、P(通過 | p=0.4) = 0.158 となり、H₁ の見落としが 34% まで下がる代わりに H₀ の誤通過が 16% に上がります。Phase 4 が「金が動くか」という更に強い gate である以上、**Phase 3 は落としすぎない側に倒すべきです。7/12 を推奨します。**
3. **trigger 分類 label を Phase 3 開始前に 4〜5 個、文言まで確定して file に書く。** §4 の判定表に「trigger 分類 label（事前確定）」の行を追加してください。
4. **§4 判定表の「12 件中の同一 trigger 件数 ≥ 8（6 件時点 ≥ 3）」を修正する。** §3 の 6 件 gate は「金または時間を投じた件数」であり、同一 trigger 件数ではありません。表の括弧書きは構成概念を取り違えています。行を 2 つに分けてください。
5. **gate 通過後に観測された集中度を事業前提に使わないよう注記する。** 真の集中度 50% でも、通過した候補では平均 71% と観測されます（§4.2）。

## 5. 個人規模での A/B test 不可能性（C §4）

### 5.1 計算: 2% → 3% の検出に必要な標本

両側 α=0.05、power 0.80、2 群比率の比較。

```
n = (z_{0.975} + z_{0.80})² × [p₁(1−p₁) + p₂(1−p₂)] / (p₂ − p₁)²
  = (1.960 + 0.8416)² × [0.02×0.98 + 0.03×0.97] / (0.01)²
  = 7.849 × 0.04870 / 0.0001
```

| 式 | 各群 | 合計 |
|---|---|---|
| 単純式 | **3,822** | **7,645** |
| pooled 分散式（正しい形） | **3,825** | **7,650** |
| simulation による検証（n=3,826/群、2 万回） | 検出力 **0.805** | — |

**合計約 7,650 click が必要です。**

### 5.2 検証: この数字は「回らない」を支持するか

支持します。

| 月間 visit | 両群を埋めるのに要する月数 |
|---|---|
| 200 | 38.3 |
| 500 | 15.3 |
| 1,000 | 7.7 |
| 3,000 | 2.6 |

手順書 §4 の Phase 4 gate は「4 週で GSC impression > 0」です。impression が数百〜数千の段階で click は 2 桁でしょうから、A/B test は 2 桁足りません。C §4.6 の「traffic が月 1,000 未満なら A/B test をせず、大きく違う案を逐次投入」は妥当です。

なお C §4.1 の表（baseline 3.8%）と本節（baseline 2%）は baseline が違うだけで、結論の向きは同じです。C の計算式・数値も再計算して一致を確認しました。

### 5.3 検証: 「金が動いたか / 動かなかったか」の 2 値判定は何を主張できるか

**主張できること（否定側）: 上限。** Clopper-Pearson 95% 区間で計算しました。

| 観測 | 95% 信頼区間 | rule of three（3/n） |
|---|---|---|
| 0 / 30 | [0%, **11.6%**] | 10.0% |
| 0 / 300 | [0%, **1.22%**] | 1.00% |
| 1 / 30 | [0.084%, 17.2%] | — |
| 1 / 12 | [0.211%, **38.5%**] | — |
| 2 / 12 | [2.09%, 48.4%] | — |
| 3 / 30 | [2.11%, 26.5%] | — |

**「30 名接触して 0 件」は「conversion は 11.6% 未満」という堅い結論**です。C §7.2 Phase 4 の「接触した 30 名から 0 件なら conversion は 10% 未満」は rule of three として正しく、事業を畳む判断に十分な精度です。

**主張できること（肯定側）: 存在のみ。** n=1〜数件で言えるのは「p > 0」だけです。1/12 の区間は [0.2%, 38.5%] で、幅が 2 桁以上あります。**「1 件売れた」から price や事業規模を推定することはできません。**

**この非対称性が (C §4) の核心であり、統計的に正しい主張です。** ただし、手順書 §3 Phase 4 の書き方には 1 点欠落があります。

> 比較実験ではなく「金が動いたか / 動かなかったか」の 2 値で判定します。

**分母（何名に、いくらで提示したか）を事前に宣言しなければ、この 2 値判定は何の上限も与えません。** 「1 件売れた」は、10 名に提示した場合と 300 名に提示した場合で意味が全く違います。手順書 §4 の判定表には「事前販売の件数 / 金額（自分で宣言）」とありますが、**提示した相手の人数（分母）の欄がありません。**

もう 1 点、**肯定側の特異度**が低いことも書くべきです。最初の数件は知人・強い早期採用者から出やすく、母集団の p を代表しません。**「1 件出た」は継続の許可であって、成立の証拠ではありません。**

### 5.4 判定

**成立。** 計算は C §4 の主張を支持します。代替設計（否定に倒す・rule of three）も統計的に正当です。

### 5.5 修正案

手順書 §4 の判定表に 1 行追加してください。

| Phase | 指標 | 基準値 | 判定日 |
|---|---|---|---|
| 4 | **事前販売の提示相手の人数（分母）** | **（自分で宣言。30 名以上を推奨）** | |

および §3 Phase 4 に次を追記します。

> **分母を先に宣言してください。** 「金が動いたか」の 2 値判定が意味を持つのは、提示相手の人数が事前に決まっている場合だけです。30 名に提示して 0 件なら「conversion は 11.6% 未満」という堅い結論になりますが（rule of three）、10 名で 0 件は何の情報でもありません。逆に **1 件出たことが言えるのは「p > 0」だけです**（1/12 の 95% 区間は 0.2%〜38.5%）。最初の 1 件は知人や強い早期採用者から出やすく、母集団を代表しません。**1 件は継続の許可であって、成立の証拠ではありません。**

## 6. benchmark の解釈（D §5 / 手順書 §6.4）

### 6.1 主張の再構成

- (P) 月 $50 未満 tier は GRR 23% / NRR 32%、月 $250 超 tier は GRR 70% / NRR 85%。
- (C) 低単価 self-serve は churn を価格で買っている構造である。単価を上げることは利益率の問題ではなく、事業が成立するかの問題である。

### 6.2 検証: これは観察 data からの因果推論です

(C) は「価格 → churn」という因果の向きを主張しています。これを観察 data から導くには交絡の排除が要りますが、排除されていません。少なくとも次の 4 経路が未処理です。

**(1) 顧客種別の交絡。** 月 $50 未満の tier を買うのは個人・prosumer・試用目的の利用者が中心で、月 $250 超は法人です。法人には稟議・年度予算・複数利用者・移行 cost があり、解約が構造的に遅くなります。churn の差は価格ではなく購買主体の差で説明できます。

**(2) 逆因果。** 継続利用の見込みが薄い用途（一時的・試用的）ほど支払意思が低く、**だから安い価格が付いています。** 価格は顧客種別の下流にある結果変数であって、原因ではありません。**同一の product の価格だけを $9 から $250 に上げても、$250 tier の retention には移動しません。移動するのは conversion のほうです。**

**(3) NRR 差の一部は定義上の帰結です。** NRR は expansion revenue を含みます。単一 seat・固定機能の月 $9 plan には**構造的に expansion 経路がありません**。上限が GRR に等しくなります。一方 $250 超の plan は seat 数・利用量で増えます。したがって NRR 32% 対 85% の差のうち、行動の差ではなく **課金 model の差**に帰す部分が確実にあります。D は GRR も併記しているので誠実ですが、手順書 §6.4 は NRR を並べたまま因果を読ませています。

**(4) 製品成熟度。** D §5.1 の注記どおり、この表は AI-native 約 200 社のものであり、AI-native は新しく実験的利用が多い層です。価格 tier と製品年齢が交絡しています。**D 自身がこの注記を書いていますが、手順書 §6.4 は落としています。**

### 6.3 検証: ecological fallacy

あります。しかも二重です。

**(1) 集団水準の関連を個人水準に適用している。** 「価格 tier 別の企業中央値」は企業を単位とした集約量です。tier 内の分散は報告されていません。中央値が 23% でも、その tier に GRR 70% の企業が存在しないことは示されていません。**「あなたの product が低単価なら GRR は 23% になる」は、この表から導けません。**

**(2) 標本が個人規模ではありません。** D §5.1 は「retention 算出は **ARR $250k 以上**を対象」と明記しています。つまり「月 $50 未満 tier」の企業とは、**単価が $50 未満で ARR が $250k 以上ある企業**、すなわち顧客を 400 名以上抱える企業です。副業の個人（ARR 数千〜数万ドル）とは母集団が違います。手順書 §9 が「ARR 30 万ドル未満の SaaS の churn benchmark は公表されていない」と正しく書いている一方で、§6.4 では ARR $250k 以上の benchmark を個人の意思決定に当てはめており、**手順書内部で矛盾しています。**

### 6.4 計算: 手順書内部の数値矛盾

年次 GRR を月次 logo churn に直します。

| tier | 年次 GRR | 含意される月次 churn |
|---|---|---|
| 月 $250 超 | 70% | 2.93% |
| 月 $50〜249 | 45% | 6.44% |
| 月 $50 未満 | 23% | **11.53%** |

一方、手順書 §2.3 は次のように書いています。

> **月 3% churn は「理想」ではなく「中央値」**（ChartMogul 2023、2,100 社超の実 billing data）

年次にすると 0.97¹² = 69.4%、すなわち **GRR 約 70%** で、上表の「月 $250 超」tier と一致します。**同一手順書内に、月次 churn が 3.8 倍食い違う 2 つの中央値が、いずれも「中央値」として並置されています。** どちらの母集団の話かを書かない限り、読者はどちらを前提にすべきか判断できません。

### 6.5 判定

**不成立**（因果推論として）。交絡（顧客種別・契約 model・製品成熟度）と逆因果が排除されておらず、NRR 差の一部は課金 model の定義上の帰結です。加えて集団水準の中央値を個人に適用する ecological fallacy があり、標本の下限（ARR $250k 以上）が対象読者の規模と乖離しています。

**ただし「単価を上げよ」という実務的な推奨自体は、別の根拠で維持できます。** 単価が低いと (a) 必要顧客数が増えて support 工数が線形に増える、(b) 個人が到達できる channel の規模で必要顧客数に届かない、(c) 単一 seat plan には expansion 経路が無い、という 3 つは因果 data を必要としない構造的な議論です。

### 6.6 修正案

手順書 §6.4 を差し替えます。

> **低単価 self-serve は継続率が低い、という強い相関があります。**ChartMogul 2025 の **AI-native 製品 約 200 社**（retention 算出は **ARR $250k 以上**が対象）で、月 $50 未満 tier は GRR 23% / NRR 32%、月 $250 超 tier は GRR 70% / NRR 85% でした。
>
> **これを「価格を上げれば churn が下がる」と読んではいけません。** 価格 tier は顧客種別（個人 / 法人）・契約 model・製品成熟度と交絡しており、価格はむしろ顧客種別の**結果**です。同じ product の価格だけを上げても $250 tier の retention には移動しません。また NRR 差の一部は定義上の帰結です（単一 seat の月 $9 plan には expansion 経路が構造的に存在せず、NRR は GRR を超えられません）。
>
> **標本の規模にも注意してください。** この表の「月 $50 未満 tier」とは、単価が $50 未満で **ARR が $250k 以上ある**企業、すなわち顧客を 400 名以上抱える企業です。副業の個人規模の benchmark ではありません（§9 のとおり、その帯の benchmark は公表されていません）。
>
> **それでも単価を上げるべき理由は、因果 data ではなく構造から出ます。** (1) 単価が低いほど必要顧客数が増え、support 工数が線形に増える。(2) 個人が到達できる channel の規模では、必要顧客数に届かない。(3) 単一 seat plan には収益を伸ばす経路が無く、成長が新規獲得だけに依存する。
>
> なお §2.3 の「月 3% churn は中央値」（ChartMogul 2023、ARR $30 万以上）は年次 GRR 約 70% に相当し、上表の「月 $250 超」tier に対応します。**2 つの数字は矛盾しておらず、母集団が違うだけです。自分がどちらの帯にいるかを先に決めてから、対応する benchmark を使ってください。**

## 8. 手順書 §0 の土台は維持できるか

**結論: §0 の 5 行のうち 1 行目（category 調査をやらない）は、現在の根拠では維持できません。残り 4 行は維持できます。**

| §0 の論点 | 土台の状態 |
|---|---|
| category / 市場を測る調査をやらない | **維持できません。** 根拠として挙がっている 3 つのうち、(a) power law 論証は不成立（§1）、(b) 5.6 倍対 400 倍は分散分解ではなく、log 尺度に直すと η² ≈ 9.5%（§2）、(c) 自前 35,995 件の分散 ≈ 0 は測定設計で説明でき、category の性質の証拠になりません（§1.7）。**3 つとも崩れます。** ただし結論を弱めた形（「主要な labor を割かない」）なら維持可能です |
| TAM / SAM / SOM の省略 | **維持できます。** A §3.1 が「予測妥当性を検証した査読論文は発見できなかった」と正直に書いており、「有効という証拠が無い」という控えめな根拠付けは統計的に問題ありません。ただし §3.2 の分散分解に依存している部分は §2 の修正に合わせて弱めてください |
| 成功事例からの逆算を手法として使わない | **維持できます。** Denrell (2003) は形式 model による証明で、Golder & Tellis (1993) が実証的裏付けです。本監査で問題を見つけていません |
| 「red ocean を避けよ」を folklore 扱い | **維持できます。** 統計的推論としては pioneer 失敗率 47%（500 brand / 50 category の歴史再構成）に依拠しており、母集団の作り方が明示されています |
| 調査の目的は「外れを安く殺す」 | **維持できます。しかも本監査で強化されました。** §5 の rule of three（0/30 → 11.6% 未満）が、否定側の推論が小標本で成立し肯定側が成立しないことを定量的に裏付けています。§3.5 の「AND funnel の感度は 5 段で 0.33」も同じ設計思想の帰結で、これは欠陥ではなく意図した trade-off です |

### 崩れる 1 行が手順書全体に及ぼす影響

したがって **必要な修正は §0 の表現の後退と §8「やらないこと」からの削除であり、pipeline の作り直しではありません。**
