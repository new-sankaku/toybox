## 1. 致命

### #1 Phase 4 の GSC gate は反証として機能しません

**引用（手順書 §3 Phase 4）**
> landing page を 1 枚作り、狙う入口の語で index させ、Google Search Console で **impression が立つか**を見ます。impression が 0 なら、その入口はあなたの想定した言葉で検索されていません。**これは search volume tool がどれだけ大きな数字を返しても覆せない事実です。**

**引用（手順書 §2.3）**
> **96.55% の page は Google からの流入がゼロ**（Ahrefs, 2023、約 140 億 page）…「**既定値は流入ゼロであり、それを覆す理由の説明が必要**」の意味

**何が問題か**

impression = 0 は、少なくとも次の4つの原因の論理和であって、需要の不在ではありません。

1. **index されていない。** 新規 domain の1枚の page が4週で index される保証はありません。手順書は「index させ」と1行で書きますが、index されなかった場合の観測値も 0 です。
2. **順位が低い。** impression は「その語の検索結果 page に自分の page が表示されたこと」であり、100位なら実質 0 です。つまりこの gate は需要ではなく **自分の順位** を測っています。
3. **anonymized query の除外。** B §2.5 は「少数 user しか出していない query は表から除外される」と記録しています。手順書が測ろうとしているのは定義上の低頻度語であり、**除外規則が最も効く帯域とちょうど重なります**。
4. **channel の取り違え。** Phase 2 の gate（#5 参照）は WordPress plugin directory の検索 hit 数と install 数で入口を篩います。そこで残る入口の流通経路は **WordPress.org の store 内検索** です。その入口に対して Google の impression を測るのは、別の channel の空きを測っているに過ぎません。手順書 §7 は自ら「獲得 channel が SEO 依存でないか」を確認項目に挙げており、**SEO 非依存を推奨しながら Google の指標を唯一の終端 gate に置く**という矛盾になっています。

さらに、§2.3 の 96.55% の使い方自体が誤っています。E は Ahrefs 自身の caveat を2点記録しています — 140億 page は index 全体（推定3,408億）のうち「質の高い」側に偏った部分集合であること、traffic 推定が6.51億 keyword に依存し超 long-tail を拾えていないこと。手順書はこの2点を落としたうえで、**「web上の全 page」という参照集合の base rate を、「特定の語を知っている当事者が意図して作った1枚」という別の参照集合に適用**しています。

**なぜ問題か**

gate の目的は仮説の反証です。既定値が流入ゼロだと自ら宣言している以上、impression 0 は仮説と整合する観測であり、何も棄却しません。逆に impression が立った場合も、それは「index されて順位が付いた」ことの証拠であって支払意欲の証拠ではありません。**両側とも情報量がゼロに近い gate** です。加えて、この記述は B §8-5 の断定文をそのまま持ち込んだものですが、B は道具の説明として書いており、手順書はそれを **判定規則** に格上げしています。格上げの瞬間に検証責任が発生しているのに、それが果たされていません。

**修正案**

1. GSC を gate から外し、**補助観測**に降格してください。gate に残すなら、`impression = 0` ではなく `index 済み（URL 検査で確認）かつ平均順位が取得できている状態で impression = 0` という **前提条件つきの複合条件**に書き換えてください。前提が満たされない場合は「測定不成立」であり、不合格ではありません。
2. 需要の実測は index に依存しない経路に置き換えてください。C §3.1 は landing page test に **有料 traffic** を前提しています。数千円の検索広告で狙う語に対する click を買えば、index も順位も交絡しません。
3. 判定は C §4.3 の rule of three で行ってください。「300 訪問で0件 → conversion は1%未満」は index 状態に依存しない堅い否定です。
4. WordPress / Atlassian 系の入口を選んだ場合の終端 gate は、Google ではなく **その store 内での掲載後の impression / install** に置き換えてください。channel を測る対象と一致させることが必須です。

### #2 着手を決める唯一の gate が空欄で、宣言時点が第8週です

**引用（手順書 §4）**
> | 4 | 事前販売の件数 / 金額 | （自分で宣言） | |
>
> 数値は事業の目標に応じて自分で埋めます。**空欄のまま Phase を開始しないでください。**

**引用（B §7.6）**
> **事前登録** — 走査する**前に**「何を満たしたら採用するか」を数値で書き出す。走査結果を見てから基準を決めると、必ず noise を拾います

**何が問題か**

Phase 0〜3 の閾値（1 / 5・3 / 1 / 8・3）は手順書側で固定されているのに、**着手可否を決める唯一の gate だけが読者任せ**です。しかも「Phase 開始前に確定」という規定に従えば、Phase 4 の数値が確定するのは第8週の開始時点です。その時点で読者は56時間と12件の interview を投じています。B が事前登録を要求したのは、まさにこの状況で人が基準を動かすからです。**最も動きやすい gate だけが最も遅く決まる**という、防ぎたい失敗そのものの配置になっています。

「目安の置き方の指針すら無い」のも事実誤認ではなく、元documentに材料があるのに落としたものです。

- C §7.2 Phase 4: 「接触した30名から0件なら、その価格・価値提案の conversion は10%未満」
- C §4.3: rule of three（n=100→3%以下、n=300→1%以下）
- D §3.2: 目標月次利益から必要契約数・**必要月次純増契約数**への逆算
- E #11: 副業月収の中央値5万円という、目標額の現実性を測る唯一の公的分布

**なぜ問題か**

空欄の gate は gate ではありません。判定基準を宣言できない候補は不採用だと §4 は書いていますが、その規則が自分自身の表に適用されていません。

**修正案**

1. Phase 4 の数値を **Phase 0 の時点で** 宣言させ、file に commit させてください（C §4.4 の p-hacking 対策と同じ運用）。Phase 4 開始時ではなく、投資が最小の時点で決めることが要点です。
2. 空欄のまま出さず、**導出式**を書いてください。例:
   - 目標月次利益 → 必要 MRR → 想定単価 → 必要契約数（D §3.2）
   - 必要契約数 × 想定 conversion → 必要接触数
   - 接触数が確保できないなら、その時点で単価設計をやり直す（D §8 step6 と同じ判定）
3. 「何件接触したか」を必ず記録させてください。分母のない「0件」は rule of three が使えず、否定にすらなりません（#9・#18 と連動）。

### #3 stock 型の唯一の真の証拠「2ヶ月目の決済」が消えています

**引用（手順書 §3 Phase 4）**
> 比較実験ではなく「金が動いたか / 動かなかったか」の 2 値で判定します。

**引用（C §3.0）**
> 継続課金（2ヶ月目の決済） ← stock 型 business では唯一の真の証拠
> **副業 micro SaaS では最下段の「2ヶ月目の決済」が到達目標です。**stock 型 business の経済性は継続率で決まるので、初回決済だけでは何も証明されていません。

**引用（C §8 落とし穴12）**
> | 12 | 初回決済で PMF と判断する | 第3.0節（stock 型の本命は継続） | 2ヶ月目の決済を判定点にする |

**何が問題か**

手順書の終端判定は初回決済の2値です。これは C が明示的に落とし穴として列挙した行為と一字一句同じです。C の protocol では週10末に「3名全員が2ヶ月目も支払った」を判定点に置いていました。手順書はこの判定点を丸ごと削除しています。

削除の影響は D §5.1 が定量化しています。月$50未満の tier は GRR 23%、つまり1年で顧客の8割弱が消えます。初回決済しか見ない判定は、**この構造を検出できない位置に判定点を置く**ことを意味します。F §2-3 も A 類型の確認項目として「解約理由が『使わなくなった』か『代替した』か」を挙げており、初回決済ではこれも取れません。

**なぜ問題か**

手順書の対象は明示的に「stock 型 business」です。その対象の成否を決める変数を測らないまま着手判断を出す設計になっています。

**修正案**

1. Phase 4 の gate を「初回決済 N 件」から **「2ヶ月目の決済 M 件」** に変更してください。C の値（3名中3名）をそのまま採るか、自分で M を宣言するかは読者の判断ですが、判定点は2ヶ月目に置くことを必須にしてください。
2. これに伴い Phase 4 は最低8週必要になります。現在の4週では2回目の課金日が来ません。#18 の期間見直しと同時に扱ってください。
3. 解約が出た場合、C §4.6 の通り **全数に理由を聞く**手順を Phase 4 に足してください（n が小さいので全数調査が可能です）。

### #4 interview 12件の接触先が手順書に書かれていません

**引用（手順書 §3 Phase 1）**
> Reddit / Stack Overflow / GitHub issue / 業界 forum / X を、採取した語彙で検索し直しながら 2 周します。

**引用（C §7.2 Phase 1、週あたり時間）**
> | interview 候補者の list 化（最低20名。実名・所属・接点） | 2時間 |
> | 接触（既存の知人経由の紹介依頼、Qiita/Zenn 記事の投稿） | 2時間 |

**何が問題か**

C の Phase 1 は週7時間のうち **4時間を候補者の list 化と接触に充てています**（2週で8時間）。さらに C の interview phase では毎週2時間を「次の候補者への接触・日程調整」に充てています。手順書 Phase 1 は「14時間で community 観察を2周」としか書いておらず、**この8時間の獲得工数を削除したまま、Phase 3 の12件という目標だけを残しています**。

加えて、C が持っていた接触経路の知見が全滅しています。

- C §6.2.2: Qiita / Zenn に自分の困った経験を書き、comment で当事者を釣り上げる。「日本語圏で最も costs の低い interview 相手の発見法」
- C §6.2.1: 展示会の**来場者**に話しかけ、後日30分の interview を依頼する（土日開催を選べば副業と両立）
- C §1.8.7: interview 末尾の紹介依頼（手順書は30分配分の最後に「紹介依頼」とだけ残していますが、最初の1件をどう得るかは書かれていません）
- C §6.2.3: **日本では個人宛の突然の連絡は忌避されやすく、紹介の重みが大きい**

**引用（B §3.2(e)）**

### #8 「再検討不要」と宣言した論点から、反証が削除されています

**引用（手順書 §0）**
> 再検討の必要がない事項を先に固定します。蒸し返すと時間を失います。
> | 「どの category / 市場を選ぶか」を測る調査 | **やらない。** 情報量が構造的にほぼゼロ | …（`B §7.1`） |

**引用（A §1.4）**
> 著者らは成功を「market timing skill（良い industry × 良い年に始めたこと）」と…に分け、**次回成功を最もよく予測するのは前者**だと報告しております。

**なぜ問題か**

手順書の設計原則3は「調査は『観察』ではなく『反証可能な予測』の形にする」です。その文書が、自分の前提に対する最強の反証を統合時に落としています。読者は反証の存在を知らないまま「再検討禁止」を受け取ります。これは手法の問題ではなく、**文書の誠実性の問題**です。

**修正案**

1. §0 の当該行の根拠欄に、Gompers et al. の存在と A §1.4 の3つの限定を **1〜2行で明記**してください。「反証はあるが母集団が違うため本件には適用しない」と書けば済みます。消す必要はありません。
2. 「蒸し返すと時間を失います」という表現を削ってください。再検討を禁止する文言は、反証可能性を掲げる文書と両立しません。「この論点を再検討する場合は、以下の反証と限定を出発点にしてください」に書き換えるべきです。

手順書 §1-6（原則6）は A §6 第6条を引いていますが、第6条の根拠は「日本公庫の販路課題」と「**実測 data では価格設計・paywall・trial 長といった実行 variable に2〜8.6倍の効果が観測されている**」の2つでした。手順書は前者だけを残し、後者を落としました。

その結果、A が「同じ調査基盤が生き返る」と提案した再設計の方向（実行 variable の事前見積り）が手順書に一切現れません。§7 の型別確認項目にも paywall 方式・trial 長・free tier 設計の項目はありません。§7 の A 類型に F 由来の5項目が並びますが、そのどれも実行 variable ではありません。

**なぜ問題か**

手順書の中心命題は「category を測る調査は情報量が低い」です。その裏面が「実行の差が結果を決める」であり、A はその実行の差を数値で測っていました。**裏面を落とすと、手順書は『何を測っても無駄』に近い主張だけを残します。** 実際、12週の pipeline を通っても、読者は paywall / trial / 価格 tier について何一つ決めていません。

**修正案**

§7 の共通確認項目、または新しい節として **実行 variable の事前決定** を追加してください。最小構成は3つです。

- 課金方式（hard paywall / freemium / free trial）— A §2.4 の効果量（D35 conversion で約5倍）を根拠として提示
- trial 長（17〜32日 vs 4日以下で 1.7倍）
- 価格 tier の段数（D §4.5 step6 の price ladder ratio。「上位 plan を作らないこと」が個人開発 SaaS の典型的失敗）

なお A §2.4 の母集団は mobile subscription app であり B2B web SaaS ではない点も、A の記載通り併記してください。

### #31 C の bias 補正手法が全削除され、survey が全面禁止に読めます

> - 「買いますか」と尋ねる survey（`C §2`）

## 5. 反証可能性の検査（lead 依頼 #6 への回答）

各 gate が「不合格になり得るか」を判定します。

| gate | 不合格になり得るか | 実態 |
|---|---|---|
| Phase 0 | 形式上は可能 | **ほぼ必ず通過**。「過去2年で自作した script があり、同僚も同じ物を作っていた」に該当しない software engineer は稀。定義も自己申告（#6） |
| Phase 1 | 形式上は可能 | **ほぼ必ず通過**。Phase 0 の選定基準と重複しており、query 集合は自作報告を釣り上げる設計、探索の停止条件は「見つかったら」（#14） |
| Phase 2 | 判定不能 | 参照先が存在せず、WordPress 外の入口では評価できない。**通過も不合格も定義されていない**（#5） |
| Phase 3（6件） | **可能** | 本当に投資している人が居なければ落ちます。ただし統計的根拠は無い（#16） |
| Phase 3（12件） | **可能**。ただし実行不能 | 12件が最も厳しい gate ですが、接触経路が手順書に無いため、**gate に到達する前に手順が停止**します（#4）。到達しても「同じ trigger」の粒度を読者が決めるため、緩められます |
| Phase 4（GSC） | 形式上は可能 | **測っているものが違う**。impression 0 は index 状態・順位・匿名化・channel 取り違えの論理和（#1） |
| Phase 4（金銭） | 判定不能 | **空欄**（#2） |

**要約: 5つの gate のうち、実質的に仮説を反証しうるのは Phase 3 の2つだけです。** そのうち12件 gate は実行手段が書かれておらず、6件 gate は統計的根拠を欠きます。他の3つは、ほぼ必ず通過するか、判定不能か、別のものを測っています。

lead の指摘（Phase 0 で決まっているなら後続は確認作業に過ぎないのではないか）は、部分的に当たっています。正確には次の構図です。

- Phase 0〜1 は **同じ命題**（自分と同種の人が同じ困りごとを持っている）を、自分の記憶と public な投稿という2つの source で確認しているだけです。source は違いますが、命題が同じなので反証機会が増えていません。
- 本来 Phase 1〜2 が追加すべき情報は「**既存解がなぜ満たしていないか**」（B §3.2 の DL/install 比・support 未解決率・更新停滞）ですが、それを測る gate は Phase 2 にあり、そこが判定不能です（#5）。
- 結果として、**Phase 0 で決めた領域を最初に本気で疑うのは Phase 3（第3〜6週）** になります。それまでの3週間・21時間は、確証を積む工程になっています。

## 6. 総合判定: この手順書は現状で使えるか

**使えません。** 理由は3点です。

**第一に、12週を投じても着手可否が決まりません。** 終端の2つの gate のうち、GSC gate は需要ではなく index 状態を測っており（#1）、金銭 gate は空欄です（#2）。しかも stock 型 business の成否を決める継続課金（2ヶ月目の決済）が判定点から消えています（#3）。読者は12週の末に「初回決済が何件かあった / 無かった」という、C が明示的に落とし穴として列挙した情報だけを手にします。

**第二に、pipeline が第3週で物理的に停止します。** Phase 3 の interview 12件を得る手段が書かれておらず、C が Phase 1 に配置していた獲得工数8時間が削除されています（#4）。停止の原因は仮説の反証ではなく手順の欠落なので、読者は「この領域は駄目だった」と誤って結論します。設計上の欠陥が仮説の失敗に化けるのが最悪の形です。

**第三に、手順書が自分の規律を守っていません。** 原則7（原典に当たる）に反する数字が少なくとも4件（#10 標本17倍、#11 算術不一致、#21 別指標の転用、#23 版の混成）、§8 の禁止事項に自ら違反する手順が2件（#17 事後 segment、#20 生存者のみの測定）、文書内で二通りある gate が1件（#15）、自表と矛盾する運用規則が1件（#12）、元documentに無い数値が1件（#13）あります。読者に「数字を見たら標本・期間・分母を問え」と指示する文書が、自分の数字にそれを適用していません。
