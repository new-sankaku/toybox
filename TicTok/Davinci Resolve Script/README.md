# DaVinci Resolve 用スクリプト

## 装飾を試すだけなら2つ

1. **`装飾プリセットを選ぶ.html`** をブラウザで開いて、気に入った装飾の札を押す
2. Resolve で **`Resolveで動かす/実務_字幕を装飾する.py`** を実行する（`Workspace > Console > Py3` に貼るだけ）

貼るだけで走る。選ぶところは無い。字幕が Text+ になり、装飾が当たる。
もう一度貼ると、目印を読み直して装飾を当て直す。
毎回貼るのが面倒になったら `手元で動かす/導入_Resolveのメニューへ登録.py` を1回動かすと
`Workspace > Scripts` から呼べる。

## 正しく出ることを確かめる

**`Resolveで動かす/テスト_ぜんぶ確かめる.py` を Console へ貼る。** これ1本で全部。

1件ごとに、Text+ へ**書いた値をその場で読み返して比べる**。
食い違ったら Input 名・書いた値・読めた値を出し、そのクリップを赤にする。

読み返しを書き込みの直後にやるのは、**Text+ が要素を切ると、その要素の値を
読めなくなる**ため。全部書いてからまとめて読むと、切ってある要素が全部
「読めない」になって、正しいのか壊れているのか分からなくなる。

在るかどうかを `GetInputList` で訊いてはいけない。`comp.Lock()` の間は一覧が
古いままで、**書けている値まで「無い」と答える**。

装飾の中身は `装飾データ.json` から読むので、件数が増えても script は太らない。

**Media Pool の素材から尺を指定して置く経路**（本番だけが通っていた道）も見るようにした。
素材の作り方・置いた尺が頼んだとおりか・置いたものに Text+ が在るかまで確かめる。

**テストが見ていないもの**（本番だけが通る道）:

* 行頭の目印から装飾を導く処理（`split_marker` / `rule_hits` / `resolve_style`）
* `Comments` の控えから装飾を戻す処理（`marked_rules` / `marks_for`）

装飾を足したり直したりしたら、生成をやり直す。

**順番が決まっている。** 元表から画面と Resolve 側の script を作る。

    python 手元で動かす/道具_装飾プリセットを生成.py     元表から画面・装飾データ・Resolve側を作る
    python 手元で動かす/導入_Resolveのメニューへ登録.py     Resolve へ入れ直す

`Resolveで動かす/道具_Text+の実寸と書体の字幅を測ってサンプルデータを変更する.py` で換算係数を直したときも、上から回し直す。

## ファイルの並び

**フォルダは「どこで動かすか」、名前の頭は「何のためか」。**

**頭を見れば、それが何を書き替えるか分かる。**

| 頭 | 何を書き替えるか | 中身 |
| --- | --- | --- |
| `実務_` | **作品** | タイムライン・動画。ふだんの作業 |
| `道具_` | **この道具の中身** | 見本帳・装飾データ・Resolve側script・見本画像・換算係数 |
| `導入_` | **PC と Resolve** | 書体を入れる・メニューに登録する。初回だけ |
| `テスト_` | **何も** | 確かめて結果を書き出すだけ |

測るものが `道具_` なのは、測った値を生成側へ**書き戻して**見本帳まで作り直すため。
作品には触らないので実務ではなく、書き替えるので `テスト_` でもない。

| ファイル | 何をするもの |
| --- | --- |
| `Resolveで動かす/実務_字幕を装飾する.py` | 字幕を Text+ にして装飾を当てる。ふだん使う本体 |
| `Resolveで動かす/実務_字幕の区切りで動画を区切る.py` | 字幕の切れ目でクリップを分ける |
| `Resolveで動かす/道具_Text+の実寸と書体の字幅を測ってサンプルデータを変更する.py` | 調べる・測る・書き戻す・見本帳まで作り直す |
| `Resolveで動かす/テスト_ぜんぶ確かめる.py` | **確かめはこれ1本。** API・装飾の全件・下調べ |

`実務_字幕を装飾する.py` は `Workspace > Scripts` から呼ぶ。ほかは Console へ貼る。

**`手元で動かす/` に Resolve の API を呼ぶものは1つも無い。** 逆も同じ。
各 file の1行目が貼り先を名乗っている。

残りは手元で動かすもの。

| ファイル | 何をするもの | 置き場 |
| --- | --- | --- |
| `装飾プリセットを選ぶ.html` | 装飾を選ぶ。実物大で見られる | ブラウザで開く |
| `手元で動かす/導入_Resolveのメニューへ登録.py` | 本体を `Workspace > Scripts` に出す。1回だけ | 手元 |
| `装飾データ.json` | 装飾の実体。Resolve 側はこれを読む | 生成物 |
| `手元で動かす/道具_装飾プリセットを生成.py` | 元表。画面・装飾データ・Resolve側を作り直す | 手元 |
| `手元で動かす/導入_書体を入れる.py` | 同梱の書体を入れる。初回だけ | 手元 |
| `手元で動かす/道具_見本を切り出す.py` | 書き出した見本を割り当てごとの画像に切る | 手元 |
| `doc/わかったこと.md` | 実機で確かめたことの置き場 | 読む |
| `doc/測定/` `doc/テスト結果.txt` | 測った値と確かめた結果。走らせるたびに上書き | 読む |

## 確かめ方

`Resolveで動かす/テスト_ぜんぶ確かめる.py` を Console に貼るだけ。結果は
`doc/テスト結果.txt` と `doc/テスト結果.json` に残るので、Console からcopyしなくてよい。

**毎回やらなくてよい。** 装飾データ.json の1件ごとに中身の印が入っていて、
前に通っていて印が同じ件は飛ばす。試した数と飛ばした数は必ず出る。
`手元で動かす/道具_装飾プリセットを生成.py` を動かすと、いまの装飾が確かめ済みかどうかを名乗る。

    確かめ: 139件すべて確かめ済み。Resolve で流し直す必要はありません。
    確かめ: 139件中 3件が未確認（純金 白金 古銅）。…を実行してください。

全部やり直したいときは、script の頭の `FORCE = 0` を `1` にする。

## 字幕の装飾を変える

Resolve の字幕トラックは、フォント・縁・影を Scripting API から一切変更できない。
`TimelineItem.SetProperty` が受け付けるのは Pan/Tilt/Zoom などの変形だけで、装飾のキーは存在しない
（`C:\ProgramData\Blackmagic Design\DaVinci Resolve\Support\Developer\Scripting\README.txt`）。
装飾をスクリプトで扱えるのは Text+（Fusion）だけなので、字幕を Text+ に置き換えてから装飾する。

### 装飾プリセットを選ぶ.html

ブラウザで開いて見た目を選び、画面下のスクリプトをコピーして Console に貼る。
**割り当ての札を押すと、その目印（`[筆文字]` など）がクリップボードに入る。**
字幕の行頭にそのまま貼れる。
左が **装飾の割り当て（231件）**、右が **プレビュー**。
細かい値を触るときだけ右上の「調整」を押すと、一番右に調整欄が出る。
一覧は長いので、プレビューと調整はスクロールに追従して画面に貼り付く。
プレビューはブラウザ描画による目安なので、最終確認は Resolve 側で行う。

### 実在の題字から起こした90種

**1件＝実在の1本**。ジャンルの雰囲気ではなく、特定のタイトルの題字を見て組んである。
色は印象で決めず、**ロゴ画像を手元に落として画素を数えた値**から採り、そこから
字幕として読める側へ寄せている（暗すぎる塗りには明るい縁を足す、彩度を少し落とす）。
6つの系統（RPG・ホラー・格闘/アクション・任天堂系/パズル・FPS/SF・インディー/レトロ）で
分けて調べ、全90件で書体の実在・縁の上限・幅・白背景と黒背景の可読性を機械で確かめてある。

**装飾の名前は見た目を表す日本語**にしてあり、題名は使っていない。代わりに
`装飾プリセットを選ぶ.html` の札と `装飾データ.json` の `origin` に**もとにしたもの**を
残してある（札には題名だけ、年と機種は tooltip に出る）。名前だけでは何を見て作ったのかが
辿れず、色や縁を直すときに何へ寄せるのかが分からなくなるため。

`origin` はゲームの題字に限らない。**かわいい・ポップ の `[甲羅うら]` `[若緑]` `[甲羅座布団]`
の3件は絵文字の🐢**から起こしてあり、色は🐢を描いて画素を数えた3色
（`#008060` 甲羅 62.9%／`#c0e030` 手足と頭 17.5%／`#00d060` 甲羅の筋 9.6%）だけで組んである。
甲羅の六角模様は Text+ では出せないので、亀らしさは配色と丸みで作っている。

**この90件だけは分類「ゲームの題字」にまとめてある。** 最初は気分の16分類へ配ったが、
一覧から「どれがゲームの題字か」を辿れなくなり、1つの分類として独立させた。
先にあった24件（`[黒金]` `[朱印]` ほか）は気分の分類のままなので、そちらは混ざらない。

* ストライプ・チェック・水玉などの模様 … 画像を差す `Type{n}=1`（Image）が要る
* ハート・リボン・吹き出しなどの飾り … Text+ ではなく別のツールの仕事

### 見た目の作り

Resolve 同梱の Fusion テンプレート（`Fusion/Templates/Templates.drfx` 内の165本、
うち Blackmagic 自身の字幕テンプレート17本）から、実在する Input 名と実値を取り出して合わせてある。

Text+ は装飾の層（要素）を8つ持ち、**番号が小さいほど手前**に描かれる。ここでは6つ使う。

| 要素 | 役割 | 主な Input |
| --- | --- | --- |
| 1 | 塗り | `ElementShape1=0` `Red1` `Green1` `Blue1` `Alpha1` |
| 2 | 縁取り | `ElementShape2=1` `Thickness2` `JoinStyle2` `OutsideOnly2` |
| 3 | 二重縁取り | 要素2より太くして2色の縁にする |
| 4 | **グロー（ぼかした縁）** | `Thickness4` `SoftnessX4` `SoftnessY4` `SoftnessGlow4` `Opacity4` |
| 5 | 影（落とし影） | `ElementShape5=0` `Offset5` `SoftnessX5` `Opacity5` |
| 6 | 帯（座布団） | `ElementShape6=2` `Level6` `ExtendHorizontal6` `ExtendVertical6` `Round6` |

`ElementShape` は 0=文字の塗り、1=文字の縁、2=帯の塗り、3=帯の縁。
`Level`（帯のみ）は 0=全体 1=行ごと 2=単語ごと 3=文字ごと。行ごとにすると帯が行の長さに合う。
`Center` と `Offset5` は Point なので、スクリプト側は `[x, y]` を Fusion の table へ直してから渡す。

既定の見た目は **白文字＋黒の細い縁＋ずらさずぼかした暗いグロー**にしてある。
無音視聴の縦動画で背景がごちゃつくため、縁だけでは沈む。距離0・大きめのぼかしの層を
文字の周りに敷くと、四角い帯を出さずに文字だけが浮く。濃い落とし影は古く見えるので既定では切ってある。

実値の目安:

| 項目 | Input | 値 |
| --- | --- | --- |
| サイズ | `Size` | 画面幅に対する比。0.065 ≒ 1080幅で70px（縦動画の定番は55〜75px相当） |
| 縁の太さ | `Thickness2` | 文字サイズに対する比。**0.03 が Resolve 標準**、0.075〜0.1 で極太 |
| 角 | `JoinStyle2` | 0=Bevel 1=Round 2=Miter **3=Miter Clip**。Blackmagic の字幕は3 |
| 字間 / 行間 | `CharacterSpacing` `LineSpacing` | 実テンプレートは 0.97〜1.6 / 0.60〜1.04 |
| 帯の余白 / 角丸 | `ExtendHorizontal6` `Round6` | 0.15 が標準、`Round6=1` で完全な丸（ピル型） |

グラデーション（`Type{n}=2` と `ShadingGradient{n}`）は Gradient 型の値が必要で
Console から素直に渡せないため入れていない。3D傾き（`AngleX` `AngleY`）や
文字ごとの回転（`CharacterRotation`）も Text+ は持っている。

### 位置

上下左右の位置は Text+ の `Center`（0.0〜1.0、0が下端）で指定する。
クリップの Tilt（px）は使わないので、タイムラインの解像度が変わっても位置は崩れない。

### 画面の絵と Resolve の絵は同じではない

画面の描画は DOM（同じ本文の span を5枚重ね、`-webkit-text-stroke` と `filter: blur()`）で、
Fusion のレンダーではない。**大きさを合わせても形は揃わない。**

* `-webkit-text-stroke` は線の角の処理を選べない（Fusion の `JoinStyle` は Sharp/Rounded/Beveled）
* CSS の縁は中心線。`paint-order` と2倍幅で「外側のみ」を模しているが、細い画では内側の食い込み方が違う
* `filter: blur()` は着色済みの層をぼかす。Fusion は要素ごとに `Opacity` と合成順が別。
  `SoftnessGlow` は `brightness()` での代用で別物
* Fusion はプロジェクトの色空間で合成する。ブラウザは sRGB 固定なので、暗いグローの濃さが変わる
* 字間は Fusion が送り幅の倍率、CSS は加算

**割り当ての見本だけは、Resolve に描かせた実物に差し替えられる**（実務_字幕を装飾する.py の「見本を書き出す」）。

### 縁の太さは書体が決める（漢字の内側が潰れる）

縁取りは字の輪郭から**外へ**伸びる。漢字の内側の隙間（無の点の間、緊の下など）も
輪郭に囲まれているので同じだけ埋まり、隙間より太い縁を引くと内側が塗り潰れて黒い塊になる。
Resolve でも画面でも同じように起きる、字形そのものの制約。

書体ごとに「隙間に入る最大の円の半径」を測ってある。文字の実寸を200pxに揃え、
無理本番緊急速報展開驚 の11字の中央値を取ったもの。

| 書体 | 隙間の半径 | 引ける縁の太さ |

### プレビューの精度

画面のプレビューの、Text+ の値をpxへ直す係数は
`手元で動かす/道具_装飾プリセットを生成.py` の `PREVIEW` にあり、初期値はマニュアルの記述からの推定。
**推定のままだと文字の大きさ・縁の太さ・ぼかしの量が実物とずれる**（画面にも警告が出る）。

合わせるには、Resolve に測定用の画像を描かせて測る。**貼るのは1本だけ**で、
測る・書き戻す・見本帳を作り直すところまで通しでやる。手元でコマンドを打つ必要は無い。

```
Resolve の Console（Workspace > Console > Py3）で:  Resolveで動かす/道具_Text+の実寸と書体の字幅を測ってサンプルデータを変更する.py
```

書き出すのは、換算用の8枚と、書体ごとの送り幅を測る画像（書体の数＋2枚）。
測定用の Text+ はテストと同じく Fusion Title を直接タイムラインへ入れて作るので、
Media Pool に素材を用意しておく必要は無い。測定用のタイムラインは終わったら消す。

Text+ に何の値があるかを `GetInputList` で訊いてはいけない。
`comp.Lock()` の間は一覧が古いままで、**書けている帯の値まで「無い」と答える**。
在るかどうかは、書いた直後に読み返して確かめる。

係数はすべて **文字の実寸（塗りの高さ）** を基準にしている。em を基準にすると、
書体ごとの「em と実寸の比」が測定側と描画側の両方に要って堂々巡りになるため。
ブラウザ側は canvas で書体ごとの実寸比を測り、font-size を逆算している。

真値の分かっている合成画像で測定側を検証済み。文字の大きさ・縁の太さ・帯の余白は誤差0%、
角丸は+3.6%、ぼかしは+8%（しきい値から σ に戻すときの近似による）。

### 全角何文字まで入るか（はみ出しの関門）

字幕は全角 `FIT_CHARS` 文字（既定11）に切り詰めて出すが、装飾ごとに書体・大きさ・
字送りが違うので、**同じ文字数でも幅が変わる**。画面幅の `FIT_WIDTH`（既定86%）に
収まらない装飾は、`手元で動かす/道具_装飾プリセットを生成.py` が名指しで注意を出す。
`FIT_CHARS` は TicTok 側の設定（`subtitle_chars_per_line` と余白）と揃えること。

判定に使うのは `FONT_WIDTH`（書体ごとの送り幅・字幅・字高、Size 1・画面幅1 あたり）で、
**Resolve で実測した値だけ**を使う。測っていない書体は推定で埋めず、
「関門が働いていない」と名乗る。推定で答えると、はみ出すものを見逃したのか、
収まるものまで刈ったのかが分からなくなる。

見本帳では札に「◯字」、プレビューの下に「全角◯字まで入ります」が出る。
足りなければ警告色になる。

実行時に自動で縮める仕掛けは入れていない。Text+ は文字の幅をAPIで返さないので測れず、
Frame配置＋折り返しに替えると勝手に2行になって帯まで動く。

### 行頭の目印で装飾を切り替える

`BASE_PRESET` が既定の見た目で、`RULES` が目印に一致したときの上書き。
行頭の目印は本文から自動で取り除かれる。一致したruleを上から順に重ねるので
組み合わせられる（`>!` なら「相手が・驚いて」、`[筆文字]!` なら「筆文字で驚いて」）。

**話者は縁の色、感情は文字の色**を変えるので、重ねても両方残る。

目印の書き方は2通りある。

| 書き方 | 例 | 使いどころ |
| --- | --- | --- |
| 1文字の記号 | `!嘘でしょ` | 話者・感情など毎行打つもの |
| `[名前]` | `[筆文字]墨のように書く` | 見た目のプリセットなど数が多いもの |

どちらでも同じruleを呼べる（`!嘘でしょ` と `[驚き]嘘でしょ` は同じ）。
記号は打つのが速く、名前は表を見に行かずに済む。

**括弧は中身が既知の名前のときだけ目印として食べる。**
`【耳かき】眠れない夜のとなり` のような行はそのまま本文になる。
日本語入力では `[` が `「` になるため、`[]` `［］` `「」` `【】` のどれでも受ける。

記号を目印に使うのは話者・感情など20件だけにしてある。見た目のプリセットは211種あり、
記号だと足りず、`@@@@@` のような繰り返しは数え間違えるため。

| 目印 | 意味 | 例 |
| --- | --- | --- |
| `>` | 相手・ゲスト（縁を紺に） | `>それは違うでしょ` |
| `>>` | もう一人（縁を緑に） | `>>こっちも見て` |
| `!` | 驚き | `!嘘でしょ` |
| `!!` | 絶叫 | `!!無理無理無理` |
| `w` | 笑い | `wそれはずるい` |
| `ww` | 大爆笑 | `wwやめてくれ` |
| `*` | 小声 | `*これ言っていいのかな` |
| `**` | 心の声 | `**絶対勝てない` |
| `?` | 困惑 | `?どういうこと` |
| `#` | 見出し | `#ここから本番` |
| `##` | ニュース風 | `##緊急速報` |
| `###` | 煽り | `###まさかの展開` |
| `:` | リスナーのコメント | `:それ知ってる` |
| `$` | ギフト | `$バラをありがとう` |
| `=` | ナレーション | `=このあと事件が起きる` |
| `"` | 引用・回想 | `"あの時こう言った` |
| `~` | 弾む（動き） | `~うわあ` |
| `~~` | 揺れる（動き） | `~~ぐらぐらする` |
| `^` | 画面の上へ | `^ここは上に出す` |
| `_` | 画面の下へ | `_ここは下に出す` |

この20件も `[驚き]` `[相手]` `[コメント]` `[引用]` `[上]` `[下]` のように名前で書ける。

半角・全角のどちらでも効く。目印だけで本文が空になる行（`ｗｗｗ` など）は、目印として扱わずそのまま表示する。
キーワードで色を変えたい場合は `pattern` に `(配信者名|ゲーム名)` のように書く（本文に対して判定する）。
目印を増やすときは `MARKER_CHARS` にもその文字を足す。

先頭の目印は変換時に本文から取り除かれるが、効いた目印は Text+ の `Comments` に控えてある。
貼り直しても既定へ戻らないのはこの控えのため。1行だけ付け直すなら本文の行頭へ打ち直す。
全部まとめて塗り替えるなら `KEEP_MARKS = False` にして、控えを捨てると宣言してから貼る。

### 動きを付ける

動きは Text+ 素材の差し替えで表す。動きを付けた Text+ をタイムラインで作り、Media Pool へ
`Text+ 弾む` のような名前で置き、ruleの `source` にその名前を書く。
動きは **Text+ の後ろに置いた Transform** で付けること。Text+ 自身の Size や色を keyframe で
動かすと、この script が書き込む装飾とぶつかる。
使う素材が Media Pool に無い場合は、名前を挙げて停止する。

### 実務_字幕を装飾する.py

Resolve 側の処理はすべてこの1本。以前は5本に分かれていたが、
どれも同じ装飾の表を抱えていて貼り分けが手間だったのでまとめた。

**字幕をText+に置き換える**

字幕トラックの各行を、同じ位置・同じ尺の Text+ クリップに置き換える。
元タイムラインを複製してから加工するので、元の字幕はそのまま残る。

**事前準備（1度だけ）: Text+ 素材を手で Media Pool へ置く。**
Effects > Titles の Text+ をタイムラインに置いて尺を長め（60秒ほど）に伸ばし、
そのクリップを Media Pool へドラッグして名前を `Text+` にする。

Resolve の API には尺を指定して Text+ を挿入する手段が無い
（`InsertFusionTitleIntoTimeline` は再生ヘッド位置に既定尺で入るだけ）。
`AppendToTimeline` に `recordFrame`/`endFrame` を渡せば尺を合わせられるが、それには
Media Pool の素材が要る。そして **Fusion Title からは Media Pool のクリップを引けない**
（`GetMediaPoolItem()` が None。実機で確認）。だからここだけ手作業になる。

**素材尺を超える長さの字幕は配置できない**ので、足りない場合は長く伸ばした Text+ を
手で置き直す。動きを使う場合も、動きを付けた Text+ を手で置く。

`endFrame` が inclusive か exclusive かは環境で違うため、仮タイムラインで実測してから使う。

**Text+ に値を書く順番には決まりがある。** 入れたばかりの Text+ は `Enabled2` は持つが
`Thickness2` も `Red2` も持たない。要素を有効にして初めてそのパラメータが生える。
そこで、いったん全要素を有効にしてから値を書き、最後に本来の On/Off へ戻している。
書けたかどうかは `GetInput` で読み返して確かめ、書けなかった名前だけを1回報せる。

**Text+ が在るタイムラインで貼ったとき**

すでに置いた Text+ の `StyledText` を読み直し、目印を判定して装飾を書き直す。
目印を書き替えたら、もう一度貼れば当たり直る。

**行ごとに装飾を変える**なら、字幕の行頭に手で `[怪談]` と打つ
（画面の札を押すとクリップボードに入る）。設定は `MARKER` で、書き方は2つ。

| `MARKER` | 何が起きるか |
| --- | --- |
| 名前を書く（`夕暮れ`） | まだ何も選んでいない行が、まとめてその装飾になる |
| `触らない` | 目印か控えを名乗る行だけ装飾する。残りは既定のまま |

空欄では止まる。「当てないと決めた」のか「書き忘れた」のかを file から見分けられないため、
**`触らない` と言葉で書かせる**。記号の目印（`!` など）は話者・感情で別枠なので、
`MARKER` と重なって両方効く。

目印は装飾になった時点で本文から外れるので、効いた目印は Text+ の `Comments` に控える。
当てる順は **本文の行頭 → `Comments` の控え → `MARKER`**。一度選んだ行は `MARKER` を
書き替えても動かない。控えが `MARKER` より弱いと、後から `MARKER` を書いただけで
行ごとに選んだ装飾が黙って消えるため。まとめて塗り替えるときだけ `KEEP_MARKS = False` と
書く（控えを捨て、字幕トラックの行は `MARKER`、他トラックは既定に戻る）。

**当て直しは全ビデオトラックの Text+ を見る。** 字幕から作った `字幕Text+` トラックは
目印が無くても装飾するが、それ以外のトラックは**目印か控えを名乗る Text+ だけ**触る。
無関係なタイトルを既定の装飾で塗り替えないため。Video 3 に自分で置いた Text+ も、
行頭に `[ルージュ]` と打てば当たる。

以前は「置き換える / 作り直す / 切り替える / 並べる」を `ACTION` と窓で選ばせていたが、
選ぶ意味が無いので消した。前の2つは **Text+ が在るか無いかで決まる**ので script が見れば分かる。
「切り替える」は `LOOK` を書き替えて貼り直せば同じことになる。
「並べる」の見本は `装飾プリセットを選ぶ.html` で見る。

割り当ての見本を Resolve に描かせて1フレームずつ書き出す。画面の見本を

## Text+ の実物で確かめたこと

### 型が違う値は、黙って捨てられる

`Resolveで動かす/道具_Text+の実寸と書体の字幅を測ってサンプルデータを変更する.py` を走らせると、ノードが持っている
Input 名と型と現在値が `doc/測定/Input一覧.txt` に全部出る。ここで名前の取り違えが2つ見つかった。

* **Text+ に `Angle` は無い。** 字全体の回転は `AngleZ`（Layout の回転）。
  ほかに行・単語・文字ごとの `LineAngleZ` `WordAngleZ` `CharacterAngleZ` がある。
  `Angle` が在るのは `RectangleMask` `EllipseMask` `Merge` `Transform` のほう。
* **`Background` の `Type` は数字ではなく名前（FuID）。** `Solid` `Horizontal`
  `Vertical` `Corner` `Gradient` の5つ。`GradientType` も名前で `Linear`
  `Reflect` `Radial` `Square` `Angle`。Resolve 同梱の
  `Fusion/Templates/**/*.drfx` の中の `.setting` に実物が書かれている。

**型が違う値を書くと、Resolve は例外を出さずに黙って捨てる。** 読み返すと `None` になる。
テストが「書いた直後に読み返す」のはこれを捕まえるためで、実際これで見つかった。

### 書体の名乗り方

太さ900は `"Noto Sans JP"` の `Black` ではなく `"Noto Sans JP Black"` の `Regular`。
Resolve が引けるのは後者なので、同じ太さなら古い名乗り方（Regular / Bold）の組を選ぶ。

### Text+ の文字組みで何ができるか

`DaVinci Resolve/Plugins/text.plugin` から Text+ 本体の制御名を取り出して確かめた結果。

**列挙値は plugin の文字列表の逆順に並んでいる。** `ElementShape`（Text Fill / Text Outline /
Border Fill / Border Outline）と `Level`（Text / Line / Word / Character）の2つで裏取りした。
どちらも既に分かっている並びと一致したので、他の列挙値もこの読み方で確定できる。

これで1つ誤りが見つかった。**`JoinStyle` は 0=Bevel 1=Round 2=Miter 3=Miter Clip** で、
これまで「角を丸める」に 3 を書いていたが、3 は Miter Clip（角を落とす）だった。
丸めるは 1 に直した（角ばらせる側は Blackmagic の字幕と同じ 3 のまま）。

| やりたいこと | できるか | 使う Input |
| --- | --- | --- |
| 縦書き | **できる** | `Direction` = 3（0=自動 1=横 2=逆向き横 3=縦 4=逆向き縦） |
| 行の進む向き | できる | `LineDirection` = Top Down / Bottom Up |
| 右から左へ読む | できる | `ReadingDirection` = Left to Right / Right to Left |
| 一文の中で装飾を変える | **できる（手作業）** | `CharacterLevelStyling`（型は StyledText） |
| 下線・打ち消し線 | できる | `Underline` `Strikeout` `UnderlinePosition` |
| 等幅に揃える | できる | `ForceMonospaced` |
| 文字ごとの位置・詰め | できる（手作業） | `ManualFontKerning` `ManualFontKerningPlacement` |
| 合字・異体字 | できる | `UseLigatures` `StylisticSet` |
| **ルビ（振り仮名）** | **無い** | 制御そのものが存在しない |
| 圏点（傍点） | 無い | 同上 |

縦書きは `[縦書き]` `[縦明朝]` として割り当てに入れてある。画面のプレビューも縦に組む。
行の位置は `Center` で決めるので、右端に寄せて上から始まるようにしてある。
**行が進む向き（右→左か左→右か）は Resolve で確かめること。** 調整欄の「行の向き」で切り替わる。

**ルビと圏点は Text+ に無い。** 別の Text+ を小さくして本文の脇に置くしかない。
縦書きなら本文の右、横書きなら本文の上。位置は手で合わせる。

**一文の中で装飾を変えるのは、スクリプトからは書けない。**
`CharacterLevelStyling` の値は `StyledText` という Fusion 独自の型で、中身は
`{ 100, 0, 0, String = "Open Sans" }` のような番号の配列（同梱テンプレート
Letterbox Text.setting などで確認）。Console から組み立てられないため、
Inspector で文字を選んで設定する手作業になる。1行を複数の Text+ に割る方が確実。

**丸囲みは Text+ の機能ではない。** Fusion の Ellipse などの図形で、囲みたい語に
合わせて置く。Text+ は「この文字が画面のどこに出るか」を返さないので、
一部分だけを自動で囲むことはできない。語ごとに Text+ を分ければ位置が分かる。
