# 字幕の枠の設計

依頼された「画面幅の73%・下から28%の位置に2行」という枠を、Text+ の Input へ落とすための設計。
まだ実装していない。決めるべきことと、実測で確かめるべきことを先に出す。

## 1. 依頼された仕様

| 項目 | 値 |
|---|---|
| テキスト枠幅 | 792px（左余白 50px / 右余白 238px。右はアイコン列を避けて広く空ける） |
| 字幕ブロックの下辺 | 画面下端から 540px |
| 文字 | 90px |
| 行間 | 1.35（1行 約121px、2行 約243px。上辺は画面上から 1137px） |
| 縁取り | 黒 約22px |
| 揃え | 左 |

## 2. いまの持ち方

枠という概念が無い。

- 位置は `Center`（`cx`=0.500 / `cy`=0.300。`cy` は 0 が下端）だけで決めている
- 揃えは中央（`HorizontalJustificationNew`=3）
- 幅は `Wrap`=1 に任せ、生成時の関門で抑えているだけ
  - `FIT_WIDTH`=0.86（画面幅の86%を超える装飾を作らせない）
  - `WRAP_MAX`=20（読み手が目で追える1行の上限）
  - `FIT_CHARS`=11（1枚に載る全角の文字数。TicTok の `subtitle_chars_per_line` と揃える約束）
- 大きさは装飾ごとに手で決めた `size`（0.056〜0.086）

つまり「枠に入れる」のではなく「はみ出させない」設計になっている。依頼仕様は前者なので、
持ち方そのものを変えることになる。

## 3. 使う Input

`doc/測定/Input一覧.txt` に実在を確認済み。値の意味は未確認。

| 目的 | Input | 現在値 |
|---|---|---|
| 枠にする | `LayoutType` | 0.0 |
| 枠の幅 | `LayoutWidth` | 0.5 |
| 枠の高さ | `LayoutHeight` | 0.5 |
| 枠の中心 | `Center` | {0.5, 0.5} |
| 横の揃え | `HorizontalJustificationNew` | 3.0 |
| 縦の揃え | `VerticalJustificationNew` | 3.0 |
| 行送り | `LineSpacing` | 0.9 |

### 実測で決めること（Resolve で1回流せば全部決まる）

1. `LayoutType` の 1 が Frame（枠）か
2. `LayoutWidth` の 1.0 が画面幅なのか高さなのか（縦画面では 1.78倍ずれる）
3. `HorizontalJustificationNew` の「左」の値（旧 Input の `HorizontalJustificationLeft` も残っている）
4. `Center` が枠の中心を指すのか、行の基準点を指すのか
5. `LineSpacing` 1.0 が何 px か（換算表に無い唯一の量）

`道具_Text+の実寸と書体の字幅を測ってサンプルデータを変更する.py` に case を足せば、
既存の測り方（値を書く → 静止画を書き出す → 画素を数える）のまま測れる。

## 4. 換算

`doc/測定/換算と送り幅.txt` の実測係数から。画面は 1080x1920。

```
塗りの高さ px = 字高比 × Size × 1080
全角の送り px = 送り比 × Size × 1080 × tracking
縁の太さ  px = Thickness × 0.9690 × 塗りの高さ px
```

依頼値をこの式で戻すと：

| 依頼 | Text+ の値 |
|---|---|
| 枠幅 792px | `LayoutWidth` = 0.7333（単位が画面幅なら） |
| 左50 / 右238 | 枠の中心 x = 446/1080 → `cx` = **0.4130** |
| 下端から540px・2行243px | 枠の中心 y = 661.5/1920 → `cy` = **0.3445** |
| 文字 90px | `Size` は書体ごとに別の値（下表） |
| 行間 1.35 | `LineSpacing` は未実測のため出せない |
| 縁 22px | `Thickness` ≈ 0.30 → **成立しない**（§5） |

### 「文字90px」は書体ごとに違う Size になる

送り比が書体で 0.5481〜0.8000 とばらつくため、同じ 90px を出す Size が揃わない。

| 定番 | 送り比 | tracking | Size（90px 送り） | 塗りの高さ | いまの Size |
|---|---|---|---|---|---|
| 標準 | 0.6667 | 0.98 | 0.1276 | 74.0px | 0.065 |
| 極太 | 0.8000 | 1.00 | 0.1042 | 72.9px | 0.065 |
| ドン | 0.6667 | 0.94 | 0.1330 | 77.1px | 0.078 |

いまは「装飾ごとに手で決めた `size`」を持っているが、この仕様では
**狙いの送り px を持ち、生成時に書体ごとの送り比から Size を逆算する**形へ変えるのが筋。
そうしないと 138件ぶんの Size を書体を替えるたびに手で直すことになる。

## 5. 成立しない項目：縁 22px

縁は字の輪郭から外へ伸びるので、漢字の内側の隙間も同じだけ埋まる。
`FONT_COUNTER`（書体ごとに測った、隙間に入る円の半径）から、塗り潰れない縁の上限は：

```
縁の上限 px = 半径 × COUNTER_ALLOW(1.3) × 塗りの高さ px / 200
```

| 書体 | 半径 | 塗りの高さ | 縁の上限 |
|---|---|---|---|
| Noto Sans JP Black（ドン） | 6 | 77.1px | **3.0px** |
| Noto Sans JP Bold（標準） | 9 | 74.0px | **4.3px** |
| BIZ UDPGothic Bold（極太） | 11 | 72.9px | **5.2px** |
| Noto Sans JP Regular | 13 | 74px | 6.3px |
| Rampart One（表で最も内側が広い） | 19.4 | 75px | 9.5px |

**22px は表の40書体すべてで不可能**（最も余裕のある Rampart One でも 9.5px）。
太い字ほど内側が詰まっているので、太い書体を選ぶほど上限は下がる。

選べる道は3つ。どれも user の判断が要る。

- **(a) 縁は上限まで、太さは別の要素で作る** — にじみ（`glow`）か帯（`band`）で黒い面積を足す。
  にじみは裾が柔らかいので内側が灰色になるだけで、輪郭は残る。
- **(b) 関門を緩める** — `COUNTER_ALLOW`=1.3 を上げる。漢字の内側が潰れるのを承知で、
  TikTok でよく見る「潰れた極太」に寄せる。どこまで潰してよいかを数値で決める必要がある。
- **(c) 22px を実寸の上限へ直す** — 依頼元の見積り違いとして扱う。
  「プレビューの6px相当」という但し書きがあるので、プレビューの倍率の取り違えの可能性がある。

## 6. 影響範囲

| 対象 | 内容 |
|---|---|
| `LOOKS` 118件 | `size` の持ち方を「送り px」へ変える。全件書き直し |
| `RULES` 138件 | `chars` が再計算される（枠 792px・送り 90px なら 1行 8字） |
| `FIT_WIDTH` 0.86 | 枠が入れば役目が変わる。枠幅 0.7333 に置き換え |
| `WRAP_MAX` 20 | 枠に入る字数（8）が先に効くので、上限としては働かなくなる |
| `FIT_CHARS` 11 | TicTok の `subtitle_chars_per_line` と揃える約束（README:360）。両方直す |
| `BASE_PRESET` | `LayoutType` / `LayoutWidth` / `LayoutHeight` / 揃えの key を追加 |
| `SWATCH_CASES` 139件 | 全件が未確認になる。Resolve で `テスト_ぜんぶ確かめる.py` を流し直す |
| 位置の目印 6件 | `[^]` `[_]` など `cy` を上書きする割り当ては、枠の中心基準へ読み替える |

## 7. 手順

1. §3 の未確認5点を測る case を `道具_Text+の実寸と書体の字幅を測ってサンプルデータを変更する.py`
   へ足し、Resolve で1回流す
2. `換算と送り幅.txt` に `LineSpacing` の換算を追加する
3. §5 の (a)(b)(c) を決める
4. 生成側に枠（`cx` / `cy` / `LayoutWidth` / 揃え）を持たせ、`size` を送り px からの逆算に変える
5. 138件を再生成し、関門の警告を潰す
6. `テスト_ぜんぶ確かめる.py` で 139件を確かめ直す
