## 書ける値・書けない値

**要素ごとに書ける**（読み返して確認済み）

`Type`（0=Solid 1=Image 2=Gradient）/ `ImageSource` / `Rotation` / `AngleX` `AngleY` `AngleZ` /
`SizeX` `SizeY` / `ShearX` `ShearY` / `Offset`（3成分のPoint）/ `OffsetZ` / `Pivot` /
`Level` / `ColorFile` / `ColorImage` / `ShadingGradient` / `ShadingMapping*` / `Name`。
全体には `SortShadingElements`。

**無い**（plugin の文字列にはあるが、Input としては存在しない）

`MergeOperator` / `ElementPosition` / `Extrusion`。代わりに `Position` と `PriorityBack` が在る。

**Text+ に `Angle` は無い。** 文字全体の回転は `AngleZ`。
`Angle` を持つのは RectangleMask / EllipseMask / Merge / Transform。

**Background の `Type` は数値ではなく文字列（FuID）。**
`Solid` / `Horizontal` / `Vertical` / `Corner` / `Gradient`。
`GradientType` は `Linear` / `Reflect` / `Radial` / `Square` / `Angle`。
同梱の `Fusion/Templates/**/*.drfx` の `.setting` から拾った。

**型が違う値は、例外も出さずに捨てられる。** 読み返すと `None` が返る。
「書いてすぐ読み返す」以外に気づく方法が無い。

## グラデーション

* `tool.SetInput("ShadingGradient1", {位置: {1:r, 2:g, 3:b, 4:a}})` で入る（絵で確認）
* `{"Colors": ...}` の形で渡すと**画面が真っ黒**になる
* 停止点は4つまで確認。`ShadingMappingAngle` で回る。位置 0.0 は**下**
* 読み返しは `PyRemoteObject` で、書いた値と比べられない。**入ったかどうかしか確かめられない**
* preset には**リストのリスト** `[[位置, r, g, b, a], ...]` で持つ。
  JSON にすると辞書の数値キーが文字列に化けるため。Fusion の辞書に組むのは書き込む直前

**画像・テクスチャは出ない。** `Type=1` + `ColorFile` は、書き込みは通るのに
出来上がった絵が単色のときと1バイトも違わなかった。金属や箔は**グラデーションの
色の置き方**で出すしかない。

## API の落とし穴

* **`GetInputList` は `comp.Lock()` の間、更新されない。**
  要素を有効にした直後に一覧を取ると、**書けている帯の値まで「無い」と答える**。
  在るかどうかは、書いた直後に読み返して確かめること
* **字幕 clip の本文は書き替えられない。** `TimelineItem.SetName()` は API 一覧に在るが、
  字幕 track の行に書くと **戻り値 False・書いた値は残らない**（下の測定を見ること）。
  書けるのは Text+ の `StyledText` だけなので、行頭の目印は Text+ に付ける
* `ExportCurrentFrameAsStill` は Project の関数。Timeline には無い
* 現在のタイムラインは削除できない。消す前に別のタイムラインへ移る
* 測定用タイムラインだけ大きさを変えられる（`SetSetting("useCustomSettings", "1")`）。
  プロジェクトの設定に触らずに済む

## 大きさと字送り

* **全角1文字の送り幅は、書体ファイル上はどれもちょうど 1em**（41書体で確認）。
  ただし Resolve が実際に描く大きさは書体ごとに違う（下の実測を見ること）
* **字送り（CharacterSpacing）は送り幅を掛けない。足す。**
  `送り幅 = 素の送り幅 + (字送り - 1.0) × Size × 画面幅`。
  実測: 字送り1.3 で 64.0px → 92.8px。差の 28.8px は `0.3 × Size × 画面幅` ちょうど。
  掛け算だと思っていると、字面の狭い書体ほど最大45%広く見積もる
* **`Round` 1.0 は「完全に丸める」**（半径＝短い辺の半分）。
  「半径 = 係数 × 文字の実寸」という比例の式では表せない

## 縁の太さの上限

縁は字の輪郭から外へ伸びるので、漢字の内側の隙間も同じだけ埋まる。
隙間に入る円の半径より太い縁を引くと内側が潰れる。

`edgeW × edgeScale` と `edge2W` の両方が
`FONT_COUNTER[書体|スタイル] × 1.3 ÷ (200 × thickToPx)` 以下でなければならない。

**二重縁は内側の縁の外に描かれる。** `edge2W` が `edgeW` 以下だと1本も見えない。

## 2026-08-17 Text+ の尺は元の尺に縛られない（Resolve）

Media Pool に置いた Text+（元の尺120フレーム）を、`AppendToTimeline` で尺を変えて置いた。

| 頼んだ尺 | 置けた尺 |
| --- | --- |
| 30フレーム | 30フレーム |
| 600フレーム | **600フレーム** |

**元の尺より長くも置ける。** Text+ はジェネレータで、動画ファイルのように素材の長さで
頭打ちにならない。よって「素材を長く伸ばしてから Media Pool へ入れる」は要らない。
公開ツールが1フレームのテンプレートで足りているのはこのため。

* `endFrame` はこの環境では **exclusive**（`startFrame=0, endFrame=30` で30フレーム）。
  ここは当初 inclusive と書いていたが、読み違いだった。実行ログ.txt の
  `Text+ 'Text+': endFrame は exclusive` が実測で、`endFrame=9` を頼んで9フレーム置かれている。
  **どちらか分からないまま既定を決めて置かないこと。** 1つ短く置くと切れ目ごとに
  隙間（黒コマ）が残り、しかも黙って起きる（01_実務_字幕の区切りで動画を区切る.py で実際に起きた）
* `InsertFusionTitleIntoTimeline` で入る既定尺は **120フレーム**（24fps で5秒）
* 尺の関門（字幕が素材より長いと止める）は誤りだったので外した。
  代わりに、置いたあとで1本ずつ「頼んだ尺になっているか」を見る

## 2026-08-17 素材とタイムラインのフレームレートが違うと、頼んだ本数と尺が一致しない

`AppendToTimeline` の `startFrame` / `endFrame` はソースのフレーム番号、置かれた尺は
タイムラインのフレーム数。1フレームの長さが違うと、この2つは一致しない。

実機（素材 25fps / タイムライン 24fps、比 0.96）で測った値。

| 頼んだ本数 | 置かれた尺 |
| --- | --- |
| 10本（`endFrame=9`） | 8フレーム |
| 110本（`endFrame=109`） | 104フレーム |

exclusive（9本と109本）で端数を**切り捨て**ると `floor(9×0.96)=8`、`floor(109×0.96)=104` で
両方合う。inclusive でも四捨五入でも合わない。

* **比は実測の差から出さない。** 2点の差から割り出すと丸め誤差が乗り、25/24 を 1.05 と
  読んで長い区間ほどずれる。`GetClipProperty("FPS")` と `timelineFrameRate` で割る
* **1つ置いて数えるだけでは仕様を判定できない。** 比が1でないと inclusive/exclusive と
  尺の縮みが混ざる。仮説ごとに答えが分かれる長さを選んで置く
* **測定用タイムラインは project 設定で作られる**ので、作業中のタイムラインと
  フレームレートが違うことがある。測るときの比と本番の比は別に持つ
* **タイムラインが素材より細かい（比 > 1）と、狙った尺を作れない。** ソース1本が
  1フレームより長くなり、尺が飛び飛びになる。24fps 素材を 29.97fps タイムラインへ置くと
  40フレームちょうどが作れない

## 2026-08-17 1行に載る文字数は装飾ごとに違う

字幕トラックは Resolve が勝手に折り返すが、**Text+ は折り返さない**。字幕をそのまま
Text+ に移すと1行になって画面外へ出る。折り返しは script が入れる。

何文字で折り返すかは装飾ごとに違う。書体・大きさ・字送り・縁・帯で幅が変わるため、
実測値から出すと **10〜32文字**（3.2倍の開き）。1つの数字を全部に当ててはいけない。

* 生成器が装飾ごとに `chars`（1行に載る全角の文字数）を出して `装飾データ.json` に持たせる
* Resolve 側はその値で折り返す。重ねたときは**いちばん狭いもの**に合わせる
* 実測が無い書体（縦書きなど）は `chars` が None。字数で切らない
* 版は 2 に上げた（`chars` が入ったため）

狭い順: 絶叫 10 / 煽り 10 / 大爆笑 11 / 見出し 11。
広い順: おどおど 32 / コメント 32 / 額縁 27 / ギフト 27。既定は 20。
