# グループ操作tab

見どころ(bookmarks)を**グループを跨いで仕分ける**場所と、**グループそのものを管理する**
場所。配信者動画画面の `グループ操作` tab (`#view-groups`)。

グループの模型(排他所属・複製の意味・positionが書き出し順であること)は変えていない。
ここが足しているのは、その模型の上で「今どこが食い違っているか」を読む口と、棚を触る口。

## なぜ別tabなのか

見どころtabは**選んだ1つのグループの中**を扱う。行き先を変える経路は3つ(行のグループ欄・
移動先select・tabへのドラッグ)あるが、どれも「今見ている1つのグループ」を起点にする。
A と B の中身を見比べながら動かすには、棚を往復して記憶で突き合わせるしかなかった。

加えて、グループの**改名・統合・削除・並べ替え**はAPIには在るのに画面から行えなかった
(メモだけが見どころtabの棚の足元にあった)。棚を触る口はこのtabにしかない。

## 画面の構成

```
[グループ一覧(棚)]  順 / 名前 / メモ / 見どころ / 尺あり / 点 / 完成尺 / 対比 / 操作
[絞り込み + 統合]   表示: 全て | 尺あり | 点 ／ 左を右へ統合
[左pane] | [右pane] 順 / 位置 / 尺 / 配信者・配信日 / メモ / 操作
```

行き先は**常にもう片方のpane**。移動先selectを別に置くと、画面の3箇所(左pane・右pane・
移動先)が同時に別のグループを名乗り、どこからどこへ動くのかを押す前に読めなくなる。

列順は突き合わせに要るもの(順・位置・尺)を左へ寄せてある。左右2つの表を並べるぶん幅が
足りず横へ流れるが、隠れるのはidentityとメモだけで、目的の列は常に見える。
操作列は右端に貼り付ける(`position: sticky`) — 流れると「見えているのに押せない行」が
できる。

左右のpaneの並びは**録画→位置**で、グループ内の書き出し順ではない。左右を突き合わせる
画面なので、同じ場面が縦に揃う並びを採る(書き出し順そのものは「順」の列が名乗る)。

## かつての「対応」欄

2026-08-15の統合まで、この画面は見どころ(bookmarks)と切り出し(cut_list)の2種別を1枚の表へ
混ぜ、「未昇格の見どころ」「見どころ無しの切り出し」を数える場所だった。表が2つに割れて
いたので、同じ場面の2つの行が同じ画面に並ばなかったためである。

実データでは切り出し21件のうち20件が元の見どころと範囲・グループ・ラベルまで一致し、
分けた理由(「グループごとにIN/OUTの詰め方が変わる」)は一度も成立しなかった。表を1つに
畳んだので、突き合わせるべき2つの行そのものが無くなり、この欄と絞り込みも一緒に消えた。
残ったのは「尺があるか(=mp4にできるか)」だけで、それは同じ行の中で読める。

## 一括操作

| 操作 | API |
| --- | --- |
| 移動 | `POST /api/bookmarks/bulk {op:move}` |
| 複製 | `POST /api/bookmarks/bulk {op:copy}` |
| 削除 | `POST /api/bookmarks/bulk {op:delete}` |

複製が在るのは、**同じ場面をグループごとに別の詰め方で持つ**ため。所属は排他(group_idを
1つ)なので、共用ではなく行ごと複製することでしか表せない。複製は書き出しの記録
(`exported_at` / `exported_path`)を写さない — あれは「この行を書き出した」という過去の
事実で、今作った複製にはまだ何も起きていない。

moveは行が移った時点で選択の意味が変わるので選択を外し、copyは元が残るので選択を保つ
(続けて別の行き先へも複製できる)。

行き先が「全て」のpaneは所属の指定にならないので、移動・複製とも押せない。理由はbuttonの
titleに出す。「未分類」は所属を外す行き先として有効。

## グループの管理

| 操作 | API | 備考 |
| --- | --- | --- |
| 改名・メモ | `PATCH /api/groups/{id}` | 空名は受け付けず、欄を元の名前へ戻す |
| 削除 | `DELETE /api/groups/{id}` | 中身は消えず未分類へ戻る(書き出し順は失う)。確認でその件数を名乗る |
| 統合 | `POST /api/groups/{id}/merge {into}` | 左の中身を全て右へ移して左を削除 |
| 並べ替え | `POST /api/groups/order {group_ids}` | 棚の表示順。**書き出し順とは別物** |

### 統合が1本のAPIである理由

移動と削除に割ると、途中で失敗したときに「中身は移ったが空のグループが残る」「一部だけ
移った」という半端な状態が画面に出る。`storage.merge_groups()` が1つのlock区間で行い、
相対順を保ったまま移動先の末尾へ付ける(`Aの並びの後ろにB`)。

### 棚のposition

`clip_groups.position`(2026-08-08追加)。既存行は作成順をそのまま採番するので、移行だけで
並びが変わることはない。新規グループは末尾へ採番する — 採番せずに置くと、並べ替え済みの
棚では新しいグループだけが「未採番=末尾」の塊へ入り、以後の並べ替えのたび位置が飛ぶ。

`POST /api/groups/order`(棚)と `POST /api/groups/{id}/order`(グループ内の見どころ)は
名前が似ているが別物。後者だけが連結・作品の書き出し順を決める。

## 棚の件数

`item_count`(全件)と `ranged_count`(尺のある件数)を分けて出し、合計尺は尺のある行だけの
和にする。件数を1つしか出さないと「3件あるのに0秒」という読めない組み合わせが出る
(点は素材にならないので合計尺に入らない)。

## 残す表示設定

- `tictok.videos.gopsLeft` / `gopsRight` … 左右のpaneが指すグループ。選択肢を後から作る
  のでbindPrefではなく起動時にstateへ直接戻す。指す先が消えていれば `refreshGroupData()`
  が未分類へ戻す(統合・削除の直後に空の表を「0件」として名乗らせない)。
- `tictok.videos.gopsFilter` … 表示の絞り込み。
- 残さないもの: 行の選択(表の中身に紐づく一時的な対象指定)。
