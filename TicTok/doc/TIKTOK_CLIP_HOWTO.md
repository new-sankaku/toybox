# TikTok切り抜き動画の伸ばし方（How-to調査レポート）

配信の切り抜き動画をTikTokへ投稿してimpression（動画がuserの画面に表示された回数）を
伸ばすための実務指針。2026年8月にweb調査（調査agent 29 + 批評agent 1 + 検証agent 3、
英語圏・日本語圏の約240 source）で作成した。煽り・釣り（clickbait: 誇大な釣り /
rage bait: 怒らせて反応を稼ぐ手法）に頼らない方法に限定している。

作る前・出す前に見る**§9 制作チェックリスト**を巻末近くに置いた。
分かりにくい用語は**§11 用語注釈**にまとめた。

## 確度ラベルの凡例

本文の主張には確度を付ける。要約だけ読んで数値を持ち帰らないこと（調査の批評工程で
「要約が本文の限定条件を落とす」ことが最大の品質riskと指摘された）。

| ラベル | 意味 |
|---|---|
| 【高】 | TikTok公式一次情報、または独立した複数系統の情報源で一致 |
| 【中】 | 複数の二次情報で方向性が一致。数値は未検証 |
| 【低】 | 単一source・vendor集計。方向の参考のみ。数値を根拠にしない |
| 【俗説】 | 公式根拠なし。信じない |

単一vendorの大規模集計（Buffer・Socialinsider・Metricool）は方法論が開示されていても
母集団が偏るため【中】として扱う。§5.2・§5.3の再生数だけは本調査がTikTokから直接
取得した実測値なので【高】とするが、**代表作のみのsampleである**点は各所に明記した。

## 0. 結論の要約

1. 一番の敵はban（account停止）ではなく**「静かなFor You feed除外」**（§2。
   For You feed＝appを開いて最初に出る「おすすめ」欄。以下FYF）。unoriginal content
   （独自の編集が無い転載・再利用）の判定（2025年9月執行強化）を受けると、
   動画は残るのに新規には配信されない（執行強化の日付は二次報道由来。公式が明記して
   いるのはFYF基準の2025年8月14日公表・9月13日発効）。
   無編集の切り出しはこれに落ちるriskが高い。字幕・構成・文脈付けの編集が生存条件。
2. impressionは動画1本ごとの**完視聴・share**で決まる（§1）。follower数は公式に
   「直接のfactorではない」。新規accountでも1本ごとに勝負できる。
3. 動画は**冒頭1〜3秒に山場、15〜30秒、字幕必須**（§3）。30〜60秒は成績の谷。
   ただし**尺は流行ではなく題材が決める**（§5.2の実測では14秒〜4分46秒まで散る）。
   切る対象は「上手いプレイ」ではなく**視聴者との掛け合いと感情の頂点**（§3.5）。
4. 運用は**週2〜5本の継続**から（§4.1・§6）。頻度を上げても1本あたりの中央値は動かず、
   増えるのは上位10%の上振れ＝**当たりくじの枚数**。投稿時刻の最適化は俗説に近い
   （§4.2）。**配信者名に検索需要があるなら、検索対応が切り抜きの最大の武器**
   （§4.3。検索は「視聴数よりも関連性を重視する」と公式が明言しており、努力が直接効く。
   ただし無名配信者で検索volumeが立たなければこの武器は機能しない）。
5. 配信中の市販BGM・カラオケ音源は自動検出でmute・FYF除外になり得る（§2.3）。
   トーク切り抜きはBGM除去（このtoolの機能）でriskを下げ、音はapp内音源で後付けする。
   歌枠・カラオケ配信の切り抜きは除去でも解決しないので避ける。
6. 伸びたaccountは例外なく**連載の型**を持つ（§5.3）。毎回同じなのは「開幕の一句・
   締めの一句・画角」の3つだけで、中身は毎回違う。**答えや立場を要求する枠**を作ると
   commentとshareが伸びる（3本の横比較では2桁の差が出たが、言語圏・規模の交絡は
   統制していない【中】）。

## 1. impressionが決まる仕組み

- For You feedはfollow関係ではなく「何をどれだけ見たか」のinterest graphで配信を
  決める。最重要signalは**watch time（完視聴・rewatch）**で、share・comment・like・
  followが続く（WSJのbot実験とNYT入手の内部文書leakが一致）。【高】
  ただし一次資料は2020〜2022年のものを含み、査読付き学術audit（2022/2024）には
  「follow・likeの明示的行動が最強でwatch timeが続く」とする結果もある＝watch time
  偏重の程度は未確定。持ち帰るのは「完視聴とshareを最大化する」という方向まで。
- **follower数と過去動画の実績は「recommendation systemの直接のfactorではない」**と
  公式が明言。impressionは基本的に動画1本ごとに決まる。ただし公式は同時に
  「follower baseが大きい方がviewは増えやすい」とも認めており、実測でもviewはfollowerに
  ほぼ比例する。**効いている経路はFollowing feedではなくFYP**（詳細は§4.6）。【高】
- 新規投稿を小さな視聴者poolでtestし、成績次第で段階拡大する機構の存在は確認されて
  いる。【中】 ただし「初期200〜500人」「5〜10倍ずつ拡大」「完視聴率70%が合格線」
  「shareはlikeの3倍」等の具体数値は**すべて非公式の推定・相互引用**で、設計判断の
  根拠にしてはならない。【低】
- 検索が第二の配信経路。米消費者の49%がTikTokを検索に利用（Adobe 2026年2月調査、
  n=807の単一調査）【中】、日本の10代女性はTikTok検索56%【中】。検索重視自体は
  RPM公式4指標に「search value」が入っていることでも支持される【高】。
  For You feedの配信は短命（viewsの96%が投稿後10日以内という集計【中】）なので、
  検索適合は数少ない長寿命化の手段（ただし「SEOで補える」は構造からの推測【中】）。
- 2026年1月のUS Joint Venture成立でUS向けalgorithmはUS dataで再学習される別系統に
  分岐した【高】。日本向け投稿には当面直接影響しないと見られる（推測）【中】。

### 俗説の整理

| 主張 | 判定 |
|---|---|
| 投稿時刻を最適化すると伸びる | ほぼ【俗説】。大規模研究（Buffer/Hootsuite/Metricool/Sprout）の結論が相互に矛盾＝普遍的な最適時刻は無い。自分のanalyticsのfollower activityを見る |
| #fypを付けると伸びる/付けないと罰 | 【俗説】根拠なし |
| shadowbanという隠し制度がある | 【俗説】公式の枠組みは「FYF非適格」で、動画単位の通知とappeal、Account check（§11）で可視化される。無通知のreach低下の多くは単に伸びなかっただけ |
| 動画を削除するとaccountに罰 | 【俗説】単発削除への罰の公式根拠なし。ただし**同一動画のdelete→repost**はduplicate判定で初速が絞られる【中】 |
| business accountはreach抑制される | 【俗説】と整理するsourceが多いが、brand側（Duolingo株主向け説明）は抑制を前提に語る。未決着【低】 |
| trending audioを音量0で敷くと有利 | 【俗説】実音声を解析するため無視される |

## 2. 何が切り抜きのimpressionを殺すか（FYF非適格）

### 2.1 unoriginal content判定

判定基準は「素材の出所」ではなく**「新しい要素を加えたか」**。切り抜きは何もしないと
既定でNG側に落ちるので、何を足すかを最初から設計に入れる。

**公式がNGと名指しする4類型**（Creator Academy「オリジナリティポリシーを理解する」）
【高】。切り抜きは(a)(b)(c)にそのまま当たる。

| # | 公式のNG例 | 切り抜きでの該当 |
|---|---|---|
| a | 元の音声を完全にそのまま使い、**字幕だけを追加** | 自動字幕を焼いただけの切り出し |
| b | 他creatorのcontentに基本的なtext要約だけ追加 | テロップ1枚だけ足した切り出し |
| c | **単にclipをつなぎ合わせる** | 名場面compilation |
| d | 他者のwatermark・重ねられたlogoが見えている | app保存の透かし、配信画面のUI |

**公式が挙げる「originalと認められる加え方」4つ**【高】。これがそのまま制作templateになる。

1. **画面に登場する、またはnarration（voice-over）を足す**
2. **背景情報・詳細な解説を加える** — 「〇月〇日の配信」「この直前に何があったか」
3. **編集で素材を再構築し、別の視点として提示する** — 時系列そのままをやめ、
   結論→経緯の順に並べ替える
4. **clipを並べ替え、重要情報をhighlightする** — replay・zoom・矢印で注目点を指す

実装case: 冒頭0〜3秒は原素材を出さず自分のvoice-overと自作テロップで「誰の配信で何が
起きたか」を1文、以降は原素材だが自分の説明字幕を重ねる、中盤に時系列を入れ替えた
2カット目を挿す。**発話の書き起こし字幕は(a)の「字幕だけ」に当たるので、
originalityの加点には数えない**（別途、完視聴のためには必要）。

**判定の確認場所**【中】（UI名は英語表記で確認。日本語UIの表記は実機確認）:

| 見たいもの | 経路 |
|---|---|
| account全体（直近30投稿をscan） | Profile → ☰ → TikTok Studio → More tools → **Account check**。Postsタブが赤い「!」なら該当 |
| 動画1本の判定理由とappeal | 該当投稿 → 「More insights」または「…」→ Analytics → 上部の **Appeal** |

実際に出る文言は「**Ineligible for recommendation**」、理由は「Unoriginal, low-quality,
and QR code content」。unoriginal・低品質・QR codeが同じ枠なので、**配信画面にQRが
写っていたらmaskする**、極端に短い/静止画だけのclipも同じ結果を招く。【中】

**やってはいけない回避策**【中】。TikTokが回避手口として例に挙げているのは、
watermarkのぼかし・枠で隠す、sandwich frames（上下に無関係な別映像を敷いて自動照合を
ずらす）、微細frame挿入 — つまり**隠したこと自体が想定済みのpatternで、疑わしさの根拠に
なる**。ただし**この列挙の出所はTikTok Shop（seller/affiliate）向けpolicy**で、一般投稿の
Community Guidelinesと文面が一致するわけではない（同じ判定logicが働く強い示唆に留まる）。
metadata書き換え・色調整・軽微なcropも効かない（実際の映像・音声を見ているため）。【中】
なお「9:16に収める際、上下を埋めるなら自分のtext帯・背景色で埋める（他人の別映像は
使わない）」は**当方の解釈**で、公式が引いた線ではない。

**watermarkは消すのではなく最初から入れない**【中】。TikTokアプリの「Save video」で
書き出した動画は透かしが焼き込まれるので素材にしない（自分の録画の出力を原本にする）。
配信画面のLIVE badge・gift banner・視聴者数・他platformのlogoはcropかmaskで除く。
自作素材でも他appのwatermarkが残っていてflagされた実例がある。

**同じ配信から複数clipを出すこと自体は問題ない**【低】。公式が禁じるのは「同一動画の
重複投稿」であって「同一素材からの別clip」ではない。ただし切り出し区間が重なると
音声fingerprintで引っかかり得るので、**区間の重なりを機械的に検査して排除する**。
再編集版を出す場合は旧版を先に非公開にし、冒頭5秒・voice-over・テロップを全て差し替える。

**flagされたら**: appealは1本ずつの対症療法で、templateが原因なら次も同じ判定になる。
2本連続でflagされたらappealを積むのをやめ、上記4つの加え方でtemplateを作り直す。
appeal本文には (1)素材の出所と許可の有無 (2)自分が加えた要素 (3)第三者watermarkが
無いこと (4)再審査依頼、を具体的に書く。**ただし過度に期待しない** — 数日で解除された
実例がある一方、**appealが通らなかった報告も複数ある**。また判定は機械的で
**誤爆の報告があり、正しく編集していても当たり得る**（2025年後半に正規creatorが
警告なく外された事例報道）。【中】
なお期限は**Creator Rewards側の判定が動画80日以内・account失格30日以内**で、
FYF非適格通知のappeal期限は未確認。

### 2.2 TikTokはどうやって見分けているのか

**結論を先に**: TikTokは**判定の手段を一切公表していない**。ただし「同一・高類似を
照合する仕組みを持っていること」は公式に確認でき、さらに**TikTok所属の著者が本番系の
重複検出systemの論文を2026年6月に出している**ので、機構はかなり具体的に推測できる。
一方、巷で流通する「類似度85%が閾値」「速度を1〜2%変えれば通る」といった**数値は
すべて一次根拠がない**。

**そして最初に押さえるべき区別**: 以下で説明する重複照合（duplicate detection）と、
§2.1のunoriginal判定は**別の話**である。論文が扱っているのは**推薦の重複抑制**で、
実際に測っているKPIも「同じuserに似た動画を2本見せてしまう率」。論文全文に
「unoriginal」の語は**0回**、削除・penalty・収益化への言及も**0回**である。
**「重複照合に引っかからない＝unoriginal判定を受けない」ではない。**

**公式が言っていること**【高】

- 投稿前に自動moderationが走る。技術は7分類（vision / audio / text / **similarity** /
  activity / LLM / multi-modal LLM）と公表。ただし**適用先は「violative content
  （policy違反物）」と書かれており、unoriginal contentとは結び付けていない**。
- 「**similarity detection systems**が同一または高類似のcontentを捕捉する」。
  hate speech・violent extremism・CSAM については「de-duplication と hashing で
  copy や near copy を認識する」と明記（CSAMではhashを「digital fingerprint」と呼ぶ）。
- 推薦system側も「**duplicated contentは推薦しない**」と述べている（2020年の記述）。
- TikTok Shop向けpolicyでは「sandwich frames・微細frame挿入は**動画のdigital
  fingerprintを変えてdetectionを回避する**行為」と明記 → **frameの見た目に依存する
  signatureが実在する強い示唆**。
- **著作権面にYouTubeのContent ID相当（権利者が原本を登録して自動照合する仕組み）は
  無い**。通報と異議申立てだけ。楽曲だけは例外で、音源単位の照合と一括muteが実在する。

**公式が言っていないこと**【高】: unoriginal判定をどの技術で行うか。Transparency
Reportの削除内訳にも「unoriginal / IP」の項目は無く、この分野の実績は数値化されていない。

**重複照合はこうなっているはず**【中】（TikTok所属著者9名の論文「MLT-Dedup」、
KDD 2026 ADS track採択、2026年6月公開。「large-scale short-video platformの全production
trafficに投入済み」と書かれているが、論文はplatform名を伏せているので同定は所属からの推定）

1. 動画から**embedding（見た目を「意味の近さ」で表した数値の並び）**を作る。粗い方は
   16 frameごとに768次元、細かい方はframe単位で256次元。
2. 粗い方だけを**ANN検索**（近似最近傍探索。全件×全件の比較は不可能なので、
   まず候補を数十本に絞る）に載せる。細かい方はdiskに置き、候補にだけ読み込む。
3. 候補との**frame間類似度の行列**を作る。同じ映像が使われている区間は、この行列上に
   **対角線状の明るい線**として現れる（frame iとframe i+kが、一定のずれで順番どおりに
   対応する）。それを物体検出modelで矩形として切り出し、「query動画のここと、既存動画の
   ここが重複」という**区間の座標**を出力する。
4. 報告値は、同じuserへの推薦における重複率を精度90%時点で91%削減、追加遅延200ms未満。

**照合しているのは「投稿済み動画のindex」**【高】（論文の記述）。indexに載るのは
platform上のvideo corpusで、**LIVEへの言及は実質ゼロ**（全文で "live" は3件、すべて
"time-to-live"・"delivers"・参考文献のtitle）。さらに**indexにはTTL（保持期間）があり**、
古い動画は落ちる（TTLの長さは非公開）。つまり「何と照合されるか」は無限ではない。

**長尺からの切り出しは、この論文の中核的な対象**【高】。segment-levelの区間座標
（query側のどこと、既存動画のどこが一致するか）を出力する設計になっている。
「切り出しだから部分一致で逃げられる」という考えは、この機構には通じない。

**ここから読める実務的な含意**:

- **hash（bit列の照合）ではなくembedding（意味の照合）**。だから「色を少し変える」
  「速度を1%変える」「左右反転」のような小細工は原理的に効きにくい。
  昔ながらのpHashは「まるごと転載」には強いが**切り出しには構造的に弱く**、
  TikTokで典型的な「長尺から15秒を抜く」改変はhash系の苦手領域そのもの。
  だからこそ学習型の照合へ移っている。
- **どんな改変に強いかは学習時に何を見せたかで決まる**。この分野のbenchmarkは
  crop・回転・拡縮・反転・速度変更・emoji/text/枠のoverlay・画面録画・grid合成などを
  想定改変として組み込んでいる。**「テロップを足す」「枠を付ける」は想定内**。
- **照合対象はplatform内のindexだけ**。他platform（YouTube・Twitch）にしか原本が
  無い素材は、重複照合には原理的にhitしない。**それでも§2.1の判定は受け得る** —
  次項の通り、unoriginal判定は重複照合だけで出来ていないため。
- **短尺では「この動画は既出か」の判定は易しく、「どこが重複か」の特定は難しい**という
  非対称性がある（尺が短く編集が細切れなので対角線が断片化する）。

**LIVEは照合対象なのか**

切り抜きの元がLIVEの場合、「LIVE本編と切り抜きが突き合わされるのか」が実務上いちばん
効く。分かったことを分けて書く。

- **TikTok LIVEは録画されている**【高】。公式のLIVE replay機能で、配信者は自分の過去
  LIVEを**30日間**閲覧・downloadできる（TikTok Studio → LIVE → LIVE recordings）。
- **TikTok自身が保存理由に「content moderationの改善・開発」を挙げている**【高】。
  つまりLIVE映像はTikTok側のserverに残り、moderation目的での利用が公言されている。
  なお「30日」は**配信者が見られる期間**であって、TikTok内部の保持期間ではない
  （内部の期間は非公開）。
- **ただしLIVE replayが通常投稿と同じindexに入る、という公式記述は見つからなかった**
  【中】。公式の説明はすべて「あなたのreplay」「あなたが見るため」という配信者向けtoolの
  書き方で、視聴者への公開・FYF・検索への露出に相当する記述が無い。
- **結論: LIVE本編と切り抜きが照合されるかは「分からない」**。素材はTikTok側に存在し、
  moderation利用も公言されているので**可能性は否定できない**が、そうしているという
  証拠は無い。断定している情報源は信用しないこと。
- なお**自分のLIVEを切り抜いて投稿する導線はTikTokが公式に提供している**（replayの
  「Clip」機能）。ただしこの経路で出したclipがunoriginal判定を免除されるという記述は
  どこにも無い。
- 配信中のLIVE自体はFYF・検索・profileに露出し、**LIVE sessionもFYF非適格の対象**。
  「新しい編集の無いunoriginal contentを配信する」が明文でFYF非適格事由に入っている。

**同じ配信者・同じ背景・同じ姿勢だと誤爆するのか**

「LIVEは毎回同じ背景・同じ位置・同じ姿勢だから、見た目で照合するなら切り抜き同士が
全部似てしまうのでは」——これは正しい着眼点だが、答えは**誤爆riskは中〜低**【中】。
理由は3つ。

1. **copy detectionは「見た目が似ているか」ではなく「同じ映像素材から来たか」を判定
   する技術**として定義されている。学習も「同一素材に強い加工をかけた対」を正解として
   行われ、意味的に似ているだけのものは正解にしない。
2. **時間の対応が要求される**。上記の「対角線」は、frameが**順番どおりに**対応することを
   求める。同じ配信の別の場面は、背景が同じでも**時間の対応が成立しない**ので対角線に
   ならない（人が喋る・反応するといった動きがあれば、なおさら成立しない）。
3. **「ありふれた絵」は割り引かれる**。この種のsystemは、多くの動画と似ている queryの
   scoreを下げる正規化を共通して持っている。平凡な部屋・平凡なtalking headは、まさに
   この割引を受ける側になる。

ただし**risk はゼロではない**。この分野の代表的なmodel（SSCD）の著者自身が
「**同じ場面の別の写真をcopyと誤判定しうる**」を既知の限界として明記している。また
**完全に動きが無い映像では対角線の判別力が落ちる**（類似度行列が一様に明るい塊になり、
その中には必ず対角線が引けてしまう。ただしこれは当方の推論で、論文が主張していることでは
ない）。**「同一の部屋で撮った別take」を狙って評価したbenchmarkは存在しない**ので、
この点は研究上ほぼ空白＝正直なところ分からない。

**それより構造的に大きいのは、誤爆ではなく「本当の重複」の方**【中】。切り抜き運用は、
放っておくと自分で真の重複を作ってしまう:

| やりがちなこと | なぜ危ないか |
|---|---|
| 同じ録画から複数clipを出し、**区間が重なる** | 定義上まさに同一素材＋時間の対応が成立する＝正しく重複と判定される |
| 同じclipを消して**再投稿** | §2.1の通り |

対策は**clip間の時間区間を重ねないこと**。機械的に検査できるので、切り出し工程に関門と
して入れるのが確実（§8）。

**定型のintro/outroカードは、重複判定の対象にならない**【中】

「毎回同じ数秒のカード（配信スケジュール告知など）を末尾に入れたら、全投稿に共通の
一致区間ができて重複扱いされるのでは」という懸念は、**論文を読む限り不要**である。
理由は、この論文が**まさにその誤判定を防ぐための仕掛けを明示的に持っている**から。

判定は**AND条件**で、「重複区間が動画に占める時間比率（temporal coverage）が閾値を
超える」**かつ**「類似度scoreが閾値を超える」の両方が要る。そしてこのcoverage条件を
入れた理由が、論文のIntroductionにこう書かれている——「**部分的に重なるだけの動画を
誤って重複と分類しないため**」。5秒のカードは30秒の動画で17%、1分で8%にしかならない。

- 閾値の具体値は**非公開**なので「絶対に大丈夫」とは言えない。言えるのは
  「そういう関門が存在し、その設計目的が部分一致の除外である」まで。
- **尺は揃えること**。coverageの分母がquery側かcandidate側かは論文に記載が無い。
  15秒動画と3分動画に同じ5秒カードを入れると片側33%・片側2.8%と大きく振れるので、
  尺がばらつくほど不確実性が増す。
- そもそも**公式のunoriginal定義は4類型すべてが「他者由来の素材」**であり、
  自分で作った素材を自分の動画で繰り返すことは定義に含まれない。CGの文言も
  「新しい要素を加えていない、**他から持ってきた**素材」である。【高】

**むしろTikTok公式は一貫した意匠を推奨している**【高】。Creator Academyは
「**Develop a recognizable style** — format・setup・話し方は動画をまたいで一貫させる。
決め台詞、一貫したset、signatureになる冒頭のshotは、視聴者が1秒でそれと分かる手がかりに
なる」と書いている。§5.3の連載の型（毎回同じ第一声・同じ画角）はこれそのもの。

**ただしカードの置き場所は末尾**【高】。公式は「最初の3秒でtitleか文脈を出せ」
「効かないもの: **slow intro**・挨拶・無音」と明記している。冒頭にスケジュール告知を
置くのは、この非推奨に正面から当たる。なおTikTok自身は広告向けguideで
「強いCTAで終える。**CTAカードはrecall +45%・好感度 +19%**」と末尾カードを推奨している
（広告の計測値なのでorganicの完視聴率が上がる根拠ではない点に注意）。

**カードに書いてよいもの / 避けるもの**【中】（公式policyから導ける範囲）:

| | |
|---|---|
| 書いてよい | 配信スケジュールのtext（公式がschedule公開自体を推奨）、配信者名、TikTokの@handle、次回予告、見返りの無い「フォローしてね」「LIVE見に来てね」、毎回同じ意匠・logo・配色 |
| 避ける | **QR code**（CGからは2024年に条項が消えたが、Creator Academyは今もQRに言及しており公式docsが不整合。数秒表示のQRを読む人は少なく、riskに見合わない）、商品購入への外部誘導（TikTok Shopのある市場では可視性低下が明文化）、「公式」「Official」等の本人accountと誤認させる表記、「フォローでギフト」等のfalse incentive（FYF非適格） |

他SNS名・handle・URLをtextで出すこと自体を禁じる規定は、現行CGには**無い**（link関連の
唯一の規定は「違反contentへ誘導するlinkを貼るな」）。ただし明文が無いだけで、配信量への
影響が無いことの証明ではない。

**なお他人の配信を切り抜く場合、カードを足しても原作性は生まれない**【高】。公式は
「他者contentに**固定のtextを足しただけ**」を明確にnon-originalとして列挙している。
カードはあくまで導線であって、§2.1の付加価値の要件は本編側で満たす必要がある。
また切り抜きaccountは、**display nameにfan/切り抜きである旨を明記**しないと
impersonation扱いになり得る（公式が開示場所をdisplay nameと特定している）。

**重要: unoriginal判定＝重複照合、ではない**【高】。公式が挙げるNG類型と、TikTok Shopの
事前check toolが返す項目を見ると、明らかに**別系統の判定が並んでいる**:

| 判定項目 | 必要な技術（推定） |
|---|---|
| 他人のwatermark・logoが見えている | 画面内のlogo検出・OCR |
| still-frame（動きが乏しい） | 動き量の解析。重複照合とは無関係 |
| AI narration | 音声合成の判定 |
| 録画をliveとして流す | 配信の実時間性の判定 |
| 既出素材の再利用 | 上記の重複照合 |

つまり**「重複していないから大丈夫」ではない**。公式の基準は最終的に「**新しい付加価値が
あるか**」というsemantic（意味的）な言い方で書かれており、機械的なmatchだけの話ではない。

**信じてはいけない数値**【高】: 「類似度85%が閾値」「audioが重複の70%を捕捉」
「pHashのHamming距離10〜12bit」「速度1〜2%・zoom 2〜3%・crop 4pxで回避できる」——
これらの出所を辿ると**例外なく回避tool・engagement販売業者のSEO記事**に行き着き、
一次根拠（TikTokの文書・特許番号・論文・対照実験）を1件も示していない。しかも
**業者間で主張が正面から矛盾**しており（ある業者は「速度変更は正規化されるので無効」、
別の業者は「速度1〜2%が有効」と書く。どちらも自社productを売っている）、同じ「85%」が
出所不明のまま複数siteを循環している（元とされるsiteは既に消滅）。
中立な第三者の対照実験も、学術的な調査も、探した範囲では存在しなかった。

**なお回避策を探すこと自体が筋が悪い**。TikTokは上記の手口を「contentをoriginalに
するのではなく、systemを回避するだけ」として**明示的にenforcement対象と宣言している**。
外形的なparameterをいじるより、§2.1の「公式が認めている加え方」を満たす方が根拠が強い。

**なぜ転載accountが生き残っているように見えるのか**【中】。3つの理由で説明できる。
(1) unoriginal判定の帰結は**削除ではなくFYF除外**なので、followerのfeedとprofileには
残り、外からは生存して見える。(2) 原本が他platformにあれば**platform内の照合には
hitしない**。(3) AI再生成物は新しいsignatureを持つので、定義上「付加価値なし」でも
機械的なmatchの対象にならない（2026年の調査では新規accountのFor Youの59%がAI生成の
低品質contentだったという報告もある）。**つまり「まだ捕まっていない」であって
「検出されない」ではない。**

### 2.3 音源の自動検出

- 検出はupload時の自動音声照合。帰結はmute（最多）→動画削除→strike→banの段階制
  で、muteされると通知と「Change sound」（差し替え）promptが来る。【高】（構造）/
  【中】（順序付けは二次情報）
- impressionへの実害はmuteそのものより、「権利者が制限した音源（flagged audio）」や
  unoriginal判定経由で**静かにFYF非適格になる**方が大きい。【中】
- 背景の仕組み: TikTokはJASRAC・NexToneと包括契約済みで詞曲側は通るが、**原盤権
  （CD音源・サブスク音源・カラオケ音源・市販instrumental）は対象外**。配信中に
  流れていた市販BGM・カラオケ音源が検出対象になる。【高】
- 実務の整理:
  - **トーク切り抜き**: BGM除去（speech enhancement）で検出riskを下げ、音を足すなら
    TikTok投稿時にapp内音源で付ける（app内音源は権利処理済みでmute riskがない）。
    ただし「除去すれば検出されない」ことの実証は無い。【中】
  - **歌枠・カラオケ配信の切り抜き**: mute・削除riskが最も高い組み合わせ。照合対象に
    なるのは背後で流れる市販音源・カラオケ音源（原盤）で、**BGM除去がここに効くという
    実証は無い**（照合アルゴリズムは非公開）。**原則やらない**。【中】
    例外として配信者が生伴奏・a cappellaで歌っている場合は原盤側のriskが無い
    （ただし照合の挙動は非公開なので確実ではない）。

### 2.4 その他の抑制

- engagement bait（「likeして」「follow返し」）: 人為的なengagement増加として
  FYF非適格のトリガー。content価値に紐づく自然な問いかけは対象外。【中】
- clickbait: Creator Rewardsでは明文で報酬対象外。organic側もFYF非適格に区分される
  という整理がある。誇張のないhook自体は禁止されていない。【高】（Rewards）/
  【中】（organic）
- follower・engagement購入: 公式がH1 2024だけでfake likes 360億件を阻止と発表。
  数値剥奪→表示制限→banの段階罰＋詐欺・account窃取のsecurity risk。【高】
- borderline content: 削除には至らない際どい内容（性的示唆・危険行為等）もFYF
  非適格になる。**配信内の際どい発言のclipはimpressionが出ない可能性がある**。
  【中】（公式原文は未読で、二次sourceの一致に依拠）

## 3. 動画の作り方（煽らずに伸ばす）

### 3.1 冒頭1〜3秒

- 冒頭数秒で離脱が決まり、その後の配信量を左右する。TikTok for Businessも
  「最初の3秒でcontent propositionを提示せよ」と明言。【高】
  （「平均1.7秒で判断」という数字はFacebook 2016年調査の流用疑いがあり使わない）
- 切り抜きの定石は**山場（結末・最高潮の一瞬）を冒頭に先出しして、本編で文脈を
  見せる**構成（cold open）。挨拶・前置き・状況説明から始めない。【中】
- open loop型hook（「最後まで見て」）は本編で必ず回収する。回収しない釣りは離脱で
  自滅する構造（完視聴が最重要signalである以上）。【中】（構造からの帰結）

### 3.2 尺

| 目的 | 尺 | 根拠 |
|---|---|---|
| engagement率（切り抜きの主戦場） | **15〜30秒** | Socialinsider 600万本分析: engagement率は15-30秒で6.0%と最高【中】（大規模だが単一vendor集計。genre・account規模で変わる） |
| view数 | 2〜3分 | 同分析でview中央値は120-180秒が0-15秒の約9倍【中】 |
| 避ける | 30〜60秒 | 中途半端の谷（engagement率4.2%と最低）【中】 |

**15〜30秒で完視聴を取りに行くのが基本**。連続性のある長い場面は2〜3分版を
別系統として持つ（view数の面で長尺が有利という実測があるため）。

### 3.3 編集

- 字幕とテロップは分量が多いので§3.4に分けた。
- 編集tempo: 最初のcutは3秒以内、以後3〜5秒ごとにjump cut、言い淀み・dead airは
  削る。ただし笑い・感動系は余韻が本体なので切りすぎ注意。【中】
- 山場の選定は**配信中のcomment・reactionのspike**（視聴者が既に反応した実績の
  ある瞬間）を使う（調査ではshareのspikeも挙がる。このtoolではgift spikeも同種の
  signalとして使える）。これはこのtoolの盛り上がり検出が既に出している信号そのもの
  である。ただしchat spike≒良いclipは近似で、文脈がないと伝わらない内輪ネタは
  単体で成立しない。【中】
- seamless loop（末尾が冒頭に繋がる構成）は7〜15秒の短尺でrewatchを誘発する。
  効果量の数字（4.1倍等）は単独報告で信じない。【中】

### 3.4 字幕とテロップ

まず用語を分ける。**字幕**＝発話の書き起こし（情報保障）。**テロップ**＝演出目的の
見出し文字。役割も置き場所も別なので、まとめて「text」として扱わない。

**なぜ効くのか（3つの経路。混同されがち）**

1. **完視聴を上げる（主経路）**。公式が挙げるranking signalは「caption（投稿の説明文）・
   sounds・hashtags」＋視聴行動で、**画面上の文字そのものに加点する記述は無い**。
   よって字幕は完視聴を経由した間接効果として設計し、評価指標はimpressionではなく
   平均視聴時間と完視聴率に置く。【中】 なおこのsignal一覧は2020年公開かつ非網羅なので
   「書かれていない＝使っていない」ではない（実際、後述のkeyword自動付与はこの記事に
   無い機構）。
2. **検索textを供給する**。TikTokはapp内の自動字幕・text sticker・説明文を翻訳できる＝
   これらを文字列として保持している。**焼き込んだ文字は翻訳もOFFもできない＝TikTokの
   text層に存在しない**。【高】 焼き込みtextをOCRで読んで検索に使うという公式記述は
   確認できず（SEO系blogの伝聞のみ）、**OCRに賭けない設計にする**。【中】
3. アクセシビリティと、配信音声の可読化。切り抜きは元音声がBGM・歓声・被り声で
   聞き取りづらいので、ここの価値が単純に高い。

**「動画の8割は無音視聴」はTikTokには当てはまらない**【高】。TikTok自身のMarketing
Science（Kantar 2021）は「88%が音は不可欠」「sound-on 93%」。広く流布する80〜92%という
数字は2016〜2019年の他platform（自動再生が既定でmuteのfeed型）の調査で、sound-onが
既定の全画面playerには外挿できない。**無音対策を字幕の主目的にしない。**

**推奨構成（hybrid）**【中】: 発話字幕はTikTokのapp内自動字幕に任せて誤字だけ直し、
焼き込みは画面上部の見出しテロップに限る。理由は、(1)app内字幕はtextとして保持されて
検索に載り視聴者がOFFにもできる、(2)焼き込み字幕とapp内字幕を両方出すと画面下1/3で
重なって両方読めなくなる、(3)見出しは演出の自由度が要るので焼き込みが向く。

**実装上の制約が2つある**【中】: **TikTokは.srt/.vttの直接uploadを受け付けない**ので、
このtoolのwhisper文字起こしをそのままtext層へ流す経路が無く、app内で生成して直すしかない。
そして**auto captionsは投稿後に編集できないという報告がある**ので、修正は投稿前に
済ませる。また翻訳については、**日本語がcaption翻訳の対象言語に入っているかは未確認**
（2022年時点の対応一覧に日本語は無い。auto captionsの日本語対応とは別の話）。海外reachを
狙うなら英語の見出しを1枚足す方が確実。

デザインを統一したくて焼き込み字幕を維持するなら、app内字幕はONにせず、**説明文に
発話の要点を書いて検索textを供給する**。

**日本語の具体値**【中】（複数の日本語制作guideが収束した値。公式ではない）:

| 項目 | 値 |
|---|---|
| 発話字幕 | 1行8〜10全角字・最大2行、文字高65〜86px（1080幅の6〜8%）、白＋黒縁固定、位置は動画を通して動かさない |
| 見出しテロップ | 1画面32全角字まで、文字高110〜130px、2〜4秒表示、動画あたり2〜5枚 |
| 縁取り | 文字サイズの5〜10%（4〜8px）。背景が複雑なら黒帯（不透明度50〜70%）へ切替 |
| 色 | 動画全体で4色以内（白・黒・グレー＋accent 1色）。強調は字幕内の1語だけ |
| 表示時間 | 下限1.2〜1.5秒（下記の折衷。詳細は表の下） |
| 同時表示 | 画面に出る文字要素は最大2つ（見出し＋字幕）まで |

**表示時間の根拠**: TikTokの広告guideは「5〜10 words/sec」（日本語換算で25〜50字/秒）と
かなり速く、日本語の放送字幕基準は「1秒4字」と10倍違う。**shortでは放送字幕基準は
遅すぎて字幕が動画のテンポを律速する**ので、実務値はその中間を取り、下限だけ
1.2〜1.5秒で止める（読めない字幕は意味が無いため）。切る位置は時間で機械分割せず、
句読点・助詞境界で改行し、1 cueが20字を超えたら分割する。

ASS実装の当たり値（PlayResX=1080, PlayResY=1920。ASS＝字幕format、Fontsize/Outline/
Alignment/MarginVはその設定名）: 発話字幕は Fontsize=76〜86, Outline=5, Alignment=2,
MarginV=480〜520。見出しは Fontsize=110〜130, Alignment=8, MarginV=300。
これで上下に物理的に分離する。

**safe zone**【中】: TikTok公式は「safe zoneは説明文の長さやadd-onで動く」として固定pxを
出していない（**ただしこの記述は広告formatのもので、organic投稿のUI配置と完全一致は
しない**）。実務の当たり値は1080×1920に対し x=60〜880 / y=280〜1400 を「文字と顔を置いて
よい帯」とする（上130〜250px・右64〜180px・下320〜480pxを空ける。これらのpxは出典・
計測法が不明な第三者guideの値）。**説明文を1〜2行に抑えると下部の侵食が減る**
（1行約80px、3行＋hashtagで250px超）。最終確認は実機で自分の投稿を再生してscreenshotを撮る。

**やり過ぎの弊害**: 画面が文字で埋まる、safe zone侵害、字幕がテンポを律速する。

### 3.5 どの瞬間を切るか

編集技法より前に「どの秒を切るか」で結果が決まる。実際に伸びたclipは4類型に集約される
【中】: (a)**感情の頂点**（絶叫・爆笑・崩壊）、(b)**視聴者との直接の掛け合い**
（1対1・音声メッセージ・コメント読み上げ）、(c)**自分や身内への嘲笑**（ファン制作物への
本人リアクション）、(d)**予測不能な反転**（jumpscare等）。

日本語圏の切り抜きguideの分類も概ね一致する【低】（実務blogの経験則で成果dataは無い）:
リアクション型（大きな笑い・驚き・感情が動いた一言）、参加型（投票の結果・call&response
で一体感が出た瞬間）、実用情報型（結論→理由→具体例が30秒に収まる説明）、パフォーマンス型
（曲のサビ・技が決まった場面）、節目型（配信冒頭・カウントダウン）。

**選定の絶対条件は「その30秒だけで初見に伝わる完結性」**。文脈が必要な長い説明と
内輪ネタは、どれだけ配信中に盛り上がっていても単体では成立しない【中】。

**最重要の編集則は「緊張の瞬間から入る（setupを切り捨てる）」**【中】。必要なら時系列を
入れ替えてオチを先に出す。ただし**オチを完全に前出しして後が空になるのは失敗例**として
名指しされているので、先頭に置くのは0.5〜1秒の断片に留め、そこから文脈へ戻る。

**伸びない切り抜きの特徴**（複数sourceが一致）【中】: 立ち上がりが遅い、字幕が無い、
内輪ネタ・文脈依存、尺が長い、元配信と音量差がある。出す前のcheck list —
1フレーム目にテロップがあるか／最初の1秒に音か動きがあるか／指示語（それ・あれ・
さっきの）の説明なしで通じるか／尺は詰め切ったか／字幕は入ったか。

## 4. 投稿運用

### 4.1 頻度 — 「くじの枚数」を増やす作業

公式は頻度を推している。「1日に複数回投稿するpublisherは動画視聴数とFYF露出が高い。
**一貫して達成できる1日の投稿目標を設定**し、それに沿って企画せよ」「投稿する動画の数が
増えるほど、おすすめsystemがcontentを理解し適切な視聴者に紹介する機会が増える」【高】。
ただし**この記述はpublisher（メディア事業者）向け記事のもの**で個人accountへの適用は
保証されず、同じ記事は**qualityとquantityのバランス**も同時に求めている。

一方、Bufferの1,140万投稿の実測（account規模を統制した固定効果回帰）が示すのは、
**増えるのは平均ではなく上振れ**という構造【中】:

| 週の投稿数 | 中央値views | 90パーセンタイルviews |
|---|---|---|
| 1本 | 489 | 3,722 |
| 2〜5本 | 506 | 6,983 |
| 6〜10本 | 487 | 10,092 |
| 11本以上 | 459 | 14,401 |

中央値はどの頻度でも459〜506でほぼ動かず、上位10%だけが3.9倍になる。つまり
**頻度は当たりくじを引く回数を増やす作業**で、1本1本が良くなるわけではない。

この表の限界は3つある。**母集団はBuffer（投稿予約tool）の利用者**で、中央値500 views
前後という水準は小〜中規模accountが中心＝大規模accountには外挿できない。**観察dataで
因果は分離できていない**（頻度を上げたから上位が伸びたのか、伸びるaccountがよく投稿
するのか）。そして**viewはimpressionと厳密に同義ではない**。別の集計（Metricool）は
platform全体で投稿量が前年比+72%なのにほぼ全指標が低下したとしており、こちらは
「account内の頻度効果」とは別の現象（供給の希釈）だが、量を追うだけでは駄目という
方向は共通している。

切り抜きへの含意が2つある。(1)素材在庫があり1本の限界費用が低い切り抜きは、この分布と
最も相性が良い。逆に1本に何時間もかけるなら本数を増やす意味は薄い。(2)**評価指標を
中央値でなく上位（p90か上位3本の合計view）に置く**。中央値で見ると「増やしても効果なし」
と誤って結論する。

**「一貫性 > 一気」の意味**: 1回の配信から10本まとめて出して以後止まる運用より、
毎配信後に1本ずつ出し続ける運用の方が良い、という切り抜き実務guideの一致点【中】。
理由は2つ。**まとめ出しは互いに食い合う** — 公式のranking工程には「似すぎた動画
（例: 同じsoundを使っている）を別の動画に差し替える」similarity checkがあり、同一
視聴者のfeedに自分の似たclipが並ばない。**そして在庫を一気に使うと翌週が空く**。
「休むとaccountが弱る」わけではない（投稿間隔はranking signalの公式列挙に無い）が、
くじを引かない週はそれだけ機会を失う。【中】

在庫と工数から見た現実的な出発点は**週2〜5本**（日本語圏のguideは週2〜3本、海外の
clip実務は週3〜5本を挙げる【中】）。そこから下記の要領で増やす。

運用形: 「1日N本」を宣言してNは在庫が切れても守れる数にする。増やす時はNを1つ上げて
最低2週間固定する（1本ごとの分散が大きすぎて2週間未満では判断できない）。同日に2本
以上出すなら**連続する2本は配信者を変える**（似た組ほどsimilarity checkに当たる）。
本数を増やす方向は「同じ配信から複数本」より「同じniche内の別の配信から」が良い
（公式は「特定のnicheを選べ」とも言っており、配信者を10人に広げるのはniche判定を
ぼやけさせる）。休みが読めているなら、**TikTok Studio web版の一括upload＋予約投稿**で
穴を埋める（これが公式の案内する唯一の対処）。【高】

### 4.2 投稿時刻 — 労力をかける場所ではない

投稿時刻・鮮度・投稿からの経過時間は、**公式のranking signal列挙に一度も出てこない**
【高】。時刻で変わるのは主に「その瞬間にfeedを開いている人の構成」で、algorithmが時刻を
見て加点する記述は無い。大規模研究どうしの結論も矛盾している（§1の俗説表）。

**ただし公式は自らこのsignal一覧を「non-exhaustive（非網羅）」と明記している**ので、
「列挙に無い＝効かない」ではない。言えるのは**公開documentが一度も挙げていない**まで
（この但し書きは§4.1の「休むこと自体への罰は無い」にも同じく掛かる）。

「最初の1時間が勝負」にも公式の裏付けは無い。むしろ公式は「**再生数が伸びないからと
いって、おすすめされなかったとは限らない**」「制限を受けた場合はその情報がインサイトに
表示される」と書いている【高】。投稿後1時間に人を張り付けるより、冒頭3秒と検索
関連性（§4.3）に同じ労力を回す方が根拠が強い。

自分のfollower activityは **TikTok Studio → インサイト → フォロワー → アクティブ時間**
で見る。読み方は「複数曜日で同じ時間帯に再現するpeakだけ採る」「UTC表示なら+9時間」。
**ただし立ち上げ期には使わない** — この表はfollowerがonlineな時間であって、impressionの
大半を占める非followerの話ではない。動画別インサイトのtraffic sourceで「フォロー中」経由が
意味のある比率に育ってから初めて見る価値が出る。【中】

海外視聴者を時刻で狙うのは筋が悪い。公式に「FYFにviewerの地域のcreatorのcontentが
含まれるようruleを設けている」とあり、regionと言語の壁の方が支配的【高】。狙うなら
順序は (1)captionと画面textを対象言語に (2)対象言語のkeyword (3)時刻、の順。

### 4.3 検索対応（TikTok SEO）— 切り抜きが最も得をする場所

公式が明言している【高】: 「**検索はおすすめフィードとは異なり、動画の視聴数や
エンゲージメントよりも関連性を重視します**」。FYFはengagement勝負で運の要素が大きいが、
検索は関連性勝負なので努力が直接効く。しかも切り抜きは**配信者名という極めて強い
検索語を最初から持っている**。ここが投資対効果の最も高い場所。

公式が挙げるkeywordの置き場所は「動画・字幕・キャプション」＋「タイトルとカバー」。
切り抜きでの実装:

| 置き場所 | 何を書くか | 検索への効き |
|---|---|---|
| caption 1行目（冒頭30〜40字） | 配信者名＋ゲーム/話題名＋出来事。折り返しの手前に収める | **確実**（公式が明示） |
| app内の自動字幕 | 生成後に固有名詞の誤字を必ず直す | **確実**（textとして保持される） |
| cover（表紙） | 配信者名を文字で | **公式が明示**（「カバーにトピックが明確に示される必要」） |
| 焼き込みテロップ（最初1.5〜2秒） | 配信者名を含む1行。hookも兼ねる | **賭けない**（§3.4の通りtext層に存在せず、OCR利用の公式記述は無い。コストゼロの二重化として入れるのは構わないが、ここに載ることを前提に企画しない） |

**切り抜き固有の問題**: 元配信の発話に「配信者の名前」「ゲームの正式名称」はまず出て
こない。だから発話に頼らず、**caption・app内字幕・cover**で担保する。narrationを足すなら
そこで名前を言う — §2.1のoriginality要件も同時に満たせる。

keywordの優先順位は原則 **配信者名 > ゲーム/コンテンツ名 > 出来事語**（「コラボ」「初見」
「最終回」）。ただし**無名の配信者では順序が逆転する**（ゲーム名で流入して配信者を知る）
ので、下記の検索volume確認で決める。「爆笑」「神プレイ」のようなシーン描写は検索語として
弱いので、captionではなく冒頭テロップに回す（そこはSEOでなく完視聴の仕事）。【中】

需要の確認は**Creator Search Insights**（検索バーで「Creator Search Insights」と検索して
開く）。公式がpro tipとして名指しするのは「**コンテンツ不足**」タブで、検索数は多いのに
質の高い動画が少ないtopicが分かる。監視している配信者名を1人ずつ入れて検索volumeが
出るか確認し、出ない名前は検索SEOの対象にならないと割り切る。【中】

**公式が明示的にNGとしているもの**【高】:「人気のみを根拠に、無関係なキーワードや
誤解を招くキーワードを含めることは避けましょう。無関係なテキストが多すぎると、動画の
トラフィックに悪影響を及ぼします」。内容と無関係な #おすすめ #バズれ 系の汎用tagが
これに当たる、というのは**当方の解釈**（公式が名指ししているわけではない）。

hashtagは3〜5個・具体的なものにして、うち1つは配信者名 —これは**第三者の慣行**で公式の
数値ではない【中】。効果は小さい正（views+5%程度）だが**相関であり、hashtagを丁寧に
付けるaccountは他も丁寧という交絡があり得る**【中】。役割は「どのnicheに属するかの宣言」。

なおTikTokは投稿に対して**人気の検索語に基づくkeywordを自動付与**しており、投稿画面から
的外れなものを外せる。投稿後に点検する。【中】

### 4.4 Playlist（無料。ただしfollower 1万の壁）

**結論から**: Playlistは**無料**の整理機能で、有料なのは名前の似た**Series**の方（別物）。
ただしPlaylistには**follower 1万人超**という利用条件が公式に明記されている。【高】
（「無料」は公式が明言しているのではなく、公式記事に価格・課金条項が一切無く、有料の
Seriesだけに決済条項がある構造からの判断。1万人は公式明記の線だが、段階的な開放で
1万人未満でも使えたという報告もある。）

| | Playlist | Series |
|---|---|---|
| 課金 | **無料** | **有料販売機能**（視聴者が購入して視聴） |
| 用途 | 既存の公開動画をまとめ直す | 新たに有料contentを売る |
| 条件 | follower 1万人超 | 地域別（米国版はfollower 1万人以上ほか） |
| 規模 | 動画数の上限なし・一度に100本追加可 | 最大80本・1本20分まで |

**何が起きるか**: 動画をPlaylistに入れると、**その動画の再生画面にPlaylistへのlinkが
出る**。FYFで1本が当たったとき、その1本を入口に同じPlaylistの過去動画へ視聴者を送れる。
Playlist詳細ページはFYFと同じ縦swipeで見られる。【高】

**重要な設計制約**: **各動画は1つのPlaylistにしか入れられない**。「配信者A」と
「神回まとめ」の両方に同じ動画を入れることはできないので、軸を1本に決める。複数配信者を
扱うなら軸は配信者名（視聴者の動機が「この配信者をもっと見たい」で最も強い）、単一
配信者なら企画名。もう一方の軸はhashtagとcaptionで表現する。Playlistを消しても中の
動画は消えないので、軸の付け替えはやり直せる。【高】

**期待しすぎないこと**【中】: 「視聴数が増える」という公式のclaimはあるが**数値を伴う
公式dataも第三者の実証も見つからなかった**（ただし調査は検索回数の上限で打ち切っており、
日本語圏の検証記事までは掘れていない＝「無い」の証明ではない）。公式が説明しているのは
「動画上のlink→Playlist詳細ページ」という導線だけで、**FYFのalgorithmがPlaylist入り
動画を優遇するという記述はどこにも無い**。新規impressionを生む機能ではなく、既に得た
impressionを過去動画の再生へ変換する機能と理解する。効果を測るなら主KPIは「投稿30日
以上前の旧動画の日次再生数」（新着が当たった翌日に跳ねるか）。

なお「Playlist詳細ページが自動で次へ進む（autoplay）」という第三者記述があるが、公式が
言っているのは「FYFと同じ操作感で縦swipeできる」まで。自分のPlaylistを再生して放置すれば
30秒で確かめられる。【中】

follower 1万に届かない間は、**profileへのピン留め（最大3本、follower要件なし）**で代替する。

### 4.5 comment・analytics・伸びなかった動画

- **comment**: 公式が明示している運用は「視聴者のcommentに素早く返信し、そのcommentを
  content制作に活用する」だけ【高】。切り抜きはこれを最も安く実行できる — 「この配信の
  ここが見たい」というcommentに対し、**素材が既に手元にある**。公式機能の
  **reply with video**（commentを画面に貼った新規動画として投稿）で応えれば、
  originality要件（背景情報の追加）も同時に満たす。
- **pinned comment機能は2025年に（公式告知なく）消えたという報告がある**が、2026年に
  現在形で「3件までpinできる」と書く記事もあり**情報が矛盾している**【低】。自分のappで
  自分の動画のcommentを長押ししてmenuを見るのが唯一の確認方法。現行の代替は「1件目の
  commentが強調表示される」仕様なので、投稿したら自分で1件目を入れる。書く内容は
  「出典（〇月〇日の配信）＋文脈（この直前に〇〇があります）＋軽い問い」。切り抜きは
  文脈が落ちて誤読されやすいので、**煽らない方針とも噛み合う**。「いいね押して」だけの
  CTAは書かない。
- **analytics**の優先順: (1) 完視聴率／平均視聴時間 → (2) shares・saves →
  (3) traffic source（おすすめ vs 検索の比率）→ (4) follower activity。
  like数とfollower数は虚栄指標に近い（followerの実際の効き方は§4.6）。
  目安の完視聴benchmarkはvendor経験則。【中】
- **伸びなかった動画は原則消さない**【中】。理由は検索が関連性優先だから — FYFで0でも、
  配信者名の検索資産として残る。配信者が後で話題になれば過去の切り抜きが一斉に拾われる。
  消す前に必ずインサイトを見る: 制限表示があるなら原因が特定済み（作り直す）、
  「おすすめ」がほぼ0で検索・プロフィールだけ動いているならFYF非適格の可能性、
  おすすめ経由はあるのに完視聴率が低いなら内容の問題（冒頭3秒を作り直す）。
  **「伸びなかった」には最低3つの別々の原因があり、対処が全部違う。**
- **再投稿するなら同一動画をそのまま出し直さない**【中】。冒頭3秒・cover・尺・文脈textの
  どれかを実質的に変える。重複判定で初速が絞られ、繰り返すとspam挙動になる。
  「48時間以内なら再投稿してもpenaltyなし」という説は出典が無いので採用しない。
- **効果測定**（提案）: 最初の10〜20本は編集の型を固定してbaselineを作る → 変えるのは
  1変数ずつ（hook構成、尺、テロップ量）→ 判定は完視聴率とshareで、view数の単発の
  上振れでは判定しない。時刻のA/Bは1本ごとの内容のばらつきが大きすぎて、
  各条件20〜30本必要になり割に合わない。

### 4.6 followerはどう効くのか

「followerが多ければfollowerが見てくれて、いいね率も上がるのでは」は自然な直感だが、
**viewについては正しく、engagement率については成立しない**。しかも効く経路が直感と違う。

**viewは follower にほぼ比例して増える**【中】。tier別の平均viewから計算すると
elasticityは約0.93（followerが141倍でviewが約100倍＝わずかに逓減するがほぼ比例）。
公式も「follower baseが大きいaccountの動画は、そのfollowerに見られることで結果的に
view数が多くなりやすい」と認めている。**ここまではご指摘の通り**。

**ただし経路が違う。Following feedはviewの2%しかない**【高】。Metricoolの231万投稿の
実測では、traffic sourceの内訳は For You Page 73% / profile 11% / hashtag 10% /
検索 4% / **Following 2%** / sound 0%。account規模別に見ても Following は 1〜4% 止まりで、
**follower 100万超でも4%**。公式も「利用時間の96%はFor You feed」と明言している。

つまり**followerの効果は「Following tabを見に来ること」ではなく、「FYPで配られやすく
なること」として現れる**（follow行為はpersonalizationの最強driverの1つという学術研究が
ある）。なおFollowing feedすら時系列の全件配信ではなく、**推薦でrankingされる枠**である
ことを公式が明記している。

**engagement率は分母で結論が真逆になる**【高】。ここを混同した情報が非常に多い。

| 分母 | follower 1-5K | 50-100K | 100K-1M | 傾向 |
|---|---|---|---|---|
| **view基準**（TikTokの業界標準） | 4.40% | 3.75% | 3.95% | **ほぼ横ばい〜微減** |
| **follower基準** | 9〜15% | — | 1〜3%（100万超） | **急落** |

view基準（200万本・21万accountの実測）では、followerが20倍以上になってもERはほぼ動かず
むしろ微減する。follower基準の急落は「大きいaccountほど質が低い」のではなく、
**分母だけが膨らむ算術的な帰結**。つまり**どちらの分母でも「followerが増えるといいね率が
上がる」を支持するdataは無い**。

外部のbenchmarkと自分の数字を比べるときは、**必ず分母を確認する**こと。同じ曲線を
「view基準」と称するsiteと「follower基準」と称するsiteが実在し、業界に混乱がある。

**それでもfollowerを取る価値はある**【高】。理由はengagement率ではなく**機能の解禁**:

| 閾値 | 解禁されるもの | 切り抜きでの価値 |
|---|---|---|
| 1万 | Playlist / Creator Rewards / Series | **実質Playlistだけ**（Rewards・Seriesは§2.1のoriginality要件で塞がれやすい） |
| 5万 | **bulletin board** | **followerへ自動通知が飛ぶ唯一の明示channel**で、「次のLIVEを告知する」機能がある。LIVE導線を作るならここが実質的な目標線 |

**LIVE集客の即効策はfollowerではない**【高】。公式が推奨しているのは
「**LIVE開始前に動画を1本投稿して、For You feedから入ってもらう**」という手順で、
followerへの自動通知は公式に約束されていない（LIVE Eventのpush通知も、届くのは
そのeventに登録した人だけ）。

**実務結論**: 追うべきは**1本ごとのview**。view→followerの向きは効く（切り抜きが属する
広い娯楽系の転換率は0.5〜1%という目安がある【低】）が、**follower→viewの向きは
Following feedが2%しかない以上ほとんど効かない**。followerは1万・5万の閾値を通過する
ための副産物として扱うのが合理的。

## 5. 海外事例から学ぶこと

### 5.1 切り抜き→配信送客の実証例

**Jynxzi**（視聴者ほぼ1人の状態から約2年でTwitch最多subscriberへ）。重要なのは
**何を切ったか**で、本人がForbesで名指ししているのは**ゲームの上手さではない**【高】:

> 「The 1v1s, the voice messages and much more; that is just core to my community」
> （視聴者との1対1、視聴者から届いた音声メッセージ、そして友人との掛け合い）

最初にバズったのも「alpha packを開けている自分」のclipで、gameplayより日常
（mallでの買い物）のclipの方が伸びた、という報告もある【低】。TikTokのclipで見た人格が
配信に来ても**そのまま**であることが定着の鍵、とForbesは分析している。

**ここから引ける実装の結論**: 切る対象を「試合のハイライト」ではなく
**「視聴者と1対1で絡んだ区間」「視聴者のコメント・音声を読んだ直後のリアクション」**に
置く。さらに配信側に**切り抜き前提の定番コーナーを毎配信1つ**用意すると、素材の歩留まりが
構造的に上がる（視聴者と1本勝負、視聴者の音声メッセージを再生、視聴者の環境を採点など。
勝敗が数秒で決まる仕掛けは、決着の瞬間＝clip終端として機械的に検出できる）。

**CaseOh**: 型は「ファンが作った自分のedit・アニメを見て過剰にリアクションする」と
「ホラーゲームの絶叫」。前者は**素材を視聴者が作り、本人がリアクションを供給し、
それがまた切り抜かれる**二重loop。clipの形は「gameplay画面＋face cam＋実況音声」の
約15秒で、transitionもtrend音源も無い【低】。ホラー×初見×jumpscareは今でも最短距離で
数字が出る素材（あるホラーゲームのプレイ動画は3週間で約300万再生）【中】。

**Kai Cenat / IShowSpeed系**の切り抜きの類型は「叫び」「有名人ゲスト」「長時間耐久で人が
壊れる瞬間」「新語の誕生」。共通するのは**音と表情だけで何が起きたか伝わる**こと【中】。

確度と限界: Jynxziは【高】（Forbes本人談）、CaseOhは【中】。**両者の送客先はTwitchで、
TikTok Live送客の直接実証ではない**（構造の転用）。またgaming×高テンション芸風であり、
全genreで同じ爆発力の保証はない。なおTikTok公式もLIVE前の予告動画・LIVE直後の
highlight投稿を誘導導線として推奨しており、「切り抜き→LIVE」の循環はplatform公認の
設計ではある【中】。

**業界全体の構造も押さえておく**【中】: あるcampaignでは520人のclipperが11,000本を
出して合計4.3億再生。**量で当てる**構造だが、これは**既に巨大な原作者の素材があっての
数字**で、無名素材を量産すれば当たるという意味ではない。同じ記事はAIの自動切り出しのみの
実験が1本2,500再生に留まったとも報じているが、**これは条件（どのAI・どの素材・どの
account）非開示の単一test**なので根拠としては弱い。

より確かなのは実務の観測の方 — 上位のclipperは**配信中にリアルタイムで切っている**。
**toolの役割は完成品の自動生成ではなく「候補の抽出と順位付け」**に置き、人が10秒ずつ
見て採否を決める形が現実的。

**1本あたりの所要時間**【中】。よく見る「1本15分」はAI切り抜きtoolのvendorが掲げた
**目標値**で、実測ではない（当のpageが「clipper communityの慣行の反映」としか書かず、
CTAで「自社toolを使えばこの目標は絵に描いた餅でなくなる」と締めている）。
vendorに依存しない実測はおおむね**20〜30分/本**に寄る:

| 出所 | 値 | 条件 |
|---|---|---|
| timerを回した実測（45分素材→8本） | 約22分/本 | 手作業。素材探し40分・切り38分・9:16への変換25分・字幕30分・書き出しと投稿30分 |
| 手動clipper（1か月習熟後） | 20〜30分/本 | 手作業 |
| 職業editor（AI tool併用） | 24〜36分/本 | overlay追加とrenderがtool外に残るため |
| tool vendorの主張 | 4〜15分/本 | 自社tool前提。**投稿・説明文・cover・submissionを含まない** |

差の大半は「何を含めるか」と「自動化の範囲」。**9:16への変換・字幕・素材探しを自動化できるかで
1本10分近く動く**（上の内訳ではこの3つで11.9分/本）。batch制作（1回で5〜10本）は
素材探しの固定費を分母で割るので効くが、長時間のsessionは後半で品質が落ちるという
自認もvendor側から出ている。

### 5.2 煽らずに伸びた個人creator

「nicheを絞れ」は結論としては正しいが、それだけでは何も作れない。実際の動画が
**どんな見た目で、毎回何が同じなのか**を調べた。以下は記事の描写に加え、動画の尺・
再生数・音源・caption原文を実測した結果【高】。ただし読み方に3つ注意がある:
**実測値は各creator 1〜3本の代表作のもので、accountの中央値ではない**（＝当たった回だけを
見ている）。**再生数は2026年8月時点の累計**で、非公式のmirror API経由なので公式表示値と
厳密一致は保証されない。そして下記のうち**Tanner Leathersteinの再生数と、Miss Excelの
「24時間で360万再生」は実測ではなく記事の引用値**（前者はWired 2024年11月時点、後者は
本人談で該当動画は特定できていない）【中】。

**Keith Lee（食レビュー / 1,700万follower）**
- 代表作は**4分29秒**で6,142万再生。caption はたった1行「Frankensons Pizzeria
  Taste test 💕 would you try it ? 💕 #foodcritic」。
- 画は**車の運転席でテイクアウト袋を開けるだけ**。音は original sound のみ＝
  **BGMなし・filterなし・演出なし**。
- 毎回同じ: 決め台詞「let's try it and rate it one through 10」、
  進行順「店名を言う→なぜここを試すか→食べる→1〜10で採点」。
- 店に忖度されないよう自分では名乗らず、家族に注文させてto-goで受け取る。

**Jim McFarland（靴修理 / America's Cobbler）**
- 代表作は**4分46秒・一言も喋らない・手元固定カメラ**で3,414万再生。BGMはジャズ。
  映っているのは終始「作業台の上の靴と手」だけで、顔出しも語りもない。
- その回の構成は「客から届いた箱を開ける→同封の手紙を読む→修理する」で、
  オチは**読んでいる途中で差出人が自分のいとこだと気づく**、その一点だけ。
- captionが「Relax & unwind as I〜（くつろいで見てて、今から私が〜する）」という
  **誘い文句の定型**。1足の修理を5本に分割して投稿する連載型も常用。

**Mercury Stardust（DIY修理 / 260万follower）**
- 最初のバズは**他人の動画への返信**として作った、ratchet strapの使い方の約1分の実演。
  これで24時間に100→25,000 follower。
- 毎回同じ: **フランネルシャツ＋オーバーオール姿で工具を持つ**画と、締めの台詞
  「Learning something new is a triumph, and I'm proud of you.」。
- 実測1本は**29秒**で176万再生、captionは一言
  「Drywall patching! #DIY #Trans #Lgbtqia #Drywall」。
- 題材は全部「借家人が自分でできる」範囲（壁穴のパッチ、排水管の詰まり、
  ネジのバカ穴をつまようじで直す）。1,600本以上。視聴者の約9割が女性。

**Poppy O'Toole（料理 / 400万follower）**
- 有名な「15 HOUR POTATO」は**52秒**で1,132万再生。だが**単発のひらめきではなく
  『25 days of potato recipes』連載の25本目**。
- さらに**1年後にコメント返信の形で作り直した2本目が2,264万再生と本家を超えた**
  （caption「Reply to @lfor05 The new and improved 15 HOUR POTATO recipe…」、47秒。
  中身は油をduck fatからbeef drippingに替えただけの改訂版）。

**Miss Excel（Excel講座）**
- 型は**14秒**。グリーンバック合成で**自分の頭の上にExcel画面を浮かせ**、曲に合わせて
  踊りながら操作を見せる。1本につき学習目標は必ず1つだけ。
- 4本目のXLOOKUP解説はDMXの「X Gon' Give It to Ya」に乗せた（XLOOKUPのXと曲名のXを
  掛けている）。Drakeの「left foot up, right foot slide」でLEFT関数/RIGHT関数、など。
- **10本まとめ撮りして1日1本ずつ出す**運用。3週間後に1本が24時間で360万再生、
  follower 10万に到達。

**Tanner Leatherstein（高級バッグ解体）**
- 開幕の問いが毎回同じ「**Is it worth it?**」。そこから縫い目を切り、パネルを剥がし、
  革にアセトンをかけて表面を削る。
- 終盤で原価を積算して定価と並べ、オチは必ず**3択のどれか**（not worth it /
  good but overpriced / worth it）。Louboutin回で740万再生（Wired 2024年11月時点の
  引用値。実測できたのは平凡な回1本のみ）。

**この6人から抽出できるもの**（切り抜きへ転用できる形で）:

1. **尺は流行ではなく題材が決めている**。14秒（Miss Excel）から4分46秒（McFarland）
   まで散っており、「短くしろ」は普遍則ではない。**題材が持つ長さに合わせる**。
2. **毎回同じなのは「開幕の一句」「締めの一句」「画角」の3つだけ**。中身は毎回違って
   よく、固定するのは入口と出口と絵。切り抜きなら「〇〇の配信より」という定型の入り、
   固定のテロップ様式、固定の締め方が同じ役割を果たす。
3. **跳ねた1本が「他人への返信」だった例が複数**（Mercuryの初バズ、Poppyの改訂版）。
   commentへの返信は新規動画として配信されるので、切り抜きでも最も安い増幅手段。
4. **当たりは連載を回している最中に出ている**。Poppyの15時間ポテトは25日連載の25本目
   （これだけが「代表作＝連載回」と実測で言える）。Miss Excelは10本まとめ撮り→1日1本の
   連載運用の最中に別の1本が跳ねた。McFarlandは1足の修理を5分割する連載型を常用しつつ、
   代表作は別の単発回。いずれも**単発の傑作を狙ったのではなく、回している最中に
   当たりが出ている**。
5. **演出は足していない**。Keith Leeは無音・無filter、McFarlandは無言。
   BGMは煽り方ではなく題材への合わせ方で選ばれている。

注意: 成長期はいずれも2020〜2022年のplatform拡大期を含み、現在は同じ戦術でも到達規模が
一段小さくなる前提で計画する。【中】

### 5.3 「連載の型」の実例と摩耗の仕方

反復可能なseries formatは§5.2で繰り返し出てきた要素なので、実測値のある2例で分解する。

**Fowlerville図書館「One-Star Review Guess Who」**（★1レビューを読んで本を当てさせる）
- 画は**書架の前で司書がカメラ目線に立ち、実在の★1レビューを読み上げるだけ**。
  書名は伏せ、読み上げ中のレビュー文がテロップで乗る。
- **2本1組**の構成: 問題編（60〜100秒）→ **翌日に答え合わせを別動画で出す**。
  答え合わせは**コメント返信機能で投稿**するので、視聴者のコメントが画面に貼られた
  状態から始まる。
- captionは毎回定型「EPISODE 87!!! Comment your guesses and we'll post the reveal
  tomorrow!」。series専用hashtagを毎回固定で付け、bioの1行目にもseries名を置く。
- 実測: EP87（2023年）は**72秒で169.6万再生・comment 4,522件・share 36,992件**。
- 答え合わせ回は21〜22秒で5,700〜14,000再生だが、**実測できたのは2024年の失速期の
  回だけ**で、同時期の問題編（EP121=1.19万、EP137=6,110）とほぼ同水準。つまりこの
  数字は「本編は当てに行き答え合わせは安く済ませる分業」の証拠にはならず、単に
  format全体が失速していただけの可能性が同じだけ残る。【低】
  **持ち帰るのは数字ではなく形の方** — 問題編と答え合わせを分け、答え合わせは
  コメント返信機能で出すという構成そのもの。
- **摩耗も実測できた**: EP32（2022/6）10.4万 → EP87（2023/6）**169.6万** →
  EP121（2024/2）1.19万 → EP137（2024/7）6,110。1年でピークの1/100以下。
  同時に**尺が60→72→101秒へ肥大**し、captionには
  「Ok, did this post now?? We've been struggling to post this since last week 🤨」と
  **投稿の周期が守れなくなった自白**が入り始める。検索で確認できる最終回は2024年8月の
  EP141前後で、以後の投稿は確認できなかった。【中】

**SubwayTakes**（地下鉄で持論を聞く）— 摩耗への対処が対照的
- 画は**地下鉄の座席に並んで座る固定の絵**。マイクは交通カードに挟んだ小型mic。
  第一声は毎回「**So, what's your take?**」、受けは「100 percent agree / disagree」。
- **caption＝回数＋その回の主張そのもの**（「Episode 739: Steak is the most overrated
  food of all time!!」）。実測138秒で104万再生。
- 743回まで続いている。**型は変えずに、本数・土地・ゲストだけを差し替えている**:
  週2本→週4本へ倍増、舞台をNYC→Chicago（"L Takes"）→London（"Tube Takes"）へ移植、
  ゲストを一般乗客から著名人へ拡張。【高】
  ただし**これが摩耗対策として意図されたものかは本人発言で確認できていない**
  （単なる成長施策の可能性がある）【中】。読み取れるのは「型を変えずに743回まで
  続いている」という事実の方。

**「答えを求める型」と「ただ切った型」で反応が2桁違う**【中】（言語圏・規模が違う
横比較なので交絡はある）:

| 動画 | 再生 | comment | share |
|---|---|---|---|
| Fowlerville EP87（答えを当てさせる） | 169.6万 | 4,522 | 36,992 |
| SubwayTakes EP739（立場表明を迫る） | 104.4万 | 1,698 | 7,696 |
| 令和の虎 切り抜き（面白い場面を見せて終わる） | 46.0万 | 47 | 32 |

前二者はcaptionで**行動を明示的に指定している**（「Comment your guesses」）。
切り抜きでcommentを増やしたいなら、面白い場面を出して終わるのではなく、
**答えや立場を要求する枠**を1つ作る必要がある。

**日本の切り抜きの連載の背骨**は「通し番号」と「名場面/名言集」という固定名詞【高】。
令和の虎の切り抜きは志願者の通し番号をそのまま連載番号に使っている
（caption「歌もダンスも教えない演劇ジム【令和の虎729人目】」111秒・46.0万再生）。

### 5.4 組織account（構造だけ転用する）

- Duolingo: 5万→1,600万follower。宣伝より娯楽を先に置く・一貫した人格・comment欄を
  企画の源泉にする。【高】 2025年4月のAI-first宣言で炎上しfollower約40万減
  【低】（数字は単独source。炎上と投稿全消去の事実は複数source一致【高】）。
  ただし直後の決算は好調で「炎上=事業毀損」と単純化は
  できない。教訓は「発信人格と実際の行動の一致が信頼の担保」。
- Washington Post: 担当者個人（Jorgenson）の退職でWaPo系のYouTube再生が85%減。
  **視聴者はbrandではなくcreator個人に付く**。【高】
- 図書館（Fowlerville等）: 「One-Star Review朗読quiz」という**単一formatを約3年・
  137回以上反復**して10万follower級（§5.3に実測）。反復可能なseries formatを1つ確立
  するのが小規模の最短経路。【中】
- 横断5法則: (1)娯楽が先 (2)一貫した人格 (3)comment欄が企画書 (4)低予算でplatform
  文化に馴染む (5)反復formatを1つ。【高】（帰納。寄与度の分離検証は無い）

## 6. 日本からの投稿

- 日本のTikTok userは約2,700万人規模（定義により2,500万〜4,200万の幅）、25-34歳が
  最大セグメントで全年代化。10代の利用率66%。【中】
- 日本から投稿した動画の初期test配信は、投稿時IP・SIM・言語設定等の地域信号から
  **日本のuserに配られる**。【中】（第三者の一致。公式明文なし）
- 公式は言語・国設定を「低weight」と説明するが、それは設定値の話で、**contentの
  言語（音声・テロップ）が届く圏を実質規定する**。日本語トークの切り抜きは日本語圏に
  閉じる。海外reachを狙うなら、言語非依存の場面（リアクション・プレイ映像）か
  対象言語の字幕併記。VPN等の地域偽装は不安定でrisk。【高】（公式の低weight）/
  【中】（言語圏収束の機構は推測）
- 日本語の切り抜き実務guideの一致点: (1)その30秒だけで初見に伝わる完結性
  (2)冒頭1〜2秒で本題 (3)短い発話字幕（白＋縁取り・画面下1/3。テロップ＝上部の見出しとの分担は§3.4）(4)週2〜3本以上の
  継続 (5)KPIは完走率・フォロー率・comment (6)「ライブ→切り抜き→次回告知→ライブ」の
  循環導線。【高】（複数source一致。A/B検証データは無い）

## 7. AI加工と有料増幅

### 7.1 AIGC label（このtoolのAI高画質化・字幕への影響）

- label義務の対象は「**realisticに見える人物・場面を描くAI生成または大幅編集**」に
  限定。【高】（公式Community Guidelines原文）
- **AI高画質化（upscale）・AI字幕・自動編集はlabel義務の対象として挙げられて
  いない**。第三者解説も一致して対象外扱い。ただしTikTok公式に「upscaleは対象外」の
  明文はない（YouTubeは明文で除外）。実写配信のupscale・字幕焼き込みは「何が
  起きたか」を変えないため安全側。顔が別人に見えるレベルの強いAI復元はgrey zone。
  【中】（推論を含む）
- 自動検出の主経路はC2PA metadata（DALL-E等の商用生成toolが埋め込む）。ffmpeg／
  PyTorch系の自前pipelineはC2PA manifestを付けないため自動labelは発火しにくい。
  【中】（機構からの推測。実測ではない）

### 7.2 有料増幅（Promote / Spark Ads）

- Promoteは300円/日から使えるself-serve増幅。**「他の非promote動画のviewに影響
  しない」と公式が明言**（悪影響説の否定）【高】（公式の自社主張。第三者の統制実験は
  無い）。「効果は出稿中にほぼ閉じ、積層しない」は日本語圏解説の整理【中】で、
  公式は「終了後もsome positive effectsが続く」とする。
- 切り抜きでの注意: (1) 音源を含む動画は**広告審査で落ちやすい**（投稿はOKでも
  広告NG。配信の生音声は差し替え不能なことが多い）【高】 (2) unoriginal判定による
  FYF非適格は金で解決できない【中】。
- 使うなら、編集の独自性を確立した後、organicで手応えのあった動画への小額test
  （$10〜30）に限る。立ち上げ期の主戦力にはならない。【中】（実務推奨の統合）

## 8. このtoolとの接続

調査結果と既存機能の対応。実装済みの機能が定石とどう噛み合うか。

| 定石（本レポート） | toolの現状 | 示唆 |
|---|---|---|
| chat/reaction spikeで山場選定（§3.5） | 盛り上がり検出＋short生成が実装済み | そのまま定石に合致 |
| 9:16縦型 | 配信が元々9:16でreframe不要 | 世間のclip制作で最も重い工程が不要という優位 |
| 冒頭に山場を先出し（§3.1） | short生成は`peak_position`既定0.65（見せてから山） | 「山の0.5〜1秒を冒頭へ先出し→文脈へ戻る」構成のoption追加は検討価値あり |
| 15〜30秒（§3.2） | clip_presetsで尺の型を定義可能 | 15-30秒中心の型を既定に。30-60秒の谷を避ける |
| 字幕・テロップ（§3.4） | 字幕焼き込み（PIL・カラー絵文字対応）実装済み | 焼き込みは見出しに寄せ、発話字幕はapp内自動字幕へ回すhybridも検討。ただし**TikTokは.srt/.vttのuploadを受け付けない**ので既存の文字起こしをtext層へ流す経路は無く、app内で生成し投稿前に直すしかない。safe zone（x=60〜880 / y=280〜1400）をtemplateに反映 |
| 無音・言い淀みを詰める（§3.3） | tighten（無音詰め）実装済み | そのまま合致 |
| BGM除去で音源検出risk低減（§2.3） | MossFormer2_SE_48Kの出力option実装済み | 切り抜きのTikTok投稿では常用を推奨。ただし検出回避の保証は無い |
| 検索keyword（§4.3） | clip_meta（AI metadata）実装済み | caption 1行目に「配信者名＋話題」。coverにも配信者名を文字で入れる |
| unoriginal回避（§2.1） | 未対応 | 出力前に**画面内watermark・配信UI・QRの検査**、および「発話字幕だけの成果物」を投稿経路から塞ぐ関門 |
| 重複区間の排除（§2.2） | 未対応 | **これが切り抜き運用で最も現実的な重複risk**。同一録画から複数clipを出す際に切り出し区間の重なりを機械的に検査して弾く（定型intro/outroカードの方は問題ない。§2.2） |
| 出力尺を揃える（§2.2） | clip_presetsで型を定義可能 | 定型カードを入れるなら、動画の尺がばらつくほど重複判定のcoverage比が振れる。型ごとに尺を揃える |
| 候補の抽出と順位付け（§5.1） | 実装済み | 完成品の自動生成ではなく「候補を30〜60個出して人が10秒で採否」の形が業界の実勢 |
| 連載の型（§5.3） | 未対応 | 「同じ枠で中身だけ差し替える」連載を回すなら、型ごとに素材を溜める場所（既存のグループ棚が使える）と通し番号の管理が要る |

**検出条件への落とし方**（以下は実装者向けの数値案。閾値はどのsourceにも無い当方の案で、
実配信での較正が要る。LU＝loudness unit、音量の単位。bbox＝顔検出の矩形）:
感情の頂点＝直近120秒のloudness中央値に対しshort-term loudnessが+8LU以上、または
笑い声検出（既存の笑い声一覧機能）。予測不能な反転＝0.3秒以内のloudness立ち上がり＋
顔bboxの急な移動。視聴者との掛け合い＝文字起こし中の読み上げ語（「コメント」「〜さん」）＋
直後10秒の笑い/音量peak。chatの反応＝コメント/秒が直近10分の中央値の3倍超（反応は
遅れて来るのでclip始点はspikeの8秒前）。giftの山＝秒間金額が上位1%かつ直後15秒に発話。
勝敗の決着＝battle窓のスコア確定時刻の-10〜+5秒。加えて全候補に**自己完結性penalty**を
掛ける（clip始点から3秒以内の発話が指示語で始まるならスコアを下げる＝§3.5の
「初見に伝わるか」の機械化）。


## 9. 制作チェックリスト

各項目は**「そうなっている」状態**を書いてある。詳細と根拠は括弧内の節へ。
確度は参照先の節の【高】【中】【低】に従う（safe zoneのpxやテロップの寸法は出典・
計測法が不明な第三者guideの値なので、実機で一度は目視すること）。

**§9.1は最初に一度だけ**、**§9.2〜§9.9は1本ごと**、§9.10は投稿後、§9.11は週次。
§9.1で型を決めてしまえば、1本ごとに見るのは10項目程度で済む。

所要時間の目安は§5.1に置いた。**手作業の実測は20〜30分/本**で、「15分」はvendorの
目標値であって実勢ではない。ただし内訳を見ると、時間を食う上位3つ（素材探し・
9:16への変換・字幕）は自動化できる部分で、このtoolは**9:16への変換が元から不要**なうえ
盛り上がり検出と字幕焼き込みを持っている。**残るのは採否の判断・冒頭の作り直し・
caption/cover・投稿**で、ここは人手が残る。

### 9.1 最初に一度だけ（accountと型を決める）

**account**

- display nameに「切り抜き」「Clips」等、**fan/clip accountである旨が入っている**（§2.2）
- 投稿後にcaption・coverを編集できるか実機で確認した（仕様変更が頻繁）（§10の週0）
- 動画別インサイト→traffic sourceの場所を把握した（§4.5）
- Playlistが使えるか確認した（follower 1万超が条件）。使えるなら**軸を1本に決めた**
  （複数配信者なら配信者名、単一配信者なら企画名。各動画は1つのPlaylistにしか入らない）（§4.4）
- follower 1万未満の間は、profileへのピン留め（最大3本・follower要件なし）を使っている（§4.4）
- **Creator Search Insightsで監視配信者名の検索volumeを確認した**。出ない名前は
  検索SEOの対象外と割り切り、caption 1行目の先頭をゲーム名・作品名に回す（§4.3）

**字幕の方式を決める（重要な二択）**

- 発話字幕を「**app内の自動字幕**」か「**焼き込み**」のどちらにするか決めた。
  **併用しない**（両方出すと画面下1/3で重なって両方読めなくなる）（§3.4）
  - app内字幕を選ぶ → 焼き込みは**上部の見出しテロップだけ**にする
  - 焼き込みを選ぶ → app内字幕はONにせず、**説明文に発話の要点を書いて検索textを供給する**

**型（寸法・尺）を決める**

- 尺の型を宣言した（**15〜30秒**を基本、題材が長さを要求するなら**2〜3分の別系統**。
  30〜60秒の谷は選ばない）（§3.2・§5.2）
- 発話字幕を焼き込むなら: 1行8〜10全角字・最大2行・文字高65〜86px・白＋黒縁（§3.4）
- 見出しテロップ: 1画面32全角字まで・文字高110〜130px・2〜4秒表示・1本に2〜5枚（§3.4）
- 縁取りが文字サイズの5〜10%（4〜8px）。背景が複雑なら黒帯（不透明度50〜70%）（§3.4）
- 動画全体の色数が4色以内（白・黒・グレー＋accent 1色）（§3.4）
- ASSなら 字幕 Fontsize=76〜86 / Outline=5 / Alignment=2 / MarginV=480〜520、
  見出し Fontsize=110〜130 / Alignment=8 / MarginV=300（§3.4）
- 連載の型を1つ決めた（毎回同じ「開幕の一句」「締めの一句」「画角」。中身は毎回違う）（§5.2・§5.3）
- **答えや立場を要求する枠**を型に組み込んだ（実測でcomment・shareが2桁多い型。
  ただし言語圏・規模の交絡は未統制【中】）（§5.3）

### 9.2 素材を選ぶ（どの瞬間を切るか）

- 山場が4類型のどれかに当たる: **感情の頂点** / **視聴者との掛け合い** /
  **自分や身内への嘲笑（ファン制作物への本人リアクション）** / **予測不能な反転**（§3.5・§5.1）
- **冒頭3秒の発話が指示語（それ・あれ・さっきの）で始まらず、前提説明なしで通じる**（§3.5・§8）
- 際どい発言・危険行為・性的示唆を含まない（含むとFYF非適格になり得る【中】）（§2.4）
- 歌唱区間なら、背後に原盤（市販音源・カラオケ音源）が無い＝生伴奏・a cappellaに限る
  （それ以外の歌枠・カラオケは原則やらない）（§2.3）

### 9.3 範囲を決める

- §9.1で宣言した尺の型の範囲に収まっている（§3.2）
- **山場の0.5〜1秒が冒頭に先出しされ、そこから文脈へ戻る**（オチを完全に前出しして
  後が空になるのは失敗例）（§3.1・§3.5）
- 挨拶・前置き・状況説明から始まっていない（§3.1）
- 最初の1秒に音か動きがある（§3.5）
- **同じ録画から出す他のclipと時間区間が重なっていない**（§2.2。機械検査できる）
- 無音・言い淀みを詰めてある（ただし笑い・感動系は余韻を残す）（§3.3）

### 9.4 画面（毎回の目視）

- **文字と顔が x=60〜880 / y=280〜1400 の帯に収まっている**（1080×1920。
  すなわち上280px・下520px・左60px・右200pxを空ける）（§3.4）
  - 参考の余白表記は上130〜250px・右64〜180px・下320〜480pxだが、**上の帯の方が
    厳しいのでそちらに寄せる**。どちらも出典・計測法が不明な第三者guideの値（§3.4）
- **1フレーム目にテロップがある**（後出しにしていない）（§3.5）
- 同時に出ている文字要素が2つ以内（見出し＋字幕）（§3.4）
- 発話字幕の位置が動画を通して動いていない（視線を探させない）（§3.4）
- 1つの字幕の表示が1.2〜1.5秒以上ある（§3.4）
- 字幕の切れ目が句読点・助詞境界で、1 cueが20字を超えていない（時間で機械分割しない）（§3.4）

### 9.5 originality（FYF非適格を避ける）

公式が認めている「加え方」を**最低1つ**満たしている（§2.1）:

- 自分が画面に登場している、または自分のnarration（voice-over）が入っている
- 配信日・直前の文脈など背景情報がテロップで入っている
- 時系列を組み替えるなどの再構成をしている
- replay・zoom・矢印で注目点を指している

そのうえで:

- **発話の書き起こし字幕だけで済ませていない**（それ自体が公式のNG例）（§2.1）
- 画面内に他platformのwatermark・logoが無い（§2.1）
- 配信画面のUI（LIVE badge・gift banner・視聴者数）が写っていない（§2.1）
- **QR codeが写っていない**（§2.1・§2.2）
- 静止画・動きの乏しい画だけになっていない（still-frame判定）（§2.1）
- watermarkをぼかす・枠で隠すなどの回避をしていない（§2.1）
- 上下の余白を他人の別映像で埋めていない（他人の映像を敷くのは公式が名指しする
  sandwich frames。「自分のtext帯・背景色で埋める」の方は**当方の解釈**で公式の線ではない）（§2.1）
- 素材にTikTok appの「Save video」で書き出した動画（透かし入り）を使っていない（§2.1）
- AI合成音声（AI narration）を使っていない（§2.2の別系統の判定項目に挙がっている。
  使うなら§7.1のlabel義務の範囲を実機で確認する）

### 9.6 音

- 配信中の市販BGMをBGM除去で落としてある（ただし**除去＝非検出の実証は無い**【中】）（§2.3）
- 音を足すならTikTok app内の音源で付ける（外部で焼き込まない）（§2.3）
- 他の投稿と同じloudnessに正規化して書き出した（§3.5）

### 9.7 導線カード（入れる場合）

- **末尾に置いてある**（冒頭はslow introとして公式が非推奨）（§2.2）
- カードを含めた尺が、同じ型の他の投稿と揃っている（§2.2）
- QR codeを含んでいない（§2.2）
- 「フォローでギフト」「相互フォロー」等の見返り提示が無い（§2.2・§2.4）
- 「公式」「Official」等、本人accountと誤認させる表記が無い（§2.2）
- 商品購入への外部誘導が無い（§2.2）

### 9.8 AI加工（使っている場合）

- AI高画質化・AI字幕・自動編集は、公式のlabel義務の列挙に**挙がっていない**＝
  現時点ではlabel不要と判断している（ただし**公式に「upscaleは対象外」の明文は無い**）（§7.1【中】）
- 顔が別人に見えるレベルの強いAI復元はgrey zoneなので、labelを付ける側に倒した（§7.1【中】）

### 9.9 書き出し・投稿する

- 9:16・1080×1920で書き出した（§3.4）
- caption 1行目（冒頭30〜40字）に **配信者名＋話題** が入っている
  （検索volumeが無い配信者なら、ゲーム名・作品名を先頭に）（§4.3）
- 「爆笑」「神プレイ」等のシーン描写語をcaptionに入れていない（冒頭テロップへ回す）（§4.3）
- **説明文を1〜2行に抑えた**（長いと下部のsafe zoneを侵食する）（§3.4）
- coverに配信者名が文字で入っている（§4.3）
- §9.1で選んだ字幕方式に従っている
  （app内字幕なら生成して固有名詞の誤字を直した。**投稿後は編集できないという報告がある**
  ので投稿前に済ませる／焼き込みならapp内字幕をONにしていない）（§3.4）
- hashtagが3〜5個（**第三者の慣行**で公式の数値ではない）で、うち1つは配信者名。
  #おすすめ 等の内容と無関係な汎用tagを付けていない（汎用tagが公式NGに当たるというのは
  **当方の解釈**）（§4.3）
- TikTokが自動付与したkeywordを点検し、的外れなものを外した（§4.3）
- captionに**行動を指定する一句**がある（「どちらだと思う?」「答えはcommentで」等。
  見返りを提示するengagement baitではなく、内容に紐づく問い）（§5.3・§2.4）
- 投稿直後に自分で1件目のcommentを入れた（出典＋文脈＋軽い問い）（§4.5）
- 同日に複数出すなら、連続する2本の配信者が違う（§4.1）

### 9.10 投稿した後

- **その動画のインサイトに「Ineligible for recommendation」表示が無い**（§2.1）
- **音声がmuteされていない**（「Change sound」promptが来ていない）（§2.3）
- 完視聴率とshareを記録した（view数の単発の上振れで判断していない）（§4.5）
- 伸びなかった動画を消す前に、インサイトで制限表示の有無を確認した（§4.5）
- 出し直す場合: **旧版を先に非公開にし**、冒頭5秒・voice-over・テロップを全て
  差し替えた（同じ動画をそのまま再投稿していない）（§2.1・§4.5）
- flagされた場合: appeal本文に (1)素材の出所 (2)自分が加えた要素
  (3)第三者watermarkが無いこと (4)再審査依頼 を書いた（§2.1）
- **2本連続でflagされたらappealを積むのをやめ**、§9.5の加え方でtemplateを作り直した（§2.1）

### 9.11 週次で見る

- **48時間後と1週間後にAccount checkを回した**（Postsタブが赤くない）（§2.1・§10の週0）
- 週2〜5本を維持できている。宣言した「1日N本」を守れている（Nを変えたら2週間は固定）（§4.1）
- 在庫をまとめ出ししていない（1配信から一気に出さず、毎配信後に1本ずつ）（§4.1）
- 不在の週を、TikTok Studio web版の一括upload＋予約投稿で埋めた（§4.1）
- **上位3本のview**で評価している（中央値は頻度では動かない）（§4.1）
- 今週変えた変数が1つだけ（§4.5）
- 先週付いたcommentに返信した。requestがあれば**reply with video**で応えた
  （originality要件も同時に満たす）（§4.5）
- **次のLIVEの直前に切り抜きを1本投稿した**（公式が推奨するLIVE導線。
  followerへの自動通知は当てにしない）（§4.6）
- traffic sourceの検索比率が育っているか見た（§4.3・§4.5）
- traffic sourceの「フォロー中」が意味のある比率になったら、follower activityを見始める
  （立ち上げ期は見ない）（§4.2）
- 連載の型（開幕の一句・締めの一句・画角）が崩れていない（§5.2・§5.3）
- **摩耗の兆候が出ていない**: 尺が肥大していない、投稿の周期が守れている（§5.3）

| 週1〜4 | 型を固定して週2〜5本。字幕・冒頭先出し・15〜30秒。歌枠・際どい場面は避ける。**投稿ごとに自分で1件目のcommentを入れる**（出典＋文脈＋軽い問い） | 完視聴率とshareのbaselineを取る。中央値でなく上位3本で見る |
| 週5〜8 | 1変数ずつ変えて比較（hook構成→尺→テロップ量）。**連載の型を1つ決める**（§5.3。毎回同じ入口・出口・画角を固定し、中身だけ差し替える。可能なら「答えや立場を要求する枠」を作る） | baseline比で完視聴/shareが動くか。連載回のcommentが増えるか |
| 週9〜13 | 当たった型に集中。Creator Search Insightsで配信者名の検索需要を確認し、caption・coverのkeywordを整備。follower 1万を超えていればPlaylistを配信者別に整備 | traffic sourceの検索比率、配信への流入 |

途中でFYF非適格の通知が来たら: Account checkで状態を確認し、appeal（Creator
Rewards側の判定は80日以内。FYF通知のappeal期限は未確認）＋編集の付加価値を増やして
クリーンな投稿を継続する。数週間の実績が回復に効くという観測がある。【中】

## 11. 用語注釈

### 指標・配信の仕組み

| 用語 | 意味 |
|---|---|
| impression | 動画がuserの画面に表示された回数。本レポートで「伸ばす」対象 |
| reach | 動画が届いたuserの数。impressionは回数、reachは人数 |
| For You feed（FYF） | appを開いて最初に出る「おすすめ」欄。followしていない人にも配信され、TikTok視聴の大半を占める |
| interest graph | follow関係ではなく「何をどれだけ見たか」からuserの興味を推定して配信先を決める方式 |
| ranking signal | おすすめ順を決めるためにalgorithmが見る行動データ（完視聴・share等） |
| watch time | 視聴時間。完視聴（最後まで見る）とrewatch（繰り返し再生）を含む |
| completion rate（完視聴率） | 最後まで見られたviewの割合 |
| engagement | like・comment・share・保存などの反応行動 |
| engagement率（ER） | engagementの発生割合。**分母がviewかfollowerかで結論が真逆になる**ので必ず確認する（§4.6）。TikTokの業界標準はview基準 |
| Following feed | followしている人の投稿が並ぶ欄。TikTokではviewの2%しか生まない（§4.6）|
| bulletin board | followerへ自動通知が飛ぶ公式機能。follower 5万で解禁。LIVE告知に使える |
| save | 「保存」（bookmark）。後で見返す意思を示す強い興味のsignal |
| test配信（視聴者pool） | 新規投稿をまず少数のuserに配って反応を測り、成績次第で配信を広げる仕組み（§1） |
| traffic source | 視聴の流入元の内訳（For You／検索／profile等）。TikTok analyticsで見られる |
| search value | 検索経由で見られる価値。Creator Rewardsの報酬算定4指標の1つ |
| organic | 広告費をかけない自然な配信・伸び |
| viral | 拡散によって爆発的に再生が伸びること |
| similarity check | 推薦の最終工程で「似すぎた動画（例: 同じsound）」を別の動画に差し替え、1人のfeed内の多様性を保つ仕組み。自分の似たclip同士が食い合う原因 |
| パーセンタイル（p90など） | 小さい順に並べたときの位置。90パーセンタイル＝上位10%の水準。頻度の効果は中央値ではなくここに出る（§4.1） |
| 学術audit | 研究者が実験用account（bot）でalgorithmの挙動を外部から検証する研究 |

### 判定・制限

| 用語 | 意味 |
|---|---|
| FYF非適格 | 動画は削除されないが「おすすめ」に載らなくなる状態。検索・profileからは見られる |
| Ineligible for recommendation | 上記の画面上の実際の表示。理由欄は「Unoriginal, low-quality, and QR code content」 |
| Account check | account全体と直近30投稿の状態を一括scanする公式機能（TikTok Studio → More tools）|
| unoriginal content | 独自の創作的編集が無い転載・再利用と判定されたcontent。FYF非適格の対象 |
| minimal edits | filterを掛ける程度の軽微な編集。これだけではunoriginal判定を回避できない |
| voice-over（narration） | 素材の上に重ねる自分の語り。公式が挙げる「originalと認められる加え方」の筆頭 |
| sandwich frames | 映像の上下に無関係な別映像を敷いて自動照合をずらす手口。公式が名指しで禁止 |
| audio fingerprint | 音声から作る指紋。同じ録音かを照合する（楽曲権利の照合に実在。§2.3）|
| embedding | 動画や画像を「意味の近さ」を表す数値の並びに変換したもの。bit列の一致ではなく近さで照合するので、色や速度を少し変えても近いままになる（§2.2）|
| perceptual hash（pHash） | 見た目から短いbit列を作り、その差で似ているかを判定する古典的手法。まるごと転載には強いが、切り出しには弱い（§2.2）|
| ANN検索（近似最近傍探索） | 全件と比較せず、近いものを高速に絞り込む検索。大規模platformでは必須（§2.2）|
| de-duplication | 重複の排除。TikTok公式もこの語でcopy検出の存在を認めている |
| flagged audio | 権利者が利用を制限した音源 |
| mute | 音声だけ消されて動画は残る措置。音源検出時に最も多い |
| strike | 違反の累積カウント。溜まるほどaccount停止に近づく |
| ban | account停止 |
| appeal | 判定への異議申し立て |
| shadowban | 「通知なく配信を絞られる」ことの俗称。公式の制度ではない（§1俗説） |
| engagement bait | 「likeして」「follow返し」など反応を乞う手法。抑制対象 |
| borderline content | 削除まではされないが際どい内容（性的示唆・危険行為等）。おすすめから外される |
| Creator Rewards | TikTok公式の、再生数に連動した報酬program |
| RPM | 1,000再生あたりの収益額（Revenue Per Mille） |

### 制作・編集

| 用語 | 意味 |
|---|---|
| hook | 冒頭数秒で視聴者を掴む「つかみ」の仕掛け |
| open loop | 「答えは最後に」と期待を張って見続けさせる構成。本編で回収しないと釣りになる |
| cold open | 前置きなしで山場から始める構成 |
| seamless loop | 終端が冒頭へ自然につながり、気づかないうちに繰り返し再生される構成 |
| jump cut | 間・言い淀みを切り詰めるカット編集 |
| jumpscare | 突然の音と映像で驚かせる演出（ホラーゲーム等）|
| ASS | 字幕format。PlayResX/Y＝基準解像度、Fontsize＝文字サイズ、Outline＝縁取り、Alignment＝配置位置、MarginV＝縦の余白 |
| テロップ／text overlay | 画面上の文字入れ。字幕（発話の書き起こし）と見出し的な文字の2層で使う |
| caption | 投稿の説明文（動画の下に出る本文）。字幕の意味で使われる場合もあるが、本レポートでは説明文を指す |
| cover（表紙） | 一覧・profileで表示される表紙画像。公式が「トピックが明確に示される必要」と書く画像要素 |
| safe zone | TikTokのUI（右側のbutton列・下部の説明文表示等）と重ならない画面領域 |
| TikTok SEO | 検索で見つかるように、caption・テロップ・発話にkeywordを入れること |
| Creator Search Insights | 視聴者が何を検索しているかを見る公式tool。「コンテンツ不足」タブ＝検索は多いが良い動画が少ないtopic |
| niche | 狭い専門分野・題材 |
| series format（連載の型） | 毎回同じ枠で中身だけ差し替える反復可能な企画の形（§5.3）|
