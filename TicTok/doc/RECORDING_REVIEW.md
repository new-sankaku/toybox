# 録画の確認状態(観たかどうかの印)

配信者動画(`/videos`)の録画一覧で、録画1本ごとに **未確認 / 確認中 / 確認済** を付ける。
「この録画はもう観たのか」を画面から読めるようにするための印で、値はoperatorが手で動かす。

- 保存先: `recordings.review_state` (`'unchecked'`(既定) / `'checking'` / `'checked'`) と
  `recordings.review_updated_at`
- 書き換え: `PATCH /api/recordings/{recording_id}/review` — body `{"state": "checked"}`
- 読み出し: `GET /api/recordings/browse`(一覧)と `GET /api/recordings/{id}/path`(再生画面)

## 自動では動かさない

再生・焼き込み・切り出しのどれも印を進めない。開いた時点で「確認中」、末尾まで再生したら
「確認済」と自動化すると、少し覗いただけ・流しただけの録画にも印が付き、印が**観た事実**を
指すのか**開いた事実**を指すのかが読めなくなる。既存録画の移行も同じ理由で全件`unchecked`
から始める(観たかどうかはDBのどの列からも導けないので、推測で確認済みを配らない)。

## 画面

| 場所 | 形 |
|---|---|
| シーン検索の録画一覧(検索語なし) | 行の先頭列のselect。行clickは録画を開く操作なので、印の操作は行へ伝えない |
| 再生画面の操作欄 | `確認` のsegmented control。一覧とどちらから変えても同じ値になる |
| toolbarの `確認` | 一覧の絞り込み。「未確認だけ出す」用 |

検索語がある間の行は録画ではなく**シーン**(同じ録画の別の位置が何行も並ぶ)なので、確認列は
隠し、絞り込みselectもdisableする。効かない指定を押せる状態で残すと、効いているように見える。

絞り込みは受け取り済みの一覧の上で行う(serverへ引き直さない)。件数は
`未確認 3本 / 録画 120本` の形で、絞った結果と一覧の総数を併記する。絞った先の件数だけでは、
録画そのものが少ないのか印で外れたのかが読めない。

## 一覧はページを開いた時点で出る

`/videos` は起動時に録画一覧を読む。以前は語を入れるまで「検索語を入力してください」のまま
だったため、当たる語を先に発明しないと1本も開けず、印も目に入らなかった。
