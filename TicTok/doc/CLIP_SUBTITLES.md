# 切り抜きに添える字幕file（sidecar）

切り出したmp4の隣へ、同じ名前で `.srt` / `.vtt` / `.ass` を置く。実装は
`tictok/media/clip_subtitles.py`、画面は動画画面の切り出し欄「字幕fileも出す」。

焼き込みとの違いは1つだけで、それが全てである。**映像を書き換えない。** 文言の直し・書体の
変更・位置の調整・翻訳が後からいくらでも効く。焼き込みは出した瞬間に確定する。

## どこに、いつ出るか

```
<一時保存先>/<配信者>/_clips/<mp4と同じ名前>.srt
```

置き場も名前もmp4に揃える（`CLIP_OUTPUT.md`）。NLEもplayerも「動画と同じ名前の字幕file」を
自動で拾うので、名前を変える理由が無い。

出るのは**切り出し（copy / smart / precise、BGM除去を含む）**の成果物に対してだけである。
除外したものと理由:

| 対象 | 出さない理由 |
|---|---|
| 焼き込み切り抜き（`clip_overlay`） | 映像に既に焼かれている。同じ文字を2枚重ねる意味が無い |
| short・作品（`work`） | 間の詰め・連結で時刻が組み替わる。原本の秒をそのまま添えると合わない |
| 連結（`reel`） | 同上（複数範囲を繋いだ1本） |
| 焼き込み出力・Up出力から切った切り抜き | 全編を再encodeした別のfileで、文字起こしの時刻が載っている保証が無い |

短く言えば、**時刻の対応が実測で分かっているものにだけ添える**。分からないものへ「それらしい
字幕」を出すと、誤りを検出する手段が無い。

## 原点は「要求した開始位置」ではない

ここがこの機能の全部である。

文字起こしの時刻は元録画のmedia軸（PTS秒）。切り抜きは元録画の一部なので、原点を引かずに添えると
開始位置ぶん丸ごとずれる。引くのは `make_clip` が返す `actual_start_seconds` ——
**成果物の先頭が指す元録画の時刻**であって、要求した開始位置ではない。

stream copyはkeyframeからしか始められないので、両者は常に食い違う（実測: 要求854秒に対し
実開始850.021秒＝3.979秒手前。過去には37.6秒の例もある）。要求値を引けば、その差がそのまま
全cueのズレになる。

### 実録画で確かめた

同じ範囲を copy と precise の2通りで切り、**同じ元録画の瞬間**で突き合わせた。copy側は
`t + lead`、precise側は `t` に同じ瞬間が居るはずである。

| 元録画の時刻 | copy側 | precise側 | 出ているcue |
|---|---|---|---|
| 858.0s | 7.979s | 4.0s | 一致（「ギょエーギャーゎエー」） |
| 862.0s | 11.979s | 8.0s | 一致（「魚縛りじゃない」） |
| 866.0s | 15.979s | 12.0s | 一致（「それで」） |
| 870.0s | 19.979s | 16.0s | 一致（「おーい」） |

原点に要求値を使っていれば、copy側だけが3.979秒ずれて1件も一致しない。併せて、preciseの
`t=8.0` のframeと原本の `862.0` のframeが同じ瞬間であることも確認した（切り抜きの軸が元録画の
media軸へそのまま写ることの確認）。

## 装飾

`.ass` は焼き込みのテロップpreset（`tictok/record/telop_styles.py`）をそのまま持つ。色・
内側の縁・外側の発光・影武者（ベタ影／色ずれ）・出入りのfade・pop・字間・傾き・折り返し・
画面上の縦位置まで、**焼き込んだ物と同じ層構成**で出る。

組み立ては `video_overlay.subtitle_ass_document()` の1箇所しかなく、Dialogueを作るのは焼き込みと
同じ `_build_subtitle_dialogues()` である。ここを別に持つと、焼き込みと添付fileで見た目の違う
字幕が出て、しかもどちらが正しいか誰も言えない。

座標系（`PlayResX/Y`）は**成果物の実寸**。焼き込みのように解像度を上げ直さない（重ねる先が
出来上がったmp4なので、寸法が違えばplayerが比で伸縮して位置も字の大きさもずれる）。

**書体は読ませる側に要る。** ASSは書体を名前で参照する形式なので、同梱fontが入っていない
環境では字面だけ別物になる。結果に書体名と同梱fileのpath（`assets/fonts/telop/...`）を載せて
あるので、そこからinstallすれば焼き込みと同じ見た目になる。

`.srt` / `.vtt` は書式そのものが装飾を持たない。編集ソフト・投稿siteへ渡す用途で、
書式は設定「切り出し: 字幕fileの書式」（`clip_subtitle_formats`）が決める。

### 改行

`.srt` / `.vtt` のcueは、意味の切れ目で折り返した複数行で出す（`SUBTITLE_LINEBREAK.md`）。
1行のまま渡すと読み手は折り返さず、縦画面では横へはみ出して端が切れる。折る位置は形態素解析で
決める —— 文字数だけで折ると、実データのcueの49.7%が語の内側で切れた。

### 先頭の錨

頭が無音の切り抜きでは先頭cueが0秒から始まらない。この形の字幕fileをNLEのtimelineへ
**dragで置くと、先頭cueが落とした位置へ吸着する**実装がある。DaVinci Resolveがそれで、
manualにも次のように書かれている。

> each title is added to the Timeline as an individual subtitle clip, **with its timing offset
> relative to the position of the first frame of the first subtitle in that file**

結果、頭の無音ぶんだけ全cueが早くなる（実測 2.584秒。1件目が0秒から出て、以降も同じ量ずつ
早い）。吸着させない入れ方（Media Poolで右click →
*Insert Selected Subtitles to Timeline Using Timecode*）もあるが、timelineの開始timecodeを
`00:00:00:00` にしておく必要があり、Resolveの既定は `01:00:00:00` である。

そこで `.srt` / `.vtt` は、先頭cueが0秒から始まらないとき**0秒へ空のcueを1件足す**
（`subtitles.anchor_cue()`）。中身は半角空白1つで字は出ず、長さは最長0.5秒。先頭cueの位置が
成果物の先頭と一致するので、dragで置いても時刻で差し込んでも同じ結果になる。

発話のcueは1つも動かさない。動かせば時刻の捏造になる。錨が足すのは「字の無いcue」であって
言葉ではない、というのが足してよい理由のすべてである。

`.ass` には足さない（開始時刻が絶対値として読まれるので吸着しない）。設定
「切り出し: 字幕fileの先頭に錨のcueを置く」（`clip_subtitle_anchor`）で止められる。

### 表示単位への分割

全書式に `subtitles.split_for_display()` を掛ける（焼き込みと同じ割り方）。whisperのsegmentは
1件が数十秒になることがあり、そのまま出すと1枚が画面へ居座る間ずっと別の言葉が喋られる。

録画丸ごとの書き出し（`/api/recordings/{id}/transcript/export`）も、字幕書式（SRT/VTT）は
同じ割り方で割る（`subtitles.render`）。txtだけは割らない —— あちらは原稿としても使うためで、
用途が違う。

以前は録画丸ごとの書き出しを一切割っていなかったが、それだと**無音の上に関係のないcueが
出続ける**。whisperはsegmentの終端を次のsegmentの開始まで伸ばすので、間の無音がcueに入る。

| 出し方 | SRTがtimelineを覆う割合（版2の文字起こし331件・中央値） |
|---|---|
| 語ごとの時刻を持たない文字起こし | 97.7% |
| 語ごとの時刻を持つ文字起こし、そのまま | 62.0% |
| 同上、`split_for_display` 後 | 48.4% |

実際の発話は録画の約30%（録画926でVAD実測 91.9s / 306s）。cueの長さもp99が12.04秒→3.90秒、
最大2100秒→29秒になる。

窓の端に掛かる発話は落とさず、時刻だけを内側へ詰める。切り抜きの中で確かに聞こえている言葉
なので、落とすと「聞こえているのに字幕が無い」区間ができる。textは切らない（どこで切れたかは
語の時刻を持たない文字起こしでは分からず、文字数で按分すれば時刻の捏造になる）。

**枚の境と行の折りは同時に決める。** 1枚に載る量に達した語でそのまま切ると、境が文の途中に
落ちるうえ、出来た枚が良い位置で折れなくなる。segment全体を見渡してDPで選ぶ（`SUBTITLE_LINEBREAK.md`）。
候補になる境は語の時刻がある位置だけなので、語も時刻も落ちない。

## 出さないときは理由を名乗る

黙って0件にしない。理由は結果（`subtitles.reason` / `message`）とlogに残り、画面に出る。

| 理由 | 意味 |
|---|---|
| `no_transcript` | この録画の文字起こしがまだ無い |
| `timemap_stale` | 時刻mapが現行版でない文字起こし。尺が伸びるほど後ろへずれるので添えない（再文字起こしが要る） |
| `not_source_variant` | 焼き込み出力・Up出力から切った切り抜き |
| `no_segments` | この範囲に発話が無い |
| `no_origin` | 実開始を測れなかった |

字幕fileの書き出しに失敗しても**切り出し自体は失敗にしない**（mp4は既に出来ており、消す理由が
無い）。ただし失敗はstack traceごとlogへ残り、画面にも理由が出る。

## 一覧・削除

字幕fileも「出力済みclip」tabに並ぶ（種別「字幕file」、書式つき）。この置き場はDBに行を
持たず一覧が唯一の台帳なので、走査から漏らすと出したfileがどこからも辿れない。

**mp4を消すと、それに添えた字幕fileも一緒に消える。** 字幕fileは単独では使い道が無く（時刻が
対のmp4の軸に載っている）、残すと消えた動画の字幕だけが並び続ける。逆向き（字幕fileだけを
消す）は成り立つので、そちらは1本ずつのままである。

## 設定

| key | 既定 | 内容 |
|---|---|---|
| `clip_subtitles` | 0 | 切り出し画面の「字幕fileも出す」の初期値。切り出しのたびに画面側で変えられる |
| `clip_subtitle_formats` | `srt,ass` | 出す書式。SRTのみ / SRT+ASS / ASSのみ / 全て |
| `clip_subtitle_anchor` | 1 | 先頭cueが0秒でないとき、0秒へ空のcue（半角空白・最長0.5秒）を足す。SRT/VTTのみ |
