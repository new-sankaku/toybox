# 字幕の改行位置

実装は `tictok/record/jp_wrap.py`。使うのは焼き込み（`video_overlay`）、切り抜きに添える字幕file
（`clip_subtitles`）、録画丸ごとの書き出し（`subtitles.render`）の3経路すべてで、同じ切り方をする。

## 症状は2つあり、原因は別だった

**画面からはみ出す** —— `to_srt()` はcueの中身を1行のまま書いていた。SRTはcueに複数行を書ける
書式だが、改行が無ければ読み手（CapCut・NLE・投稿siteのcaption取り込み）は折り返さない。縦画面へ
載せると横へ流れて端が切れる。

**意味不明な位置で切れる** —— 折り返しても、幅で溢れた所で機械的に切っていた。実録画53本の
文字起こしから作った表示単位 126,719件のうち、折り返しが要るのは 14,500件（11.4%）。その
**49.7% が語の内側**で切れていた。

```
現行 : 最近ポミさんの声聞くと涙が出るか / ら
現行 : 私やるんだったらポミ絶対1位取り / たいからさ
現行 : ずっと半端で終わらせたくないから / 辞退したいな   ← これは偶然合っている
```

## 方式の選定

物差しは「折った位置が形態素の内側か」＝明白な誤り。**自分以外の解析器**に判定させて循環を
避けている（fugashiの切り位置はSudachiPyが、SudachiPyの切り位置はfugashiが採点する）。
「文節一致」は両方が文節の頭と認めた割合、「ちぎれ行」は短い方の行が全角5字未満の割合。

| 方式 | 語内断裂 | 文節一致 | 行の不均衡 | ちぎれ行 |
|---|---|---|---|---|
| 文字数で折る（従来） | 49.7% | 9.5% | 12.31 | 63.0% |
| 規則ベース（辞書なし・字種＋助詞表＋禁則） | 11.0% | 68.9% | 5.27 | 14.1% |
| SudachiPy（mode C） | 7.2% | — | 3.34 | 2.9% |
| **fugashi + unidic-lite（採用）** | **3.4%** | **72.8%** | **3.75** | **3.8%** |

辞書を持たない規則（ひらがな→漢字/カタカナの変わり目＋助詞・接続詞の表）は文字数より遥かに
良いが、語内断裂が3倍以上残る。解析器2つの差は僅差に見えるが、fugashiの切り位置はSudachiPyが
96.6%認めるのに対し、逆は92.8%しか認めない。速度はどちらもcue 1件あたり0.05ミリ秒で、
実録画54本ぶん（135,062 cue）の全処理が5秒。**時間は判断材料にならないので品質で採った。**

解析器が無い環境で文字数へ落とすことはしない。落ちたことは成果物を再生するまで誰にも
分からず、元の症状へ静かに戻るだけである。無ければ導入方法を名乗って止まる。

## 切れ目の優先度

文節境界ならどこでもよいわけではない。品詞と活用形から点数を付ける（小さいほど良い）。

| 点 | 位置 | 例 |
|---|---|---|
| 0 | 句点の後 | `です。` \| `でも` |
| 1 | 読点の後 | `あのさ、` \| `マネージャーから` |
| 2 | 接続詞の前 | `でも` \| `あのさCキャッスル` |
| 3 | 接続助詞の後 | `申し訳ないから` \| `辞退しよう` |
| 4 | 係助詞・副助詞・終助詞の後 | `私は` \| `行く` |
| 5 | 格助詞・助動詞の後 | `ご飯を食べに` \| `行く` |
| 7 | それ以外の文節境界 | 副詞・連体詞の後 |
| 8 | 連体化の「の」の後 | 修飾語と被修飾語を引き剥がす |
| 9 | 自立語どうしが直に隣り合う | 複合語の内側でありうる |
| 10 | 付属語・補助用言の前 | `終わらせ` \| `たくない` は文節を割る |
| 12 | 形態素の内側 | 行の折り返しには使わない |

行頭に句読点・閉じ括弧・促音が来る位置と、結合文字・異体字selectorの直前は禁則として
候補から外す。

### 「非自立可能」は、そうであるとは言っていない

unidicの `非自立可能` は補助用言に**なり得る**という印にすぎない。束縛かどうかは直前の語の
**活用形**で決まる。

| 文 | 直前 | 判定 |
|---|---|---|
| `言って` \| `いたら` | 接続助詞「て」 | 補助用言。折らない |
| `終わらせたく` \| `ない` | 連用形 | 補助用言。折らない |
| `できなかったら` \| `やりに行く` | 仮定形「たら」 | 節が切れている。**折ってよい** |

活用形を見ずに `非自立可能` だけで束縛と決めると、3つ目まで折れなくなり
`まあでも辞体できなかっ / たらやりに行く` という切り方になる（実装中に実際に出た）。

## 切れ目の良さと、行の釣り合いの釣り合い

最小化するのは `切れ目の点数 × WEIGHT + 各行の目標幅からのずれ`。目標幅は `全体 ÷ 行数` なので、
2行なら「ずれの和」は行長の差そのものになる。行数は少ないほど良いので、収まる最小の行数を採る
（1行に収まる文は折らない）。DPで解く。

`WEIGHT` は実データで掃引して決めた。大きいほど意味の切れ目を優先し、行が不揃いになる。

| WEIGHT | 語内断裂 | 文節一致 | 不均衡 | ちぎれ行 |
|---|---|---|---|---|
| 0 | 7.3% | 42.2% | 1.35 | 0.1% |
| 1.0 | 4.3% | 66.9% | 2.57 | 0.6% |
| **2.0** | **3.4%** | **72.8%** | **3.75** | **3.8%** |
| 3.0 | 3.3% | 73.4% | 4.23 | 6.4% |
| 6.0 | 3.2% | 74.3% | 4.83 | 9.6% |

2を超えると、語内断裂が 0.1〜0.2pt しか改善しない一方でちぎれ行が倍増する。**2 が膝である。**

## 枚（cue）の割りと行の折りは、同時に決める

行内で折るだけでは足りない。1枚に載る量を超えた発話は次の枚へ送られるが、その境が文の途中に
落ちれば、折り返しを直しても読めない字幕になる。

さらに悪いことに、**枚の割り方が行の折り方を殺す**。枚が予算いっぱいになると1行目の許容幅が
数文字まで狭まり、そこに形態素境界が1つしか無ければ、それが文節を割る位置でも選ぶしかない。

```
最近ポミさんの声聞くと涙が出る      ← 全角30字。1行目は14〜16字に収まる必要があり、
からもう無理かなって思っている         その窓にある境界は「出る|から」だけだった
```

そこで `_plan_segment` が、segment全体を見渡してDPで次の合計を最小にする割り方を選ぶ。

- 枚の境の悪さ × WEIGHT — 境が文の切れ目に落ちているか
- **その枚を折るときの切れ目の悪さ × WEIGHT** — 折れない枚を作らない（`jp_wrap.layout_badness`）
- 予算の余り — 枚を無駄に短くしない（これが無いと細切れが最良になる）

候補になる境は**語の時刻がある位置だけ**である。文字数で按分すれば時刻の捏造になる
（`STT_SUBTITLE_TIMING.md`）。語と語の間が空いた位置（`DISPLAY_GAP_SECONDS` = 0.6秒）を跨ぐ枚は
作らない。**間そのものが話の切れ目**で、文字の並びより強い根拠である。

語が1つだけの枚は、上限を超えていても作る。語の内側には時刻が無いので割れず、ここで諦めると
segment全体が1枚に潰れる（実装中に実際に起きた: 予算30に対し幅62.5の枚が86件）。

### 貪欲・予算・行数は効かなかった

左から順に「上限に達したら切る」貪欲を基準に、4案を実データ135,062枚で比べた。

| 案 | 悪い切れ目 | 文節割り | 折返しが要る枚 | 所要 |
|---|---|---|---|---|
| 貪欲（上限まで溜めて最良の境まで戻す） | 9.8% | 2.7% | 10,923 | 4.2秒 |
| 割る段で折りやすさを先読み | 8.8% | 2.4% | 9,905 | 5.5秒 |
| 1枚の予算を30 / 28字へ | 9.7 / 9.6% | 2.7 / 2.5% | ほぼ不変 | — |
| 収まらなければ3行を許す | 9.8% | 2.7% | 不変 | — |
| **全体をDPで同時に決める（採用）** | **8.2%** | **2.3%** | **10,026** | 46秒 |

予算を詰めても効かない。狭まった窓に良い境界が現れるとは限らないからである。3行を許しても
効かない ——「2行に収まらない」のは折り返しの0.2%しかなく、問題は*収まらない*ことではなく
*収まる位置が1つしかない*ことだった。

DPが天井で、そこでも2.3%は残る。**許される幅の中にそもそも良い境界が無い**という意味である。

### 速度

2行への割りは `_two_lines` が1回の走査で解く。目標幅が全体の半分なので「各行の目標からの
ずれの和」は行長の差そのものになり、DPを組む必要が無い。枚を割る段が候補ごとにこれを呼ぶので、
畳まないと同じ計算をn倍繰り返す（実測 611 → 352 マイクロ秒/枚）。

実録画54本・133,806枚で47秒、1本あたり0.9秒。焼き込みは数分かかるので埋もれる。

## 読み手の画面に収まる余白

上限ちょうどまで詰めた行は、読み手の書体・字間・player側の内側余白が想定と少し違うだけで端が
切れる。SRT/VTTは**読み手が何で描くか分からない**書式なので、上限そのものを守っても収まる保証が
無い。焼き込みも、投稿先のUI（TikTokの右列icon）が被る。

`subtitle_safe_margin_percent`（既定6）を1行の幅と1枚の予算の**両方**から引く。片方だけだと、
予算いっぱいの枚が「余白を引いた行には収まらない」形で作られる。焼き込みは実測した帯幅
（`SUBTITLE_WIDTH_FRAC` = 0.90）からさらに同じ割合を引く —— 経路ごとに違う余白にすると、同じ
文字起こしから出した字幕の折り位置が経路で変わる。

**余白は切れ目の質と引き換えである。**

| 余白 | 実効1行 | 折返しが要る枚 | 悪い切れ目 | 文節割り |
|---|---|---|---|---|
| 0% | 16.00 | 10,026 | 8.2% | 2.3% |
| 3% | 15.52 | 12,669 | 9.6% | 2.9% |
| **6%（既定）** | **15.04** | **13,327** | **9.8%** | **2.9%** |
| 10% | 14.40 | 17,321 | 11.5% | 3.4% |

3%と6%は質がほぼ同じ（9.6% と 9.8%）で、値が要るのは余白を取るかどうかの一段目である。
6%は3%の倍の安全を0.2ptで買えるのでここを既定にした。10%は割に合わない。

実測では、6%の余白により公称上限16字を超える行が52本から17本へ減る。残る17本はいずれも
分割位置を持たない長いカタカナ列（文字起こしの誤り）で、語の内側には時刻が無いので割れない。

## 幅の測り方は経路で違う

| 経路 | 幅の単位 | 理由 |
|---|---|---|
| SRT / VTT | 全角換算の文字数 | 書式が書体を持たない。読み手が何で描くか分からない |
| 焼き込み・ASS | 実測した送り幅（px） | 描く書体が決まっている。文字数で折ると書体を変えた瞬間にずれる |

`jp_wrap.wrap()` の `measure` 引数で差し替える。**切れ目の選び方は同じ**なので、どの書式で
出しても文の切れ目は揃う。

焼き込みは折る前の生の文を解析器へ渡す。ASS escape後の文字列を渡すと、置換で増減した文字の
ぶんだけ語の位置がずれる。

## 設定

| key | 既定 | 内容 |
|---|---|---|
| `subtitle_chars_per_line` | 16 | 1行の文字数（全角換算・半角は0.5字） |
| `subtitle_wrap_lines` | 2 | 1枚の行数。掛けたものが1枚の文字予算 |
| `subtitle_safe_margin_percent` | 6 | 行の端に空ける余白 |
| `subtitle_max_seconds` | 3.0 | 1枚を出しておく秒数の上限 |

縦画面（1080x1920）で幅の9割を使うと、読める大きさのテロップは1行あたり全角15〜16字になる。
TikTok・Shortsでは2行までが読みやすく、3行以上は映像を覆う。

引いた後の値は `layout_from_settings()` が `per_line` / `max_chars` として返す。**引く前の値を
使う経路が1つでもあると、その経路だけ端まで詰まった行が出る。**

4つとも焼き込みのcache signatureに入っている。入れないと「1行の字数を変えたのに前の割り方の
ままcache hit」になる。

`video_overlay_subtitle_max_lines`（既定4）は別物で、**画面を覆わないための最後の関門**である。
折った結果がこれを超えた行は描かない。枚の予算が2行ぶんなので通常は働かない。

## 実データでの結果

実録画54本・133,806枚（既定の余白6%・枚1件あたり352マイクロ秒）:

- 枚の幅: 中央値 全角8.0 / p99 23.0 / 最大 30.0（＝予算ちょうど）
- 折り返しが要ったのは 13,327枚（10.0%）
- そのうち読みに影響する切れ目は 9.8%、文節を割ったのは 2.9%
- 実効幅を超えた行は 52本（0.04%）で、公称16字を超えたのは 17本。いずれも分割位置を持たない
  長いカタカナ列で、割る位置がdataに無い

折り返した13,327枚の切れ目の内訳（余白0%時の測定）:

| 切れ目 | 割合 |
|---|---|
| 句点の後 | 3.9% |
| 読点の後 | 6.8% |
| 接続詞の前 | 6.6% |
| 接続助詞の後 | 8.3% |
| 係助詞などの後 | 27.8% |
| 格助詞・助動詞の後 | 28.9% |
| その他の文節境界 | 6.3% |
| 連体の「の」の後 | 1.6% |
| 自立語どうし（複合語の内側かも） | 7.1% |
| 付属語の前（文節を割る） | 2.7% |
