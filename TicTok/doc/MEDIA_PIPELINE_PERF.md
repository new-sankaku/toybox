# 焼き込み・再mp4化の所要時間

計測環境: RTX 4070 Ti / 12 core / 録画は K:(HDD)。数値は実測で、比率だけを持ち出さないこと
(GPUと解像度で絶対値は簡単に数倍変わる)。

## どこで時間を使っているか

### 再mp4化 (reprocess)

| 段階 | 内容 | 律速 |
| --- | --- | --- |
| concat | .ts を1本のffmpegでmp4へ | **音声のAAC encode**。映像はstream copyなので隠れる相手が居ない |
| probe | 混在解像度の判定(keyframe走査) | disk。連結後mp4を頭から読み直していた |
| normalize | 混在時のみ単一解像度へre-encode | **NVENC** |

concatの内訳(46分/318MBの録画): 全体51秒のうち、両stream copyだけなら3.8秒。
音声decodeは3.4秒で、残り約47秒はすべてAAC encoder。
normalizeの内訳(同): 全体82秒のうち映像decode 22秒・scale/pad 5秒で、残りがNVENC。

### 焼き込み (overlay)

| 段階 | 内容 | 律速 |
| --- | --- | --- |
| layer | コメント層をPillowで描く | CPU(1本) |
| base | CFR baseのpre-pass | **NVENC** |
| encode | base+層+ASSを合成して本encode | **NVENC** |

layerとbaseは同時に走る。以前はbaseの方が長く(240秒 vs 120秒)、この段階はbase律速だった。

## 効いた修正

| 修正 | 効果(実測) |
| --- | --- |
| CFR baseを**元解像度**で作り、拡大は本passのgraphへ移す | base 178秒/2844MB → 35秒/1178MB |
| baseの`+faststart`を外す(捨てる中間fileにfile全体の書き直し) | 43秒(2.8GB時) |
| 解像度probeをconcatと**並行**で走らせる | 連結後mp4の再読(349MBで14秒、1.2GBで50秒)が消える |
| normalizeの音声をcopyに(concatが既にAACへ揃えている) | 6.5秒＋世代劣化1回ぶん |

### 通しの実測(1本ずつ)

| 対象 | 前 | 後 |
| --- | --- | --- |
| 焼き込み 31分/512x1024 → 1280x2560 AV1 | 457.1秒 | **308.8秒** |
| 再mp4化 46分/318MB(混在解像度) | 160.4秒 | **138.3秒** |

焼き込みの内訳は、層+baseの準備が240.6→97.8秒、本encodeが211.5→209.3秒。
残りの本encodeはAV1 NVENCが1280x2560を回している時間で、ここは品質設定そのもの。

再mp4化の内訳は、concat 56.7→55.4秒(probeを内側に畳んでも延びない)、probe 14.3→0秒、
normalize 89.3→83.0秒。

### 出力の同一性

焼き込みの出力は前後でSSIM 0.989〜0.993(8秒窓×3箇所)。解像度・frame数・尺は一致。
中間の圧縮位置が変わるぶんの差で、上の非圧縮基準の比較(CQ14で0.9958 vs 旧0.9957)が
「元の絵からの距離は変わっていない」側の根拠になる。

### 元解像度baseの品質補正

拡大を後段へ回すと、中間fileの誤差も一緒に拡大される。非圧縮の拡大を基準にしたSSIM
(31分/512x1024 → 1280x2560、8秒窓):

| 経路 | SSIM |
| --- | --- |
| 旧: 拡大 → 中間CQ20 | 0.9957 |
| 新: 中間CQ20 → 拡大 | 0.9935 |
| 新: 中間CQ14 → 拡大 | **0.9958** |

このため `TICTOK_OVERLAY_PREPASS_QUALITY` の既定を20→14にしてある。CQ14でも中間fileは
旧経路より小さく(1178MB vs 2844MB)、時間は1/5。

## 同時実行

1本のjobはGPUを使い切っていない。再mp4化は前半のconcatでNVENCを一切使わず、焼き込みも
コメント層の描画中はNVENCが空く。NVENCそのものは2session並列でほぼ2倍出る。

| NVENC同時session | 1本あたり | 合計処理量 |
| --- | --- | --- |
| 1 | 76秒 | 1.00x |
| 2 | 39秒 | 1.94x |
| 3 | 38秒 | 2.00x |
| 4 | 41秒 | 1.83x |

pipeline通しでも同じ傾向。再mp4化2本(46分/318MB と 32分/218MB):

| | 所要 |
| --- | --- |
| 直列 | 252.0秒 |
| 同時 | **164.2秒 (1.53x)** |

`TICTOK_MEDIA_QUEUE_WORKERS`(既定2)で同時実行数を決める。上げるほど中間fileの同時使用量が
増える(焼き込みは1本あたりCFR base+コメント層で数GB〜数十GB)ので、空き容量と相談して決める。
**焼き込み同士**を重ねるには `TICTOK_GPU_CONCURRENCY` も同時に上げる必要がある
(焼き込みはrender全体でGPU枠を握るため、workerだけ増やしても順番待ちになる)。
再mp4化はGPU枠を取らないので、workerを増やすだけで重なる。既定の2が安全なのはこの
非対称のおかげで、焼き込みの中間file(数GB〜数十GB)は既定のままなら重ならない。

同じ録画に対する2本(焼き込みと再mp4化など)は、workerが空いていても同時には出さない。
再mp4化はmp4を作り直して差し替えるので、その裏で同じmp4を読んでいる焼き込みは途中で
足元を抜かれる。`claim_next_pending_media_job` が実行中の録画を除外して次を選ぶ。

## 見送った案と理由

- **CUDA filter(scale_cuda/pad_cuda)**: pre-passも解像度normalizeもNVENC律速で、CPU側の
  scaleは律速ではない。full CUDA化しても同じか僅かに遅い(178.8秒 vs 178.0秒)。
- **`-hwaccel cuda`でdecodeをGPUへ**: 同上。178.4秒で差が出ない。
- **NVENC presetを下げる(p5→p4/p1)**: 効果は大きい(76→52→36秒)が出力品質そのものが変わる
  ので、既定は据え置き。
- **AAC encoderの変更**: `-aac_coder fast`で51→22秒、Windows専用の`aac_mf`で14秒まで落ちる。
  どちらも音質の判断が要るため未採用。concatが音声encode律速である事実だけ記録しておく。
