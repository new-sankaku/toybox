# シーン検索のPK・ギフトpanel

`/videos` のシーン検索tab、playerの右列で**文字起こしと横を折半する**panel。**再生位置が
入っているPK(Battle)1戦**と、**その戦の窓に飛んだ味方陣のギフト**を出す。切り所を決める
材料は「何を喋ったか」だけではなく「どのPKで誰が何を投げたか」でもあるのに、後者はこれまで
時間軸のiconでしか読めず、送り主も金額もhoverしないと判らなかった。

- 画面: `static/videos.html` の `#pk-block` / `static/videos.js` の `renderPkPanel` 以下
- 口: `GET /api/recordings/{recording_id}/gifts`

## 出す物

```
▾ PK・ギフト   ☑再生に追従                    16戦 7勝9敗 / ギフト390件
┌─────────────────────────────────────────┐
│ 00:59:28 PK 6戦目 LOSE            +2,770 リード │ ← 見出し(clickでこの戦の頭へ)
│ [ 3,058 ██████████ | 288 ███ ]                  │ ← 再生位置でのスコアバー
│ 個人戦 1v1 / 相手: 廉くん / 尺 00:05:02          │
└─────────────────────────────────────────┘
┌─────────────────────────────────────────┐
│ 味方へのギフト 10 / 14件   1,009 / 1,618 コイン  │
│ 00:59:44 🌹 ｷﾅｺ    Rose 1                       │ ← clickでその瞬間へ
│ ...                                             │
│ 01:01:19 🌹 ✙おt¹  Rose 1                       │ ← 今の行(常に一番下)
└─────────────────────────────────────────┘
```

PKの外では両方とも空になり、PK欄は「PK中ではありません」＋次(無ければ直前)のPKへ飛ぶ
buttonだけを出す。空にするだけだと、次のPKがどこかを全尺barから探し直すことになる。

## 1戦だけを出す

全戦を縦に積んでいた頃は、PKを観ていない間も全戦の見出しと曲線が並び、今どの戦のスコアを
読めばいいのかを目で探すことになった。同時に2戦以上を出さないので、見出しの戦数と
スコアバーは常に1対1で対応する。

`state.battles` の窓は重ならない(serverが次の戦の開始で閉じる)ので、再生位置から入る戦は
一意に決まる。**同じ物を映している間はDOMを作り直さない** — 毎tickで作り直すと、ギフト欄の
scroll位置と選択が飛ぶ。作り直す合図は「今の戦」または「PK外で案内している行き先」が
変わった時だけ(`renderPkPanel` の `key`)。

## 欄の高さは固定

PK欄は高さを固定し、PK中・PK外・不成立のどれでも変えない。中身なりの高さにすると、PKの窓を
出入りするたびギフト欄の境目が上下し、読んでいた行を見失う。ギフト欄は残りを全部取り、
件数が0でも数十でも**中だけがscroll**する(`style.css` の `.vd-pk-now` / `.vd-pk-gifts`)。

## スコアバー

曲線(推移)ではなくバー1本。観ている最中に要るのは推移そのものより「今どちらが勝っているか」で、
狭い欄に2本の折れ線を描いても、どちらが自陣かを色だけで名乗ることになる。

分割は履歴画面・動画焼き込みと同じN分割(`common.js` の `buildBattleScoreBar`、
1v1=2 / 個人マルチ=人数 / チーム戦=チーム数)。自陣がrose、敵陣は出現順に別色で、幅は
score比、数値はバーの中に載る。細いsegmentは数値しか出ないので、誰の分かはhover(title)で
名乗る。

**値は再生位置での実値**で、確定scoreではない。`series[].parts` がその時刻の陣営別scoreを
持つので、そこから引く。partsを持たない古い記録は陣営に割れないので `own`/`opp` の2分割へ
落とす — 確定scoreで埋めることはしない(終わった後の値を再生位置の値として見せることになる)。
推移の記録がこの録画の窓に1点も無い戦だけは最終スコアを出し、その旨を素性の行に書く。

見出し右の「+N リード / N ビハインド」も再生位置での差。敵陣は個人マルチでも最上位1陣の値
(`opp`)で、勝敗の判定と同じ相手で差を出す。

## 味方陣のギフトだけ

一覧に出るのは**自室(味方陣)へ飛んだギフト**だけである。相手陣のコインは
`OpponentRoomListener` が相手Roomから拾ってBattleの貢献とスコアに入るが、1件ずつのeventは
保存していないので行にはならない。

## 飛んだ順に下へ積む

行は**再生位置まで届いた分だけ**をDOMへ入れ、再生が進むと下へ増える(配信を観ている時と
同じ順に流れる)。先の分まで並べると、まだ飛んでいないギフトが今の盛り上がりとして読める。
巻き戻せば先の行は外す。

行そのものは戦を開いた時に全部作っておき、増減では出し入れするだけにする。都度作ると
巻き戻しのたびに同じ行を作り直すことになる。追従ONの間は**下端に貼り付く**(積み上がる
一覧では今の行は常に一番下で、中央へ寄せると最新の行の下に空白が出る)。

見出しは「ここまで / この戦の合計」の2つを出す。合計を落とすと、あと何件・いくら来るのかが
読めない。

`items[].battle` は**session内の通し番号(ordinal)**で、`core.battle.gift_window_end` が
決める窓 — つまり**Battle cardの貢献集計と同じ窓** — で帰属させる。突合はserver時刻
(`create_time`、欠落時のみ受信時刻)で行う。窓の境界(`battle_setting.*_ms`)がserver時刻
なので、受信時刻のまま突合すると端のギフトが隣のPKへ流れる。

窓を画面側で別に持ってはならない。同じギフトがpanelとBattle cardで別のPKのものとして
数えられることになる。

battle_idではなくordinalで名指すのは、battle_idを持たない古いrecordが0で保存されるため
(同じsessionに2件あると別のPKのギフトが1つの束へ畳まれる)。

## 時間軸

スコア・ギフトとも**動画の秒**で返す。壁時計のまま返すとplayerの位置と重ならない。変換は
heat・comment・検索hitと同じ `indexer.build_time_mapper_sync` を通す(生の差分では
焼き込み動画とも検索hitともズレる。理由は `TIME_AXIS.md`)。

録画の窓の外のsampleは載せない。写像は録画の中の時刻にしか意味を持たないので、外側を
渡すと0秒や末尾へ潰れた点が端にぶら下がる。録画を跨いだPKは `partial: true` で名乗り、
見出しに「一部のみ」を出す — 途中から始まるスコアを「そのPKの全体」と読ませないため。

## 1つの口にまとめてある理由

全尺barのgift iconとこのpanelは**同じ1回のresponse**で賄う。別routeに分けると同じevent列を
2度読み、時刻の写像も2度組むうえ、片方だけが別の窓で数える余地が残る。時間軸の表示
checkbox(`show-gifts`)はiconを載せるかどうかだけを決め、取得は切らない — panelはcheckboxと
無関係に中身を出す場所で、切っている間だけ空になると「ギフトが無い録画」と区別が付かない。

## 折半の仕方

横で割る(縦ではない)。縦で割ると、その分だけコメント欄の読める行が減る。畳んでも幅は
半分ずつのままで、両方畳んだ時だけ行そのものが高さを手放してコメントが残り全部を取る
(`style.css` の `.vd-sidesplit`)。畳んだ側を細くしないのは、見出しに残る件数と追従
checkboxのぶん最小幅が中途半端に広く、開閉のたび両側の幅が動いて読んでいた行を見失うため。
